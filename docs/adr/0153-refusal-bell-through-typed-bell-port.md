# ADR 0153 — 断りの音は型のある `BellPort` で鳴らし、鳴らすかは application の 1 か所が決める

- 状態: 提案（hide の試用の後に受理）
- 日付: 2026-10-22
- Issue: #789（hide の了承 2026-10-21 夜:「断る時、OS の失敗音を」）
- 規則: ARC-003 / ARC-007 / ARC-010、CPP-002 / CPP-011、QLT-013、ADR 0009（ポート）/ 0022（入力行）/ 0032（検索の報せ）/ 0060（`open_listed`・`verify_quiet_paths`）/ 0066（Ex の保存）/ 0137（自動退避）

## 文脈

Nib は入力行の確定やファイル操作が断られたとき、ステータスバーに 1 行の知らせ（`E492: Not an editor command` `E13: File exists` `開けませんでした: <名前>` など）を出すだけで、音は鳴らなかった。知らせは目を本文に置いたままだと見落としやすい。Vim は既定でこれらに加えて鍵の失敗（行末の `l` など）でもビープを鳴らすが、鍵の失敗のたびに鳴ると煩い。hide の了承の範囲は「断る時」である。

OS の音は OS の呼び出しなので、中核（core / application）からは呼べない（ARC-007）。知らせを立てる所は `EditorController` の中に散らばっていて（`with_command_message` が 30 余か所）、どれが「断り」でどれが情報（`recording @a`・検索の折り返し・設定の値・`Written`）かは文字列からは決まらない。

## 決定

1. **鳴らす場面は 2 つだけ。** (a) 入力行の確定（`:` の Ex コマンドと `/` `?` の検索の確定）から出た断り（`E492` `E474` `E32` `E13` `E139` `E37` `E475` `E486` `E35` など、1 行の知らせになるもの）。(b) ファイル操作の失敗の知らせ（`:w` `:saveas` の失敗・`open_listed` の「開けませんでした」・自動退避の失敗の 1 行）。
2. **鍵の失敗では鳴らさない。** 行末の `l`・一致なしの `n`・`u` の端・オペレータの打ち消し・マクロの入れ子の上限など engine の鍵の失敗は、同じ E 番号の文でも鳴らさない。検索の確定（`/zzz<CR>`）は (a) で鳴り、その後の `n` の E486 は鍵なので鳴らさない。同じ報せでも道で分ける。
3. **鳴らすかは application の 1 か所が決める。** `EditorController::reject(core::DisplayText)`（`with_command_message` と `ports_.bell.ring()` の 2 つ）を 1 本だけ置き、場面 (a)(b) の呼び出し元はこれを呼ぶ。情報の知らせは今までどおり `with_command_message`（鳴らない）。文字列（`E` で始まるか）では判定しない。検索の確定は engine の 1 鍵なので、`submit(SearchLine)` が鍵の結果の失敗と知らせを見て `reject` へ写す。
4. **port は型のある 1 本。** `application::BellPort`（`ring() noexcept` の 1 本・結果は返さない・`ClipboardPort` と同じく複写と移動を消した抽象）。`EditorPorts` に借用の 1 欄 `bell`。
5. **adapters が OS を呼ぶ。** `adapters::win32::Win32Bell` が `MessageBeep(MB_ICONEXCLAMATION)` を呼ぶ（非同期・戻り値は見ない・user32 は adapters_win32 の許可の内）。ui と core は OS の音に触れない（ARC-007）。合成ルート（`src/app/Main.cpp`）が 1 個を所有して渡す。
6. **静かな道の契約。** `verify_quiet_paths`（scope `--history`）に「起動・開く・切り替え・新しいタブ・保存・打鍵・枠の道で `ring` は 0 回」を足す。替え玉 `ScriptedBell` は回数を数えるだけ。鳴る場面と鳴らない場面は scope `--bell` の契約が固定する。
7. **限界。** 設定で止められない（`errorbells` / `belloff` は後続）。ダイアログ（Ctrl+O の失敗・未保存の確認）の音は OS のまま。音の種類は 1 つ。

## 却下した選択肢

- **知らせの文字列が `E` で始まるかで鳴らす。** `E486` は確定（鳴る）と `n`（鳴らない）の両方から出るので文字列では分けられない。日本語の知らせ（「開けませんでした」）も拾えない。
- **engine の `VimRepeatFailure` で鳴らす（Vim の既定と同じ）。** 鍵の失敗のたびに鳴り、hide の了承の範囲を越える。
- **ui が知らせの表示値を見て鳴らす。** 断りか情報かを ui が判定する第 2 の経路になる（ARC-001）。

## 検証

- scope `--bell`: `:nosuchcommand`（E492）→ 1 回・`:noh` → 0・`/zzz<CR>`（E486）→ 1 回・その後の `n` → 増えない・行末の `l` と端の `u` → 0・`:w next.txt` の E13 → 1 回・成功の `:w` → 0・一覧から開けない → 1 回・自動退避の失敗 → 1 回。
- scope `--history` の `verify_quiet_paths`: 静かな道で 0 回。
- `eng/symbols.py`: `MessageBeep` は adapters_win32 にだけ出る。

## 結果

得られるもの: 断りに音が付き、鳴らす所は `reject` の 1 本で数えられる。鳴らす / 鳴らさないの分類は実装の報告（`out/reports/done-789-impl.md`）の表にある。

正直に（限界・後続）:

- マクロや `.` の再生の中の `:` と `/` の確定も同じ確定の道を通るので鳴る（Vim も鳴る）。
- ブックマークの読み書きの失敗・設定の保存の失敗・まだ読んでいないタブの読み込みの失敗・退避の残骸の復元の失敗・面の補完の失敗は、今回は鳴らさない側に置いた（分類は設計席が決める）。
- 検索の確定の失敗は「鍵の失敗かつ知らせがある」で拾う。描画の layout を作れない失敗（知らせ無し）は鳴らない。
