# ADR 0080 — 文字コードを判定した本文が検証済みのバイト列を所有する

- 状態: 受理
- 日付: 2026-10-09
- Issue: #320
- 影響する規則: ARC-001 / ARC-003 / ARC-007 / ARC-008 / ARC-009 / CPP-005 / CPP-007 / CPP-016 / CPP-018 / QLT-001 / QLT-012 / QLT-014

## 文脈

ファイルを開く共通経路 `read_document` は、UTF-8 の本文を `detect_encoding` と `TextBuffer::from_utf8` で二度検証し、復号と本文の生成で二度複製していた。
判定結果の enum だけでは、その後に渡された文字列が検証した文字列と同じだと証明できない。検証を省く公開フラグや未検証の生成口を足すと、本文が正しい UTF-8 である不変条件を壊せる。
読み込み前のゼロ埋めと、改行索引の一バイトずつの走査も同じ経路の費用である。D8 の判定優先順と保存の意味、ADR 0010 の同期読み込みと上限は変えない。

## 決定

1. **判定した列は core の `DetectedText` が所有する。** 非公開コンストラクタと唯一のファクトリ `from_bytes(std::string)` を持つ。ファクトリは既存の `detect_encoding` を一度呼び、成功した文字列と `TextEncoding` を一緒に保持する。外へは文字コードと読み取り専用の view だけを貸し、可変文字列や検証を飛ばす生成口は出さない。判定規則の正本は引き続き `TextEncoding.cpp` の一つである。
2. **本文の生成は所有権を受け取る。** `TextBuffer::from_utf8(std::string)` は生の UTF-8 を検証し、成功した文字列を move する。借用の呼び手は明示的に文字列を所有して渡す。もう一つの引数型 `DetectedText` は、UTF-8 / UTF-8 BOM なら保持する検証結果を使い、Shift_JIS なら結果型で拒否する。本文の実構築は非公開の一つの関数へ集約する。`TextBuffer` だけが `DetectedText` の所有文字列を受け取れるようにし、enum と別の任意文字列を組み合わせる口は作らない。
3. **BOM を外すのは判定済みの列を本文へ移すとき。** `utf8_bom` の先頭3バイトだけを消し、後ろに不正な UTF-8 がある列は従来どおり判定で拒否する。BOM だけ・空・埋め込み NUL も既存の意味を保つ。Shift_JIS は既存の `CodePagePort::to_utf8` に借用で渡し、その結果の所有文字列を生 UTF-8 の生成口で検証する。ポートが不正 UTF-8 を返した場合も本文にしない。
4. **application は所有権をつなぐ。** `FilePort::read` の結果を `DetectedText` に move し、`decoded` は本文を返す。UTF-8 のときは判定済みの値を直接渡し、Shift_JIS のときだけポートへ渡す。`read_document` は move 前に文字コードを控え、本文と `Document` を返す。起動引数・Ctrl+O・一覧・遅延読込はこの同じ経路を通る。
5. **読み込み用 string は `resize_and_overwrite` で確保する。** `Win32FileAdapter` が `GetFileSizeEx` と既存の上限を確かめた後、同期 `ReadFile` へその領域を渡す。コールバックの容量ではなく検査した要求サイズだけを読み、成功して書かれたバイト数だけを string の長さにする。コールバックから例外を投げず、失敗は既存の `FileFailure`。空・短い読み込みの意味を保ち、未初期化の末尾を読まない。ファイルAPIは adapters の外へ出さない。
6. **改行索引の内容は変えない。** 初めて索引を作るときは `std::ranges::count` で数えて容量を取り、`string_view::find('\n', at)` で改行の位置を並べる。既存の add 索引への追記は vector の伸長を保ち、毎回必要サイズぴったりに reserve して再確保する経路を作らない。original / add の索引と piece の窓は ADR 0047 のまま。STL の純粋な探索は既存の許可シンボルを使い、SIMD・SWAR・メモリマップは導入しない。

## 検証と限界

- 文字コードの優先順、不正入力、BOM、所有値と借用値からの本文、改行索引と編集後の旧値を対象の単体試験で確かめる。
- application の開く契約と実ファイルの adapter 試験で、復号失敗・読込上限・空・短い本文・埋め込み NUL と保存を確かめる。既存の試験を対象指定し、必要な対象指定が無ければ既存関数を呼ぶ薄い selector を足す。
- 変更した target の Debug と静的解析、規約・シンボル・整形を確認する。実機 Release で `open-large-file-16mib` を既存基準と比較する。`newlines_in` は追記にも使うので、`key-to-frame-burst-200-16mib` も直接影響の確認として選ぶ。成功した記録は統合時に再利用する。
- 64 MiB の同期読み込み上限はそのまま。確保失敗やファイルが読み込み中に変化することへの新しい保証は加えない。小さな測定差だけで改善を断定しない。保存形式・見た目・基準値・許容値は変えない。

## 既存決定との関係

ADR 0009 の正しい UTF-8 を持つ本文、ADR 0010 の判定と復号の分離、ADR 0036 の改行、ADR 0047 の索引の所有を保ち、検証済みの所有値を渡す公開 API を追加する。
検証前の bytes と判定結果の enum を別々に公開の未検証生成口へ渡す案、呼び手が true を指定する検証省略フラグ、読み込み専用の別 piece table は採らない。
