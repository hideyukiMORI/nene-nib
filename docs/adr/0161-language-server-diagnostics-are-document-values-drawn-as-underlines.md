# ADR 0161 — 言語サーバーの診断は文書の値で、区間の下線と右端の件数で見せる（LSP 段 L1）

- 状態: 受理（施主 2026-10-28「全部推しでいい」・ADR 0160 の L0 の上。L-1（初版の範囲）と L-4（送らない文書の大きさ）は hide の確認の後。D60: 設定で切り替え・既定オフ・オンの速さは `lsp-` のベンチと別の基準）
- 日付: 2026-10-28
- Issue: #995（L1）・L0 は #994・計画 `docs/plans/2026-10-21-syntax-and-lsp.md` §2.3 / 2.6 / 2.7
- 規則: ARC-001 / ARC-003 / ARC-004 / ARC-011、CPP-002 / CPP-005 / CPP-011、QLT-014、ADR 0014（IME の下線の描画）/ 0037（当たりの面）/ 0056（文書の値）/ 0062（合図と `collect`）/ 0070 / 0079 / 0154（ステータスバーの枠）/ 0152（編集で位置をずらす `marks_adjusted`）/ 0156（構文の色の区間 `ColorSpan`）/ 0160

## 文脈

L0（ADR 0160）で port と JSON-RPC と設定が揃う。最初に見せる機能は診断（`textDocument/publishDiagnostics`）で、補完や定義より先に効き目が分かり、サーバーの速さに依らず打鍵の道を変えない。Nib には区間の形（`LineView.colors` の `ColorSpan`・本文の桁・昇順で重ならない）と下線の描画（IME の `underline_runs`）が既にある。

## 決定

1. **文書ごとに `didOpen` / `didChange` / `didClose`。** `lsp` が on・文書の言語に command がある・本文が 4 MiB 以下（L-4・設定に出さない定数）のとき、サーバーが `initialized` に達した後に `didOpen`（全文・`languageId` は `language_name`・`version` は `EditHistory::revision()`）。編集は `TextBuffer::replaced(begin, end, inserted)` の 1 編集が `TextDocumentContentChangeEvent`（range・text）に 1 対 1 で対応するので **増分**で送る。1 つの意図の中の複数の編集（マクロ・`.`・貼り付け）は `apply` の終わりに 1 通の `didChange` に束ね（`contentChanges` の列・順のまま）、`version` は意図の後の `revision()`。タブを閉じたら `didClose`。切り替えでは閉じない（サーバーは複数の文書を持てる）。言語ごとにサーバーは 1 本で、同時に起こすのは 1 言語まで（2 つ目の言語の文書を開いたら前のを `shutdown`・限界）。`root`（`rootUri`）は最初に開いた文書のフォルダ（`compile_commands.json` の場所は command の引数で）。

2. **診断は文書の値。** `DocumentState` に `std::vector<core::Diagnostic> diagnostics`（`Diagnostic{OffsetRange range; DiagnosticSeverity severity /* error warning information hint */; std::string message;}`・公開 aggregate・比較は非メンバー）と `std::uint64_t diagnostics_version`（届いたときの `version`）。`publishDiagnostics` の position（`line` と `character`・`positionEncoding` が `utf-16` なら UTF-16 の単位）は core の純関数 `lsp_range_to_offsets(text, range, encoding)` で本文の offset に写す（行は改行の索引・桁は `Utf16` の 1 本・行や桁が本文の外なら切り詰める）。1 文書の診断は **1,000 件まで**（超えた分は捨てて件数に `+` を付ける・限界）。

3. **編集で位置をずらす 1 本。** 新しい診断が届くまで、古い診断は編集で位置をずらして見せる（マークと同じ `EditAdjust` の規則・ADR 0152・編集の範囲の中の診断は消す）。ずらすのは `replace` の 1 か所（`forget_syntax_before` と同じ所）。届いた診断の `version` が今の `revision()` より古ければ、届いた後の編集でずらしてから置く（サーバーは古い版の位置で返す）。`version` が今より新しいことは無い。
   - 追補（#1210）: 編集で診断をずらし `didChange` の変更を積むのは `language_server_edit` の 1 本で、本文を置く 3 か所（`replace`・undo・redo）が本文を置く前に呼ぶ（undo / redo は `replace` を通らないため）。

4. **見せ方は下線と件数。** `LineView` に `std::vector<core::DiagnosticSpan> diagnostics`（`DiagnosticSpan{Column begin; Column end; DiagnosticSeverity severity;}`・`colors` と同じ桁・昇順・重なりは重い方だけ）を 1 欄足し、frame を作る所が見えている行の診断だけ写す（`colors` と同じ道・格子の画面行も `GridLineRows` の写し）。renderer は IME の `underline_runs` の道で **波線**（error は `SyntaxPalette.error`・warning は `.warning`・information と hint は `muted`・太さ 1 DIP・振幅 1 DIP・色のトークンは足さない）。ステータスバーの右端に 5 つ目の項目「E2 W1」（件数が 0 なら項目を出さず幅も取らない・枠は `write_status` の保持に 1 枠足して最大 12・録画と排他なので録画時は 9・ADR 0154 の形）。キャレットの行の診断の文は、キャレットが診断の区間の上にあるときだけ知らせの欄に出す（ほかの知らせがあればそちら・frame から作る値で状態に積まない・256 バイトで切る）。
   - 追補（L1c・#995 の ui の段）:
     - **件数と文は application が frame に載せる（R7-1）。** 型は core の `DiagnosticCounts{errors; warnings; completeness}`（`DiagnosticsCount` の打ち切り・status_items_for と同じ core の値なので core に置く）。数えるのは `diagnostic_counts(span<const Diagnostic>, DiagnosticsCount)` の 1 本で、frame の `diagnostic_counts` と窓のステータスバーの hit test（`EditorController::diagnostic_counts()`）が同じ値を引く。ui は数え直さない。キャレットの上の文は `diagnostic_notice(diagnostics, caret)`（区間 `[begin, end)` の中・空の区間はその位置・重い方が勝つ）で、`command_message` があれば作らない。文を出す frame は案内を消す（知らせと同じ・`GuideContext::hidden`）。外から来た文を 1 行にするのは `notice_line` の 1 本（最初の改行の前・制御文字は空白・256 バイトを code point の境目で切る・空と UTF-8 でない文は出さない）。
     - **5 つ目の項目は言語の右（いちばん右）。** 文字列は core の `diagnostic_count_item`（「E2」「W1」「E2 W1」・打ち切りは末尾に「+」・0 件は値なし）。`DisplayText` は空を持てないので、4 項目の配列（`status_item_count = 4`）には入れず、`StatusBarLayout.diagnostics` の矩形を足した。件数が無ければ右端の幅 0 の矩形で間の余白も取らず、あれば幅 96 DIP（上限 1,000 件の「E500 W500+」まで）で、ほかの 4 項目はその左へ寄る。配置は `status_bar_layout(width, height, dpi, counts)` の 1 本（3 引数は件数 0 と同じ配置で、帯の高さだけを読む所が使う）。畳む順は言語 → 件数（R3-1）: 件数を置いた後の右端で言語を畳み、それでも `:` の入力欄の右端が `command_input_minimum_dip` に届かなければ件数も幅 0 にする（ADR 0154 の決定 6 の不変条件を守る）。renderer の描画とステータスバーのクリックの hit test は同じ counts を渡す。
     - **波線。** 太さ 1 DIP・振幅 1 DIP（山から谷まで 2 DIP）・周期 4 DIP の三角波を、ui の `draw_diagnostic_wave`（`DiagnosticWave.hpp`）の 1 本で引く。画素の列ごとに太さの矩形を 1 つ塗り（同じ高さが続く列は 1 つにまとめる）、座標は整数の画素なので中間色が出ない。位相は画素の絶対の x で決め、隣り合う区間と行でつながる。下端は IME の下線と同じ（行の下端から `caret_inset`）。本文の行は区間を色の区間と同じ写し（`span_ranges`・IME の差し込み行は差し込みの後ろをずらす）で UTF-16 の範囲にし、run ごとに引く。行末の外の区間（空の診断）は行末の位置から 1 桁（ブロックの最小の幅 7 DIP）。格子は升の範囲の矩形の下端に同じ関数で引く。色は core の `diagnostic_color`（error は本文の `error`・warning は `warning`・information と hint は UI の `muted`・トークンは足さない）。診断の無い行は `empty()` の分岐 1 つで抜ける。
     - **録画中は文を出さない（R3-3）。** マクロの録画中は `recording @a` を隠さないよう、`add_diagnostics` が文を作らない（優先の式はこの 1 か所で、renderer は `command_message` か `diagnostic_message` の値のある方を読むだけ・両方が値を持つことは無い）。文が出ている間にトグルの位置をクリックしても、`command_message` のときと同じく何もしない（`EditorController::diagnostic_message_shown()`）。
     - **格子の行末の 1 升。** `grid_diagnosed_line` が行末へ切り詰めた空の範囲は、行の最後の画面行で行末の外の 1 升 `[starts.back(), starts.back() + 1)` にする（本文の表示の「行末の外に 1 桁」と揃える・R7-1）。
     - **枠。** `write_status` の保持は 12（トグル 2・モード 1・右の 4 項目・件数 1・案内 4）、録画中は 9。件数が 0 の frame は件数の枠を使わない（`status_layout_demand` が `StatusBarLayout.diagnostics` の幅で数える）。

5. **届く道は合図だけ。** `ServerMessage` は `WorkCompleted` → `collect` → `parse_json` → `publishDiagnostics` なら決定 2 の写し → `EditorDelivery.repaint`。ほかの通知（`window/showMessage` `window/logMessage`）は `showMessage` の error / warning だけ 1 行の知らせ、`logMessage` は捨てる。要求の答え（`initialize` 以外）は L1 では無い。
   - 追補（L1c）: 写しは core の `lsp_shown_notice` の 1 本（`type` が 1 か 2 の数・`message` が文字列のときだけ `notice_line` で 1 行）。controller は既存の `with_command_message` に置くだけで、次の使う人の意図で消える（ほかの知らせと同じ）。Info（3）・Log（4）・欄の欠け・`window/logMessage` は捨てる。

6. **打鍵の道の費用。** on のときに足すのは `apply` の終わりの `didChange` の組み立てと `send`（文字列の確保と `WriteFile` の発行・数十 µs の見込み・ベンチで測る）。診断の写し・ずらしは `collect` と `replace` の中で、見えている行の写しは frame の `colors` と同じ走り。off のときは分岐 1 つも足さない（port を呼ぶ所に入らない）。

7. **ベンチ（D60・`lsp-` の接頭辞・任意・別の基準値）。** `lsp-single-key`・`lsp-burst-200`（替え玉のサーバー exe を起こして `initialize` が返った後・診断は返さない設定）・`lsp-diagnostics-ready`（替え玉が 100 件の診断を即返す設定で、打鍵を止めてから下線が frame に載るまで・参考値）。clangd での実測は hide の実機で記録だけ（版と `compile_commands.json` の有無を書く）。基準値の採用は L1 の試用の後に hide。
   - 追補（L1d・#1216）: 3 本は `eng/measure-speed.py` の `OPTIONAL_BENCHES`（`LSP_BENCHES`）で、`--record` だけを受ける（`--check` `--adopt` `--values` は拒否・`eng/perf-reference.json` は説明だけで機械の値を持たない）。替え玉は測る exe と同じ build の `nib_fake_language_server.exe`（`--silent` は did* に黙る・`--diagnostics <N>` は `didOpen` / `didChange` ごとに同じ uri と version で N 件を 1 通・1 行 1 件の 0〜4 桁・error と warning を交互）。設定は道具の profile `out/speed/profile-lsp` の `settings.v4` に `lsp=on` と `lsp.cpp.command="<替え玉>" <引数>` を `window_driver.write_settings` で書き、文書は `key-to-frame-single-cpp` と同じ `single-cpp-1000.cpp`。**「サーバーが起きた」の節目**は製品に無いので、替え玉が窓の子プロセスとして見える（`window_driver.child_names`）まで待ってから窓のスレッドが静かになるのを待つ（替え玉は `initialize` に即答し、controller はその答えで `didOpen` を送る）。単打と 200 打鍵はその後に `key-to-frame-single` / `-burst-200` と同じ打鍵・同じ節目（同じ 1 試行）。**`lsp-diagnostics-ready` は近似**: 製品は診断の節目を持たないので、ui に節目を足さず、静かになってから送る 1 打鍵の `input_received` から**その後の 2 枚目の `frame_presented`** までを値にする（1 枚目は打鍵の frame、2 枚目は `publishDiagnostics` → `WorkCompleted` → `repaint` の frame。暖機の 2 枚目が測る打鍵より後なら、または 2 枚目が無ければ欠測）。サーバーの答えが打鍵の frame より先に着いて 1 枚に重なると、2 枚目は無関係な後の frame になる。これを拾わないよう、1 枚目と 2 枚目の間隔が `LSP_READY_GAP_MS`（100 ms）を越えた試行は欠測にし、試行ごとの `[1 枚目, 2 枚目]`（打鍵からの ms）を記録の `framesMs` に残す（#1217 のレビュー R3-1。根拠: 替え玉はマイクロ秒で答え、席の確認では診断の frame は打鍵の frame の約 1 ms 後、`--silent` でも出る無関係な frame は 300 ms 以上後）。替え玉は `--diagnostics` をほかの振る舞いの引数と併せると何も読まずに 4 で終わる（R1-1）。参考値のまま基準にしない。

8. **契約。** core: `--lsp-diagnostics`（position の写し・UTF-16 の代理対・範囲の外・1,000 件の上限・`EditAdjust` でのずらし）。application: `--language-server` に「`didOpen` の条件（on・command・4 MiB）・`didChange` の束ね（マクロの 1 意図で 1 通・`version`）・`didClose`・古い `version` の診断のずらし・2 言語目で前を閉じる・off で 0 通」。ui: `nib_window_tests` に波線の画素（WIC・`underline_runs` の既存の比較の形）と件数の枠。`verify_quiet_paths`: off で port 0 回・on でも切り替えと保存で 0 通（`didSave` は送らない・限界）。

9. **限界（L2 以降・別 ADR）。** 補完・hover・定義・code action・`relatedInformation`・`textDocument/didSave`・複数のサーバーの同時起動・診断の一覧の面（Ctrl+P の `!` など）・診断の間を跳ぶ鍵（`]d` `[d`）。

## 追補（#1208・core の段の決め事・2026-11-03）

決定 2 / 4 を core に置いたときの細部（設計席の判断・PR #1207）。`lsp_published_diagnostics` は `severity` が無い件を error として読み（LSP 3.17 は client に任せる・VS Code と同じ）、1〜4 の外の `severity`・`range` や `message` の欠けた件はその件だけ捨てて通知の全体は断らない。1,000 件の上限は残した件で数え、超えたら `PublishedDiagnostics.count` を `truncated` にする（件数の `+`）。`lsp_range_to_offsets` は行が本文の外の端を本文の末尾へ切り詰め、start も外なら末尾の空の区間（EOF の診断）として残す。`diagnostic_spans` は空の診断と改行のバイトだけに掛かる診断を行末（空の診断はその位置）の 1 桁にし、内容と改行をまたぐ診断は内容の上だけにする。`PublishedDiagnostics.version` は `version` の無い通知では値なしで、決定 2 の `diagnostics_version` と決定 3 のずらしへの写し方は L1b（application）が決める。

## 強制

- 診断の位置の写しとずらしが core の純関数 1 本ずつ: **active**（`eng/symbols.py`・契約）。#995 の core の段で `lsp_range_to_offsets` と `lsp_published_diagnostics`（`LspDiagnostics.hpp`）・`diagnostics_adjusted` と `diagnostic_spans`（`DiagnosticEdits.hpp`）を足し、契約 `nib_tests --lsp-diagnostics`（既定実行にも載る・固定 seed の性質の試験を含む）が守る。
- off のときの port の呼び出し 0 回: **active**（#1210・`nib_tests --history` の `verify_quiet_paths` が既定の設定（off）で起動・開く・切り替え・保存・打鍵の後に port の呼ばれた回数 0 を見る。`--language-server` の `verify_quiet_when_off` が off の打鍵・合図・tick で 0 回、`verify_did_close` が on でも開いた文書の間の切り替えと保存で 0 通を見る）。
- off の 8 本に退行なし: **active**（QLT-014）。
- `lsp-` のベンチの基準値: **planned**（試用の後に hide が採用・D60）。
- 件数・文・知らせ・波線の ui（決定 4・5 の追補）: **active**（L1c）。core は `nib_tests --status-items`（件数の 5 形・幅 0 の配置・hit test）と `--lsp-diagnostics`（`notice_line`・`diagnostic_notice`・`lsp_shown_notice`・`diagnostic_counts`）、application は `--language-server`（件数と `+` と文が frame に載る・区間の外で文が無い・`command_message` が勝つ・`showMessage` の error / warning だけ知らせ・行末の 1 桁と 1 升）、ui は `nib_window_tests --diagnostics`（WIC の画素で波の形と格子の error の色）と `--status`（12 枠・録画 9 枠）。

## 結果

得られるもの: C/C++（clangd）の誤りが打ちながら見える。構文の色と同じ区間の形に載るので描画の道は増えない。
失うもの・残る穴: 同時に 1 言語。診断の文は 1 行で切れる。サーバーの速さは Nib の責任の外（`lsp-diagnostics-ready` は参考値）。4 MiB 超の文書には出ない。

## 却下した選択肢

| 選択肢 | 却下の理由 |
|---|---|
| 診断を `LineView.colors` の `error` / `warning` の役割で色として塗る | 構文の色と重なると区間の統合が要り、下線の方が構文の色を消さない。`SyntaxRole::error` は閉じていない文字列などの字句器の値のまま |
| 打鍵ごとに `didChange` | マクロ・`.`・貼り付けで 1 意図に数百の編集。束ねれば 1 通 |
| 全文の `didChange`（Full） | 1 MiB の文書で打鍵ごとに 1 MiB を書く。増分は `replaced` の 1 編集と 1 対 1 |
| 診断を状態に積まず届くたびに描くだけ | 編集でずれる。文書の値にして `EditAdjust` でずらすのが ADR 0152 と同じ形 |

## 追補（2026-11-20・#1897・設計席の決め・LSP 段 S1）: 仕様どおりに話す

実物の clangd 19 と jedi-language-server で往復を確かめた調べ（`D:\NeNeNib\outputs\20261120\lsp-gap-survey.md` の §2 の穴 2・3・4・8・10・11）の手当て。決定 1 と 9 の一部を改める。

- **決定 1 の `languageId`**: `language_name` ではなく core の `lsp_language_id(Language, 文書のパス)` の 1 本（`LspLanguageId.hpp`）。LSP 3.17 の表の名前（`cs` → `csharp`・`ps1` → `powershell`・`sh` → `shellscript`・`dosini` → `ini`・`text` → `plaintext`・#1917 で足した `make` → `makefile`・`dosbatch` → `bat`）で、表に無い言語（`toml` `cmake` `gdscript` `gdresource`・#1917 の `kotlin` `zig` `terraform` `haskell` `vue` `svelte`）は Nib の名前のまま。`.tsx` と `.jsx` は拡張子（大小を問わない）で `typescriptreact` / `javascriptreact`（`Language` の値は増やさない）。`switch` に `default` は無く、言語を足すと落ちる。
- **決定 1 の「増分で送る」**: `initialize` の答えの `textDocumentSync`（数か `TextDocumentSyncOptions` の `change`）を `ServerAbilities.sync`（`DocumentSync` の none / full / incremental）に持つ。incremental は今までの形。full は意図の終わりの 1 通に range の無い全文を 1 つ（編集ごとには位置を写さず数だけを積む）。none（数の 0・欄が無い・知らない値。仕様の既定）は `didChange` を送らない（`didOpen` / `didClose` は今までどおり送る・`openClose` は読まない）。none のときは送った版が進まないので、診断は `didOpen` の版の本文で写す（ずらさない・限界）。
- **決定 9 の `didSave` を外す**: `textDocumentSync.save` が true か `SaveOptions` なら `ServerAbilities.save` が plain、`includeText` が true なら with_text。保存の成功（`save_document` の 1 か所・文書の名乗りを保つ保存は除く）の後、アクティブな文書を同じ URI のまま開いていれば、積んだ変更を流してから `didSave` を 1 通（with_text は送った本文＝改行の形を写す前の本文を `text` に）。別のパスへの保存は URI が変わるので送らず、apply の終わりの同期が閉じて開き直す。決定 8 の「保存で 0 通」は「`save` を求めないサーバーには 0 通」に読み替える（`verify_quiet_paths` の off の 0 回は変わらない）。
- **決定 5 の診断の URI の照合**: 文字列の完全一致ではなく、定義の着地（ADR 0190 の決定 4）と同じ規則の 1 本 `EditorController::same_document_uri`（完全一致か、core の `file_path_of_uri` で両方をパスへ写して `FilePort::same_file`）。ドライブ文字の大小・`%3A` などの百分率の符号化の違いで捨てない。
- **打鍵の道（決定 1）**: `lsp_position_of` / `lsp_offset_of` は行の全体を写さない。utf-8 は桁の後ろの最大 4 バイトの窓だけ（境目へ寄せる・`leading_continuations`）、utf-16 は行頭から桁まで（`lsp_offset_of` は 1 単位 3 バイトの上限で切り `whole_code_points` で端を落とした窓）だけを読む。utf-16 の写しは桁に比例し、行の長さには比例しない。
- **契約**: `--lsp-messages`（`languageId` の表・位置の写しの往復）・`--language-server`（同期の種類・`didSave`・URI の綴りの揺れ・起動の失敗の知らせ・表に無い命令の行）・新しい scope `--lsp-sync-property`（固定 seed の編集の列〔打鍵・削除・語の削除・キャレット・CRLF と代理対と結合文字の貼り付け・undo / redo・Vim の鍵とマクロと `.`〕を流し、送った `didOpen` に `didChange` の列を `lsp_offset_of` で当てた本文が controller の本文と同じ・incremental の utf-16 と utf-8・full）。
- **残る限界**: lone CR の文書（#1049 で残す）は LSP では改行だが Nib の行の索引は `\n` だけなので、行の番号がずれる（まれ・性質の試験は lone CR を作らない列で回す）。

## 追補（2026-11-20・#1909・設計席の決め・LSP 段 S2）: 言語ごとにサーバーを持ち、タブの切り替えで止めない

調べ（`lsp-gap-survey.md` §2 の穴 1・6）の手当て。決定 1 の「同時に起こすのは 1 言語まで（2 つ目の言語の文書を開いたら前のを `shutdown`）」を改める。port の形は ADR 0160 の同じ日の追補。

- **つながりは席ごと**: controller は席（`LanguageServerSlot`・上限 4）ごとに `LanguageServerLink` を 1 つ持つ（`LanguageServers`）。文書を開いた・アクティブになったとき、その言語の命令があり、その文書を受ける席（`serving_slot`）が無ければ、空いた席で起こす。受ける席は「子が居て止めに向かっていない同じ言語の席」で、設定に `root` があれば**席が実際に起きた root** がそれと同じ席だけ（今の文書に対していま決まる root と比べる。`:set root=.` が席の起きたフォルダと同じなら同じ席が受け続け、起き直さない・#1916 のレビュー M1）。設定に `root` が無ければ最初の文書のフォルダで起きた同じ言語の席が受ける（root の決め方は決定 1 のまま・印で探すのは段 S3）。同じ言語の席が 2 つあれば最後に使った席。起こすかを決めた印 `considered` の鍵は（言語・パス・設定の `root`）で、起動後に設定の `root` が変わって受ける席が無くなれば決め直す（`:set root=<別のフォルダ>` ではその root の席が起きて文書を受け、前の席は文書を `didClose` する）。
- **止めない**: 言語の違うタブ・命令の無い言語のタブへ移っても、どの席も止めない。`didOpen` した文書の `didClose` は、タブを閉じる・言語が変わる（`:set ft=`・その席が受けなくなる）・URI や大きさが変わる・席を譲るときだけ。診断は文書の値のまま残る。
- **席が満ちたら譲る**: 空いた席が無ければ、アクティブな文書で最後に使った順（`LanguageServerLink.used`・reconcile が受ける席に印を打つ）で最も前の席を `shutdown` して譲らせ（その席の文書は `didClose`）、`shutdown` の答えの後の reconcile が空いた席で起こす。止めに向かっている席があれば、その終わりを待つ。送れない文書（無題・上限を超えた本文）のためには譲らせない（#1916 のレビュー R3）。
- **失敗は言語ごと**: 続けた失敗の数（3 回）と `given_up` は言語ごとの控え `LanguageServerTrouble`（root の違う同じ言語の 2 席は数を共有する。命令の誤りは言語ごとに同じなので、これが意図・#1916 のレビュー L5）。自動の再起動は同じ席・同じ root で起こす。ある言語の命令の誤りでほかの言語の席を止めない。`:set lsp`（と設定の面でオンにすること）は全部の言語の控えを消す。
- **要求の振り分け**: 補完・hover・定義・`didChange`・`didSave` は、アクティブな文書を開いた席（`holding_slot`）へ。答えを待つ要求の表は席ごとで、id は席をまたいで一意の通し番号。答えはそれを出した席の表だけで引く（ほかの席から届いた同じ id の答えは捨てる）。能力・位置の単位はアクティブな文書を受ける席のもの（`active_language_server`）。ただし定義の着地は、答えた席の位置の単位を着地の文脈（`LspLanding`）に載せて運ぶ（着地先の文書の言語の席から引かない・`.cpp` → `.h` で単位がずれない・#1916 のレビュー R2）。補完・hover・定義の答えを消すのは、アクティブな文書を受ける・開いた席を止める・譲るときだけ（ほかの言語の席が落ちても答えは残す・R1）。
- **オフの道**: `LanguageServers.awake`（idle でない席の印・立てるのは起こす 1 か所・消すのは止める 1 か所）が 0 なら、collect・編集・保存の道は欄を 1 つ、reconcile は設定の `lsp` と `awake` の 2 欄を読むだけで抜ける（決定 9 の費用は変わらない）。
- **契約**: `--language-server` の `verify_language_follow`（命令の無い言語のタブへ移っても止めず、診断が残り、戻っても起こし直さない・前の「止める」契約を置き換えた）・`verify_two_languages_at_once`・`verify_answers_by_slot`・`verify_failures_by_language`・`verify_slot_yield`（譲った後に古い子から届いた答えと診断を捨てる）・`verify_filetype_change`・`verify_root_key`・`verify_answers_survive_other_slots`・`verify_definition_lands_in_answering_units`・`verify_unsendable_keeps_slots`（`tests/unit/LanguageServerSlotTests.cpp`）、adapter の `verify_two_slots`・`verify_retired_limit`（退く子の 9 本目で最も古い子を殺す）。

## 追補（2026-11-22・#1939・設計席の決め・LSP 段 S5）: 診断の間を跳ぶ鍵・札・一覧

決定 9 の限界のうち「診断の一覧の面」と「診断の間を跳ぶ鍵（`]d` `[d`）」を外す。`relatedInformation` と `tags` の見た目・quick fix は限界のまま。

- **文の全部を持つ**: 文書の値の `Diagnostic` は `message` に文の全部（改行を含む・`lsp_diagnostic_message_limit`＝3,840 バイトまで code point を割らずに切る）と、`source`・`code`（整数は負も含めて 10 進の文字列・文字列は 128 バイトまで・それ以外は空）を持つ（決定 2 の「改行の前までの 1 行」を改める）。1 行の知らせ（`diagnostic_notice`）と一覧の行は `notice_line` で最初の行だけを見せる。1 件は文と 2 つの欄で 4,096 バイトまでなので、上限の 1,000 件と掛けて 1 文書 4 MiB に収まる（`static_assert`・#1946 のレビュー R3 で文の上限を 4,096 から下げた）。
- **持ち方**: 文書の値の診断の列は `SharedDiagnostics`（`std::shared_ptr<const std::vector<Diagnostic>>`・空は無し）で、`EditorState` と脇の束 `DocumentState` は不変の列を指す参照だけを持つ（ほかのタブの束・`vim_text_` と同じ形）。打鍵ごとの `with_*` の写しは参照 1 つで、文を写さない。編集でずらすとき（`language_server_edit`）だけ、ずらした列を 1 回作って参照を差し替える。作るのも読むのも UI の糸の上だけ（知らせは `WorkCompleted` の collect の後に受ける・worker へ渡さない）なので、参照の数を糸をまたいで数えない。読む口は `diagnostics()` の `std::span`。目安の実測（2026-11-22・Release の nib_tests の使い捨ての測定・窓なし・同じ機械でほかの席がビルド中なので目安）: 1,000 行の文書に診断 1,000 件・各 30 行約 3,000 バイトの文で、先頭に 1 字打つ 1 打鍵（frame まで）は値で持つ形で 3.0〜5.2 ms、参照で持つ形で 1.3〜1.4 ms（短い文の 1,000 件は 0.5〜0.7 ms → 0.5〜0.6 ms・診断なしは 0.05〜0.08 ms で変わらない）。残りは位置をずらした列を 1 回作る費用で、文の写しも含む（後ろの全部がずれる最悪の場所で打った値）。
- **跳ぶ（core の純関数 1 本）**: `diagnostic_landing(診断, キャレット, 向き, 回数)`。歩くのは診断の始まりの位置で、同じ位置の診断は 1 つに数え、重さで絞らない。次はキャレットより後ろの最も近い始まり、前はキャレットより前の最も近い始まりで、端を越えたら反対の端へ折り返す（Neovim の既定）。回数は列を回る分の余りだけ歩く。一覧の順（`diagnostic_order`）は「行 → 桁 → 重さ」（始まりの位置・重い順・届いた順）。
- **鍵**: Vim の NORMAL は `]d` `[d`（回数つき）。`[` と `]` の接頭辞を分け（`VimPrefix::bracket_back` / `bracket_forward`）、`d` のときだけ表に行が無かったときと同じ失敗の歩（本文もキャレットも変えない・Vim の `[d` は定義を表示するだけで fixture に影響しない）に効果 `VimDiagnosticCommand{command, count}` を添える（`gd` の `VimLanguageQuery` と同じ形）。オペレータの後ろ・VISUAL は添えない。`gl`（Vim に無い g の鍵・表に無い g の鍵と同じに鳴る）はキャレットの上の診断の札を出す（回数つきは添えない）。engine は診断を知らないので歩は失敗のまま返り、controller が効果を果たせたとき（跳べた・札を出せた）だけ `stepped_vim` が成功の歩に読み替える（`vim_effect_landed_`・Neovim の `]d` と同じ・#1946 のレビュー R3）。だからマクロ（`qa]dxq`）と map の右辺（`nnoremap Q ]dx`）は跳んだ後の残りを流し、診断が無くて跳べないときは失敗の歩のまま残りを捨てる。本文と Vim の状態は成功でも失敗でも同じで、fixture（診断の無い本文）は変わらない。`3"a]d` の回数は `"a` の前の回数を読まない（`state.count` だけ・意味の無い組み合わせなので限界）。通常モードと Vim の両方で F8 / Shift+F8（VS Code と Visual Studio の「次の問題へ」）。操作の表に「次の診断へ」「前の診断へ」（F8 / Shift+F8）「診断を表示」「診断の一覧」（鍵なし・F1 の一覧から）を 1 行ずつ。操作と Vim の効果は controller の `run_diagnostic_command` の 1 本へ入る。
- **ジャンプの列**: 跳ぶ前の位置を `''` とジャンプの列に置く（全文検索の当たり・定義と同じ `set_context_mark` の 1 本・`<C-o>` で戻れる）。操作（F8 / Shift+F8・一覧）はキャレットを `PlaceCaret`（クリックと同じ道・INSERT では割り込みと数える）で置く。Vim の鍵の効果の中では `PlaceCaret` を呼ばず、`VimMoveTo` と同じく `move_caret_to` と NORMAL の寄せ（`settle_vim_caret`）だけで置く（INSERT の `Ctrl-o` の始め直しは鍵の出口の 1 回だけ・`i<C-o>]d`・#1946 のレビュー R3）。IME の変換中の F8 / Shift+F8 は何もしない。オペレータを待つ間の F8 は本文を変えずに跳び、オペレータは残る（F12 の着地と同じ）。
- **札**: 跳んだ先（と「診断を表示」・`gl`）の診断の文の全部を、hover の札と同じ欄（`LanguageAnswers.hover`・文脈は今のキャレット）に置く。文は `diagnostic_tip_text`（キャレットの上の診断を重い順に、文の全部と `source(code)` の行・診断の間は空の行）で、行の上限は hover と同じ 12 行（`hover_tip_text`）。消え方は hover と同じ（次の使う人の操作・窓が非アクティブ）。札を置くときは出ている hover の要求を全部の席で取り消す（`cancel_lsp_requests`・後から届いた古い答えが札を消したり上書きしたりしない・#1946 のレビュー R3）。ui は変えない。
- **一覧**: Ctrl+P の新しい出どころ `^`（`PaletteScope::diagnostics`・`PaletteOrigin::diagnostic`・ADR 0060 の追補）。候補は面を開くときに 1 回だけ作り、アクティブな文書の診断が先、続いて帯の順にほかの読み込み済みのタブ（まだ読んでいない文書は診断を持たない・サーバーへは何も頼まない）。行は「重さの印（E W I H） ファイル名:行:桁」、補足に文の最初の行。選ぶ動き `CommandChoiceKind::land` の `command` は controller が控えた列（`palette_diagnostics_`）の位置で、ほかのタブなら `SwitchTab`（`reach_tab` を通る切り替えの道）で切り替えてから `''` を置いて跳ぶ。プレビュー欄は手元の本文から当たりの行を印つきで見せる。ブックマークの対象ではない。候補はどの記号で開いても作る（ADR 0060 の「候補の列は開くときに 1 回作る」のまま・開いた後に `^` を打てば絞り込みだけで見える）。費用は件数 × タブの数に比例するが、上の同じ測定で診断 1,000 件の文書の Ctrl+P を開いて閉じる 1 回は 2.1〜2.5 ms（診断なしは 0.2 ms）で、開く操作 1 回の費用としては小さいので、`^` のときだけ作る形にはしない。プレビュー欄の帯の位置は範囲を確かめて読む（面を開いている間に読めなかったタブが帯から外れ得る）。
- **費用**: lsp がオフ・診断が無いとき、打鍵の道には何も足さない（鍵を押したときだけ診断の欄を 1 つ読む・一覧は面を開くときだけ作る）。新しい設定の鍵・色のトークンは足さない。
- **契約**: 新しい scope `--diagnostic-jump`（`tests/unit/DiagnosticJumpTests.cpp`・跳びの折り返しと回数・同じ位置を 1 つに数える・札の文・長い文の切り方・表の行・engine の効果と失敗の歩・F8 / Shift+F8・`]d` `''` `2]d` `[d`・本文を変えない・一覧の順と行の文字・ほかのタブの候補で切り替えて跳ぶ）。`--lsp-diagnostics` の期待を「文の全部・source・code」に改めた。#1946 のレビュー R3 の後に足した契約: 古い hover の答えが札を消さない・上書きしない、`qa]dxq` の `@a` と `nnoremap Q ]dx` が跳んだ後の残りを流し診断が無ければ打ち切る、`i<C-o>]dZ<Esc>` と `u`、IME の変換中の F8・INSERT の F8・オペレータを待つ間の F8、負の整数の `code`。

## 追補（2026-11-23・#1960・設計席の決め・施主の試用で出た不具合）: 開いたフォルダの中のプロジェクトでも印を探す

段 S3 の「root の決まる順」の (a)「設定の `root` があり文書がその下にある → 設定の `root`（探さない）」を改める。フォルダ `D:\NeNeNib` を開いた（設定の `root`）まま、3 段下の `hello-rust\src\main.rs` を開くと rust-analyzer が `D:\NeNeNib` で起き、`failed to find any projects` で診断が出なかった（`hello-rust\Cargo.toml` がある）。開いたフォルダの中に複数のプロジェクトがある形（モノレポ・作業フォルダ）で印を 1 回も探さないのが原因。

- **上限つきで印を先に見る**: 文書が設定の `root` の下にあれば、文書のフォルダから**設定の `root` まで**上へ印を探し、見つかればそのフォルダ、見つからなければ設定の `root`。設定の `root` より上へは出ない（上限のフォルダ自身の印は見る）。文書が設定の `root` の直下にあれば、印の有無で答えが変わらないので探さずに設定の `root`（port を呼ばない）。設定の `root` の外の文書・設定の `root` が無いとき・パスの無い文書は段 S3 のまま。印の優先の順（`vim.fs.root` と同じ意味）は上限の中で変えない。
- **上限は頼みの欄**: `LanguageRootRequest` に `ceiling`（`std::optional<FilePath>`）を足した。頼みを作るのは `EditorControllerLanguageRoots.cpp` の `language_root_request` の 1 本（`document_root` と `seek_language_root` が同じ頼みを作る）。上る列 `lsp_root_folders(folder, ceiling)` は、上限が文書のフォルダを含む（`folder_contains`）ときだけ、上限の長さ（末尾の区切り 1 つを除く）を「上れる下限」に重ねる（ドライブの根・共有の根で止まるのと同じ所・`lsp_root_found(folder, ceiling, language, present)`）。文書を含まない上限は無いのと同じ。adapter の `language_root_on_disk` は頼みをそのまま受ける。
- **区切りの形を畳んで比べる**（#1963 のレビュー M1 / R1）: 「同じフォルダか」は core の `same_folder`（`FileFolder.hpp`）の 1 本で、ASCII の大小・`\` と `/`・末尾の区切り 1 つを畳む（根の `C:\` と `\` は根のまま）。末尾の区切りを除いた形は `folder_spelling` の 1 本で、`folder_contains`（`C:\work\` は `C:\work` を含む）・`same_folder`・上る列の上限（`lsp_root_folders` の下限）が同じ形を使う。直下の判定（`document_root` の近道）・覚えの鍵・席の鍵（`serving_slot`）も `same_folder` で比べる（application の `same_language_root` は文字の大小だけを畳んでいたので消した）。`:set root=C:\work\` や `:set root=C:/work` でも、`C:\work` の直下の文書は探さずに設定の `root` で、上の印へ登らない。
- **覚えの鍵**: `same_language_root_request` は上限も比べる（`same_folder`）。設定の `root` を変えると同じフォルダでも別の頼みになり、古い答えを使わない。`HeldLanguageRoot` は前から設定の `root` を鍵に持つ。
- **席の鍵と起こし直し**は段 S2 / S3 のまま。同じ言語で root の違う文書を行き来すると、それぞれの root の席が受ける（席は 4 つで、満ちれば最も前に使った席が譲る）。
- **静けさ**: オフ・命令の無い言語・起動・切り替え・打鍵の道で port を呼ぶ回数は変わらない（頼むのは `consider_language_server` の中の 1 か所のまま）。オンで設定の `root` の下の（直下でない）文書を開いたときに、頼みが 1 回増える（前は 0 回）。答えを待つ間はその文書を受ける席が無いのも段 S3 のまま。
- **契約**: `--language-root` の `verify_configured_root` を「設定の root の下でも上限つきで頼む・印が無ければ設定の root」に改め、`verify_project_inside_configured_root`（再現の形で `hello` が root・直下の印は設定の root・上にだけある印では上へ出ない・直下の文書は探さない）と `verify_climb_ceiling`（上る列が上限で止まる・大小と末尾の区切り・含まない上限・覚えの鍵）を足した。adapter の `nib_language_root_tests` に上限の下で止まる・上限のフォルダ自身の印を見るを足した。#1963 のレビューの後に足した契約: `verify_configured_root_spelling`（`:set root=C:\work\` と `C:/work` で直下の文書は頼まない）・`verify_ceiling_changed_while_waiting`（答えを待つ間に `:set root=` を変えると新しい上限で頼み直し、古い上限の答えを使わない）・`verify_folder_contains` に末尾の区切りと `same_folder`・`verify_climb_ceiling` に `C:\work` と `C:\work\`・`verify_root_key` は答えの前に「まだ起きない・頼みが 1 回」。
