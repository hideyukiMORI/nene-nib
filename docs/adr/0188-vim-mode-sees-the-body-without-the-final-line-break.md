# ADR 0188 — Vim のモードは、最後の改行を除いた本文を見る（改行で終わる本文の行の数を Vim に揃える）

- 状態: 受理（施主決定 D94・2026-11-15。実装は別の Issue・受理は D41 の形）
- 日付: 2026-11-15
- Issue: #1739（形）・V-1673 の後続 F1
- 規則: ARC-001 / ARC-003 / ARC-012、CPP-002 / CPP-005、QLT-014、ADR 0010（改行の形）/ 0052（`Edit.restore`）/ 0054（oracle と fixture）/ 0181（`VimStep.change`）、施主決定 D82（通常モードは Windows の標準）

## 文脈

改行で終わる本文（`a\nb\n`）を、Vim は 2 行（`eol` のバッファ）として扱い、Nib は 3 行目が空の 3 行として扱う（`TextBuffer::line_count()` は改行の数 ＋ 1）。通常モードはこの形で正しい（メモ帳は最後の改行の後ろにキャレットを置ける・D82）。Vim のモードでは、次がどれも 1 行ずれる（2026-11-15 22:03〜22:11 の実測・Vim 9.1 `-u NONE -es` と PR #1673 の HEAD `1c25f341` の `nib_vim_replay`・表は `D:/NeNeNib/temp/f1-eol/table.md`）。

| 鍵（本文 `a\nb\n`） | Vim | Nib |
|---|---|---|
| `:g/^$/d` | 変えない（Pattern not found） | `a\nb`（最後の改行が消えて未保存） |
| `:$d` | `a\n`・レジスタ `b\n` | `a\nb`・レジスタ `\n` |
| `:%d` `ggdG` | 空・レジスタ `a\nb\n` | 空・レジスタ `a\nb\n\n` |
| `:%s/^$/X/` `/^$` | E486 | 3 行目に当たる |
| `G` `:$` | 2 行目 | 3 行目 |
| `Gdd` | `a\n` | `a\nb` |
| `GA` の後の `z` | `a\nbz\n` | `a\nb\nz` |
| `:%s/$/;/` | `a;\nb;\n` | `a;\nb;\n;` |

改行で終わらない本文（`a\nb`）では 26 の鍵のうち 25 が一致する（残りは未実装の `:m`）。今の fixture は全部が改行で終わらない本文で、oracle（`eng/vim-oracle.py` の `measure`）は改行で終わる本文を断るので、この形は 1 件も守られていない。

施主の決め: Vim に寄せる（2026-11-15 18:42）。Vim のモードでは最後の空の行を画面からも消す（同 22:1x「Vim に揃えて」）。

## 決定

1. **文書は Vim の `eol` に当たる旗を持つ。** 旗は「本文が空でなく、最後が改行で終わる」のときに立つ。決めるのは、文書を開いたときと、通常モードから Vim のモードへ入った後にその文書が最初に Vim のモードで見えるとき（アクティブの文書は入ったとき、通常モードの間に置いたタブは広げたとき・モードは窓全体で 1 つ・V-1761 の M2）の 2 つだけで、Vim のモードの間は本文の終わりを見て決め直さない（Vim のモードのままのタブの切り替えでも決め直さない）（`o<Esc>` で空の本文が `\n` になる今の fixture 77 件は旗が立たないまま。0 バイトのファイルを開いた Vim は `&eol` が立っている。Nib は空の文書に旗を立てず、oracle は空の入力のときだけ `setlocal noeol` を流して同じ模型で測る・#1741 の実測）。旗は文書ごとの値で、設定に入れない。
2. **旗が立っている間、engine には最後の改行を除いた本文を渡す。** 入口は `EditorController::measured_vim_step` の 1 か所（CRLF なら 2 バイトを除く）。engine の位置は本文の位置と同じなので、engine が返す編集はそのまま本文に当たり（最後の改行の手前に入る）、undo・マーク・保存の判定・`VimStep.change` は変えない。engine の中の `line_count()` を呼ぶ約 110 か所には触れない。
3. **縁は 3 つで、engine の印で扱う。** (a) 全部の行を消したら（`ggdG` `:%d` `VGd`・1 行での `dd`）、controller が最後の改行も消して空の本文にする。旗は下ろさず「空で、旗が立っている」状態にし（保存は 0 バイト・Vim の空のバッファと同じ）、その後 Vim のモードの編集で本文が空でなくなったら、controller が同じ編集（同じ undo の単位）の中で最後の改行を足し直す（Vim の `eol` のバッファと同じく `ggdGp` は `\na\nb\n`・`ggdGix<Esc>` は `x\n`）。undo で空に戻れば「空で、旗が立っている」に戻る。通常モードで打った本文には足さない（D82）。engine は「全部の行を消した」を `VimStep` に印で添え、印は「1 行目から最後の行までを消した」と行で決める（バイトの範囲で決めない。最後が空の行の本文 `a\n\n` では、空の行を残す `dd` と全部の行の削除が同じバイトの範囲になる・V-1761 の M1。controller が編集の中身から推し量らない・ADR 0181 と同じ考え）。(b) 0 バイトで開いた文書と新しい無題は旗が立たないので、足した本文の形は今の fixture のまま。(c) 空の 1 行だけの本文（`\n`）は、engine が空の本文と区別できるように、渡す側が「1 行ある」を印で添える（`:d` がレジスタに `\n` を書く）。
4. **Vim のモードの画面も、除いた本文で描く。** 旗が立っている間、frame の行の数・行番号の欄・`hlsearch` の一致・スクロールの終わりは、最後の空の行を数えない。通常モードへ戻ると今までどおり最後の空の行が見え、キャレットを置ける（D82）。通常モードで最後の空の行に居て Vim のモードへ入ったときは、キャレットが最後の行へ上がる（`vim_resting_caret` が除いた本文の上で寄せる・Vim の `check_cursor` と同じ）。
5. **保存は変えない。** 本文のバイト列をそのまま書く（`encoded_parts`）。改行で終わらない本文に改行を足す Vim の `fixeol` は入れない（別の判断・ファイルを勝手に変えない）。
6. **fixture で守る。** oracle の `measure` の断りを外し、`run_vim` が `&eol` を読んで本文を「つないだ行 ＋ `eol` なら改行」で作る（空のバッファは `wordcount().bytes == 0` で見分ける。`line2byte(line('$') + 1)` は `ggdG` の後の空を見分けない）。空の入力のときだけ、鍵の前に `setlocal noeol` を流す（決定 1 の模型。`eol` は書き込みにしか効かないので鍵の振る舞いは変わらない）。測定の領域の変更なので全件を再生成する（既存の行は同じ値になる見込み・違いが出たら止めて報告）。再生の道（`nib_tests`・窓の道・`nib_vim_replay`）は、製品と同じ 1 本の関数で旗を決める。改行で終わる fixture は上の表の鍵を本文 `a\nb\n` `a\n\nb\n` `\n` `a\n` で足す。
7. **費用。** 打鍵ごとに除いた `TextBuffer` を作り直さない（文書が旗と一緒に持ち、本文が変わったときだけ作る・形は実装で測って決める）。8 本の速さのゲートで悪化なし（QLT-014）。

## 強制

- engine に渡す本文を作る所は 1 か所: **active**（#1741）。除いた本文の正本は `EditorState::vim_text()` の 1 本で、`measured_vim_step`・`VisualTextView`・frame の行の数がこれを読む。旗を決める口は `vim_end_of_line_decided`（開いたとき・Vim のモードへ入ったとき・入った回数が違う置いた束を広げるとき）。全部の行を消すのは `EditorController::remove_every_line`、空の本文に足す改行と engine を通らない全文の削除は `EditorController::vim_end_of_line_kept`（`replace` の 1 か所）、隠した行へ着いたキャレットと選択の端を収めるのは `keep_vim_character` の 1 か所。契約 `nib_tests --vim-eol` が入口・通常モードの最後の空の行・行き来・置いたタブ・保存のバイト列・全部の行を消した後に足す形と undo・engine を通らない Ctrl+End と Ctrl+A を守る。
- 改行で終わる本文の fixture: **active**（#1741）。oracle の変更と全件の再生成で既存の行の値は 1 つも変わらず、`eol-` の fixture を本文 `a\nb\n` `a\n\nb\n` `\n` `a\n` と最後が空の行の本文 `a\n\n` `x\ny\n\n` で足し、全部の行を消した後に足す鍵（`ggdGp` `ggdGix<Esc>` など）も持つ。
- 8 本の速さ: **active**（QLT-014）。

## 結果

得られるもの: 改行で終わる普通のファイルで、`G` `dd` `VG` `:$` `:%` `:g` `:v` `/^$` と行単位のレジスタが Vim と同じになる。`:g/^$/d` が最後の改行を消さない。
失うもの・残る穴: 「通常 ⇄ Vim」を切り替えると最後の空の行が出たり消えたりする。Vim のモードでは最後の改行の後ろに文字を足せない（`Go` で行を足す・Vim と同じ）。`fixeol` が無いので、改行で終わらないファイルは保存しても改行で終わらない（Vim と違う・今までどおり）。0 バイトで開いた文書と新しい無題に打った本文を、Vim は改行で終わる形で保存し、Nib は改行で終わらない形で保存する（`fixeol` を入れない判断と同じ側・保存のバイト列を勝手に変えない・Vim 9.1 の実測: 0 バイトのファイルで `o<Esc>` の後に `\n\n`・`ix<Esc>` の後に `x\n` を書く・`D:/NeNeNib/scripts/20261116/1741/probe_empty.py`）。

## 却下した選択肢

| 選択肢 | 却下の理由 |
|---|---|
| Ex の番地と `:g` `:v` の行の列だけ寄せる | `G` `dd` `VG` `/^$` がずれたまま残る。`G` の後のキャレットが `$` より下になり、`:s` が E16・`:.,$d` が E493 になる（Vim に無い状態） |
| engine の中の行の数を全部書き換える | `line_count()` を呼ぶ約 110 か所と検索の器に触る。入口の 1 か所で同じ振る舞いが作れる |
| 「今、改行で終わるか」で毎回決める | `o<Esc>` などの後に Vim の答えが改行で終わる今の fixture 77 件とぶつかる。Vim も開いたときの旗で決める |
| 見た目は今のまま（最後の空の行を Vim のモードでも描く） | Vim では行けない行が見え、行番号の数が Vim と合わない（施主が「Vim に揃えて」と決めた） |
