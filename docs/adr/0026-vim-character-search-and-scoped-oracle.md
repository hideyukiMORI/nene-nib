# ADR 0026 — 行内文字検索は入力待ちと検索記憶を分け、既存の範囲と効果へ接続する

- 状態: 受理
- 日付: 2026-09-20
- Issue: #72
- 影響する規則: ARC-001 / ARC-004 / ARC-007 / CPP-002 / CPP-004 / CPP-011 / CPP-012 / QLT-001 / QLT-008 / QLT-012 / QLT-013 / CNF-010

## 文脈

既存の `vim_step` は回数、operator、NORMAL / VISUAL の移動と範囲を扱うが、移動対象の次の一文字を待つ状態を持たない。
`f/F/t/T` ではその待ち状態と、完了後に `;` / `,` で再利用する検索の記憶を区別する必要がある。
本文・選択・undo の所有者、UI の入力経路、範囲から削除・変更・yank を行う経路はすでに存在する。

また、oracle の `--regenerate` は未変更の329件も測り直す。QLT-001 / QLT-012 に従い、今回の追加ケースだけを測り、関連入力が同じ既存結果を維持する入口が必要である。

## 決定

1. `VimState` に省略可能な文字待ちの検索種別と、完了した文字検索の対象・種別を分けて持つ。検索種別は `f/F/t/T` の閉じた4値。本文や選択位置を記憶しない。
2. 文字待ちは通常の数字・動作キーの解釈より先に次のキーを受ける。対象が数字や `f` 自身でも文字として消費する。待ちに入る時点では回数・operator・VISUALのanchorを維持する。
3. 行内のUTF-8走査は既存の `TextBuffer` と `Utf8` の経路を使う。改行を越えず、回数に比例して同じ走査を繰り返さない。未発見と「成功したが移動先が現在位置」は区別する。
4. 検索から得た移動先を既存の `VimMoveTo` / `VimSelect` に、operator範囲を `VimMotionRange` と `performed` に渡す。専用の削除・yank・undo・画面操作経路を作らない。
5. 通常の操作完了は検索記憶を維持し、文字待ちと回数とoperatorを消す。モード切替でも検索記憶を保つ。新しいエディタ状態の初期化で記憶を空にする。検索の取消・未発見は元のモード・選択・欲しい列を維持する。保留を始める段階で欲しい列を消さない。
6. `VimRegisterKind` に `uninitialized` を加え、初期レジスタを「空・未設定」とする。成功した空範囲のyankは「空・characters」であり、文字列が空であることだけから種別を推測しない。範囲の種別は従来の `characters` / `lines` のみ。未設定のputは既存の空文字ガードで何もしない。空のdelete/changeでは既存レジスタを維持する。
7. UIの新設、設定や保存形式の変更、一般検索、テキストオブジェクト、矩形選択は含めない。

## oracleの対象指定

`--regenerate --only <名前の接頭辞> --reuse-ref <commit>` で対象を指定する。接頭辞は複数指定でき、省略時の全件生成も維持する。
再利用元は既存のGit commitにある `fixtures.json`、`VimFixtures.hpp`、生成スクリプトの組。期待値の第2の保存先を作らない。

再利用には次をすべて要求する。

- 元の生成物のSHAと本数が元のfixture入力と一致し、生成行の名前・順序・数が一致する。
- 実際に使うVimの版・実行ファイルの場所・既定設定と、測定処理が同じである。測定処理は生成器の測定部分の構文木で比較し、コメントなどは測定変更としない。
- 未選択fixtureの入力全体が元と同一である。未選択の新規・変更fixtureや一致しない接頭辞は拒否する。
- 再利用する期待値の行をそのまま維持する。今回の全入力から生成物のSHAと本数を更新し、CNF-010の契約を維持する。

測定に失敗した場合は既存生成物を書き換えない。元のcommitと今回の対象・測定数・再利用数を検証記録に残す。

## 境界の実測

固定したVim 9.1で `getcharsearch()` / `getcurpos()` / 本文・位置・レジスタを観測し、次を確定した。生の記録は `out/issue72-oracle/`、再生可能な入力は `char-search-` 接頭辞のfixtureとする。

- `f/F`は対象文字へ、`t/T`はその手前へ移る。現在位置自体は検索しない。同じ行の指定回数目がなければ位置を一切変えない。文字を確定した新しい検索は、未発見でも検索記憶を更新する。
- `;` は元の種別、`,` は前後を反転した種別で実行し、どちらも検索記憶の元の種別を書き換えない。記憶がなければ何もしない。
- `t/T`の反復では、最終回数が1で隣接文字への一致が現在位置を返す場合だけ、その一致を飛ばす。回数が2以上なら通常の指定回数目である。`axxxxb`で`tx;`と`tx2;`はともに列2、`tx3;`は列3。operator側とmotion側の回数は既存の飽和する掛け算で求め、その最終回数に同じ規則を使う。
- forwardのoperator範囲は現在文字から移動先文字までを含む。backwardは移動先から元の現在文字の直前まで。`abxc`の`dfx`は`abx`、`axbc`の`$dFx`は`xb`、`$dTx`は`b`を削除する。`d/c/y`はこの同じ範囲を使う。
- 隣接した`t`は移動が0でも成功で、`axb`の`dtx`は`a`を削除する。後方向の隣接`T`は空範囲で、`ax`の`$cTa<Esc>`は本文を変えずINSERTに入ってから列1へ戻る。未発見と同一位置への成功をoptionalの有無で区別する。
- 先に非空のレジスタを持った場合、空の文字単位範囲へのyankは空の文字単位レジスタへ更新する。空範囲へのdelete/changeは旧レジスタを維持する。この差は既存のyank経路で扱い、検索専用のレジスタ更新を増やさない。
- VISUALではanchorとモードを維持してcaretだけを動かす。選択から編集範囲を得るのは既存の `vim_visual_range`。`vf<Esc>`は検索待ちだけを取り消し、VISUAL自体は終了しない。
- Esc、Backspace、矢印、Home/End、PgUp/PgDnは待ち中の検索を取り消し、旧検索記憶を保つ。キーの通常の動作へは再解釈しない。EnterはU+000D、Ctrl-r/d/u/f/bはU+0012/0004/0015/0006/0002という検索対象になり、行内で未発見でも記憶を更新する。対応する制御キーは文字値へ写して同じ検索へ渡す。
- `$`のあとで検索に失敗する、または待ちを取り消す場合、欲しい列の「行末」を保つ。成功した検索だけが移動先の列へ更新する。短い行を経て長い行へ `j` で移る実測でも確認した。
- UTF-8の日本語・アクセント文字・非BMP文字をcode point境界で検索する。CRLFのCR/LFは行内容に含めず、次行・前行へ検索を漏らさない。

`:normal!` が失敗後のキーを捨てる場合やundoの区切りをまとめる場合は、oracleの限界と製品の振る舞いを混同しない。

## 検証

追加fixtureと直接影響する既存motion/operator/stateの代表を再生し、文字待ち・検索記憶・取消・undo境界を単体テストする。
対象指定ツールは選択したケースだけの測定、未変更行の維持、不正な再利用の拒否を短い正例・反例で確認する。
変更targetのDebugビルド（ASan/UBSanとtidy）、中核のシンボル境界、生成物整合を確認する。
nativeは文字待ち・Unicode・operatorの既存Win32入力接続だけを選ぶ。無関係なGUI・設定・テーマ・全件oracleの再測定は行わない。

Unicodeのnative確認はWM_CHARから届くUTF-16の一文字（BMPとサロゲート対）がengineへ届く範囲。NORMAL/VISUALのIMEを閉じ、compositionを受け付けない既存方針（ADR 0014）は変更していない。検索待ちでのIME変換入力を新たに実装・検証したとは扱わない。

## 却下

- UIが次の文字を待って独自の編集を行う: 純粋なengineと範囲の正典から逸脱する。
- operator用・VISUAL用に検索走査を複製する: 同じ検索の意味が分岐する。
- 待ち状態と検索記憶を一つのoptionalで表す: 取消によって以前の検索を消すなど、寿命の異なる事実が混ざる。
- 新しい期待値ストアや汎用の検証キャッシュを作る: 今回必要なのは既存生成物の限定的な再利用だけである。
