# ADR 0035 — 矩形 VISUAL（`Ctrl-v`）は仮想桁の矩形を 1 本の範囲関数で決め、行ごとの範囲の列として編集する

- 状態: 受理（固定 Vim 9.1 の 228 ケースで確認し、決定 2・4・5・6・7 を直した。下の「補足」）
- 日付: 2026-09-22
- Issue: #112
- 影響する規則: FR-003 / ARC-001 / ARC-004 / ARC-007 / ARC-009 / CPP-002 / CPP-004 / CPP-006 / CPP-011 / CPP-012 / QLT-001 / QLT-008 / QLT-012 / QLT-013 / CNF-010

## 文脈

FR-003 の T2 に残る VISUAL の 3 つめ、矩形（`Ctrl-v`）を入れる。VISUAL は `VimMode` の値で種類を持ち（`visual` / `visual_line`・ADR 0018）、選択の正本は `EditorState` の `Selection`（anchor と caret の 2 つの `Offset`）で、`vim_visual_range` 1 本が「選択が覆う本文の範囲」を決めて描画・Ctrl+C/X・`d x y c` が同じ範囲を使う（ARC-001）。矩形は行ごとに別々の範囲になるので、1 つの `VimMotionRange` では表せない。桁は ADR 0034 の仮想桁で数える（Tab と全角の上で Vim と一致させるため。`$` は各行の行末まで）。

レジスタは `VimRegister{text, kind}` で種類は `characters` / `lines`（ADR 0015）。Vim の矩形レジスタは幅を持ち（`getregtype()` が `^V{幅}` を返す）、短い行へ貼るときは空白で埋める。

`.` は鍵の列と範囲の大きさで再生する（ADR 0030 / 0033）。矩形の変更は「行数 × 幅」の大きさを持つ。

窓の Ctrl+V はいま OS の貼付で、Vim の NORMAL / VISUAL でもそのまま貼付になっている。Vim では `Ctrl-v` が矩形の入口なので衝突する。Vim ソースは読まず、help（`:help blockwise-visual` / `:help v_b_$` / `:help v_o` / `:help v_O` / `:help v_b_r` / `:help blockwise-register`）と実測を根拠にする。

## 決定

**矩形は `VimMode::visual_block` として 3 つめの VISUAL にし、選択は anchor と caret のまま「仮想桁の矩形」と読む。行ごとの範囲は core の純関数 `vim_block_range` 1 本が決め、描画・Ctrl+C/X・`d x y r` と `.` の大きさがそれを使う。矩形の編集は「行ごとの範囲の列」を運ぶ効果で、controller が 1 つの undo 単位として写す。**

1. **モードと入口**: `VimMode` に `visual_block` を足す（switch の網羅性で写し漏れが落ちる）。NORMAL / `v` / `V` からの `Ctrl-v`（`VimSpecialKey::control_v`）で入り、`visual_block` での `v` / `V` は種類の切替、`Ctrl-v` と Esc は NORMAL へ戻る。INSERT の Ctrl+V は窓の OS 貼付のまま（Vim の literal 挿入は入れない）。Vim の NORMAL / VISUAL では Ctrl+V は矩形の鍵になり、OS 貼付は INSERT と通常モードだけ（決定 9）。
2. **矩形の幾何**: 左右の仮想桁は anchor と caret の `virtual_column` / `virtual_column_end`（ADR 0034）の小さいほうと大きいほう。`$`（`VimColumnWish::at_line_end`）が立っていれば右端は各行の内容の終わり。上下は anchor と caret の行。行ごとの範囲は `vim_block_range(text, selection, wish) -> VimBlockRange`（行ごとの `OffsetRange` の列と、左の仮想桁と幅）1 本が決め、左の桁より短い行は「行の内容の終わりの空範囲」、Tab や全角の途中に桁が掛かる文字は範囲に含める（Vim の既定・`virtualedit` 無し）。
3. **移動**: 既存の移動の表をそのまま使い、`j` `k` は欲しい列（仮想桁・ADR 0034）で着地する。`o` は対角の角へ、`O` は同じ行の反対の角へ（~~anchor と caret の桁だけ入れ替え~~ → 矩形の左右の仮想桁を使い直す・追補 #1090）。
4. **編集**: `d` `x` は効果 `VimRemoveBlock{ranges}`（行ごとの範囲の列・上の行から）、`r` は `VimReplaceBlock{ranges, character}`、`y` は無名レジスタへ。controller は範囲の列を後ろの行から順に写し、履歴は前後で 1 回ずつ閉じて undo 1 単位にする。削除後のキャレットは矩形の左上（Vim の実測に従う）。`c` `I` `A` `C` `>` `<` `J` `~` `u` `U` `p`（VISUAL の中の貼付）は範囲外（次の縦切り）。
5. **レジスタ**: `VimRegisterKind` に `block` を足し、`VimRegister` に `width`（仮想桁の幅）を足す。本文は行を LF で結んだもの（末尾の改行なし）。`characters` / `lines` では `width` は使わない。~~`$` は「行末まで」の印~~ → **`$` の印は要らない**（補足 2）。
6. **矩形の貼付**: NORMAL の `p` / `P` は種類が `block` なら効果 `VimInsertBlock{at, lines, width}` で、キャレットの行から下へ 1 行ずつ同じ仮想桁に挿し、行が短ければ空白で埋め、行が足りなければ末尾に行を足す（Vim の `:help v_b_p` の既定）。回数は行ごとの繰り返し。貼付後のキャレットは Vim の実測に従う。
7. **`.`**: ADR 0033 の `VimVisualExtent` に `VimBlockExtent{lines, width | 行末まで}` を足し、再生は左上をキャレットにして同じ大きさの矩形を選び直す。鍵の列は `d x r` のまま。
8. **描画と OS の経路**: `EditorFrame` の各行の `SelectionSpan` は `visual_block` のとき `vim_block_range` の行ごとの範囲から作る（application の 1 か所。renderer は変えない）。Ctrl+C / Ctrl+X は矩形の本文を LF で結んで OS のクリップボードへ置き（改行は OS の形に直す既存の 1 か所）、Ctrl+X は `VimRemoveBlock` と同じ写しを通る。
9. **鍵の写し**: 窓の側で Ctrl+V を `VimSpecialKey::control_v` に写すのは、Vim モードの NORMAL / VISUAL のときだけ（既存の「窓の側で 1 か所だけ `VimKey` に写す」場所）。通常モードと Vim INSERT は OS 貼付のまま。
10. **oracle**: 鍵の記法に `<C-v>` を足す（`KEY_NAMES`）。`getregtype()` が返す `^V{幅}` を報告の `register_kind` にそのまま残し（`\x16` ＋ 10 進の幅）、fixture の生成側と unit の照合側で同じ文字列を比べる。

## 補足（2026-09-22・Issue #112 の実測）

実装の前に固定 Vim 9.1 を 228 ケース測った（`out/issue112-oracle/probe{,2,3,4,5,6}.py` の 109 / 39 / 25 / 21 / 20 / 14。`out/` は追跡外なので作業機にだけある）。Vim ソースは読んでいない。決定を 6 点直し、合わせられなかった差を 6 点残す。

**直した決定**

1. **決定 2 の「掛かる文字は範囲に含める」は半分だけ正しい。** 端が Tab や全角の途中に掛かると、Vim はその文字を**丸ごと外して掛かった桁ぶんの空白に置き換える**。しかも「取る空白」と「消したあとに残す空白」が逆で、取るのは矩形の**内側**の桁、残すのは**外側**の桁である（`	zz` の Tab（1〜8 桁）を 3〜9 桁の矩形で取ると `      z`＝内側 6 桁ぶんの空白、消すと `  z`＝外側 2 桁ぶんの空白）。`VimBlockLine` はこの 4 つ（`lead` / `tail` / `keep_lead` / `keep_tail`）を持つ。
2. **決定 5 の `$` の印は要らない。** `getregtype()` は `$` で取った矩形にも**有限の幅**を返す（`ab` / `cdef` / `gh` を `$` で取ると `^V4`）。Vim は取るときに「覆った行のうちいちばん長い行」へ幅を畳むので、レジスタに残る `$` は無い。`VimRegister.width` は `VimBlockWidth`（桁の数）1 つで足りる。
3. **決定 2 の `$` の右端は「行ごと」ではなく「いちばん長い行」で一度に決まる。** 結果は同じだが、幅が 1 つの数になるので矩形の形も `left` と `width` の 2 つで閉じる。
4. **決定 4 の `r` は文字の数ではなく桁の数だけ書く。** Tab 1 つを覆った矩形の `r` は Tab の桁数（6〜8 個）の文字になる（`ab<Tab>cd` の 3〜8 桁を `rZ` すると `abZZZZZZcd`）。
5. **決定 6 の貼付は、貼り先の行に本文が続くときだけ右を空白で埋める。** レジスタの行が幅より狭いときの埋めは矩形の形を保つためのもので、行末に貼るときは付かない。貼る桁が Tab の途中に落ちたら、その Tab だけを左右の空白に割る（ほかの文字は割らない）。
6. **決定 7 の再生は「選択の角」からではなく記録した幅から矩形を決める。** 角から読み直すと、短い行へ畳まれた角のぶんだけ矩形が痩せる（`cdef` / 空行 の上で 2 桁の記録を再生すると 1 桁になってしまう）。固定 Vim も `redo_VIsual_busy` のあいだは角を読み直さないので、`VimState` に `replayed_block` を 1 つ置いて同じ形にした。

**合わせていない差（fixture に採っていない）**

- **`.` の直前に `$` を打つと、固定 Vim は桁で記録した矩形も「行末まで」で再生する**（`curswant` が MAXCOL のまま再生に漏れる）。この engine は記録した大きさだけを使う。`.` の fixture は `$` を直前に打たないものだけを採った。
- ~~**VISUAL の `u` / `U`（小文字化・大文字化）は範囲外だが、固定 Vim は鍵を食べて VISUAL から抜ける。** この engine は矩形のまま残る。~~ → 矩形の `~` `u` `U` は追補（#959）で効くようになった。
- **`.` のあとの `u`** は oracle（`:normal!` 1 回を 1 つの undo 単位にする）と単位が違う。矩形 1 つが 1 単位であることは `--vim-visual-block` の契約で測る。
- **貼る桁が Tab 以外の文字（全角）の途中に落ちたとき**、固定 Vim はその文字を貼った本文の後ろへ送る。この engine はその文字の先頭へ挿す。
- **矩形レジスタに Tab が入っているときの幅の数え方**が違う（固定 Vim は各文字を 0 桁目から数えるので Tab が常に 8 桁、この engine は行頭から順に数える）。
- **行が矩形より手前で終わる行の `y` `d` `r`** は 1 回の `:normal!` では再現しない（走査の失敗が残りの打鍵を捨てる・Issue #87）。fixture に採れないので `--vim-visual-block` の契約で測る。

## 追補（2026-10-28・#959 矩形の `~` `u` `U`）

決定 4 の「`~` `u` `U` は範囲外」を外す。矩形 VISUAL の `~` `u` `U`（ADR 0015 の決定 10 の大小文字）は、行ごとに `r` と同じ範囲（`VimBlockLine.range`・端で切れた Tab や全角も含む）の ASCII の英字だけを変え、効果は `r` と同じ `VimReplaceBlock`（行ごとの `VimBlockEdit` の列・undo 1 単位）。切れた文字は大小が無いので空白に割らずそのまま残る。`$` の矩形は各行の末尾まで、矩形に届かない短い行と幅 0 の行は飛ばす。キャレットと `u` の戻り先は矩形の左上（左上が切れた Tab ならその Tab の先頭）。レジスタは書かない。`.` は決定 7 と補足 6 の規則（記録した大きさで選び直す）のまま。非 ASCII の大小は #781、~~矩形の `>` `<` は #770 で、いまは鍵を拒んで矩形のまま残る~~ → 矩形の `>` `<` は追補（#1042）で効く。根拠は固定 Vim 9.1 の oracle の `block-case-` の fixture 10 件（`<C-v>jlU`・`<C-v>$U`・`$` の矩形と空行・`~`・`u`・短い行・全角の混在・端の Tab・左上の Tab・`.`）。

## 追補（2026-10-29・#1042 矩形の `I` `A` `c` `C` `>` `<`）

決定 4 の「`c` `I` `A` `C` `>` `<` は範囲外」を外す（`J` と VISUAL の中の `p`、矩形への追記 `"A` は後続）。根拠は固定 Vim 9.1 の oracle の `block-insert-` の fixture 104 件（最初に測った 69 件と、差分 fuzz が見つけた形と追いの測定とレビューの 35 件）。

1. **INSERT は 1 行目だけに打ち、Esc で残りの行へ写す。** 状態 `VimState.block_insert`（`VimBlockInsert`：最初の行・行数・写す向き `VimBlockInsertSide`・桁・打ち始めた所・入る前の 1 行目のバイト数・Esc の後のキャレット）を矩形の入口だけが立て、Esc（`vim_resting_from`）と入力を捨てる `input_discarded`（窓の割り込み）が消す。INSERT の中の `<Left>` `<Home>` `<End>` の移動では消えず、Esc の行が 1 行目なら写す（`<Down>` で離れたら写さない・実測）。写す本文は「1 行目が入る前より伸びたぶん」（固定 Vim の op_insert / op_change と同じく長さの差で読む）で、回数（`2Iab`）の繰り返しもその後ろに足す。何も打たなければ（`Ctrl-w` `Ctrl-u` で打ち始めより前まで消して 1 行目が縮んだときも）写さない。改行を打って Esc の行が 1 行目でなくなったら `I` `A` は写さず、`c` `C` は今の行番号の行へ写す（Vim の op_change は行を問わない・実測）。1 行の形は `block_insert_edit` の 1 本で、効果は貼付と同じ `VimInsertBlock`（境界 absorb）。controller は写した編集を 1 行目の INSERT の単位（履歴のいちばん上）と 1 つの Edit に畳むので、`u` 1 回で全行が戻り、戻り先は打ち始めた所（`c` `C` は矩形の左上）。IME の確定も打鍵と同じ道を通る。
2. **向きと短い行。** `I` `c` `C` は矩形の左の桁へ写し、その桁に届かない行は飛ばす（行の内容の終わりちょうどなら末尾に付く）。`A` は右の桁の次へ写し、届かない行は空白で埋める。`$` の矩形の `A` は各行の内容の終わり（埋めない）。写す桁が Tab の途中なら Tab を空白に割り、全角の途中なら前を空白で埋めて全角を右へ送る。ただし `A` の 1 行目で右の端が文字の途中に掛かれば、その文字の後ろから打つ（Vim はカーソルを矩形の本文の次へ進める・`.` の再生で実測）。
3. **キャレット。** Esc の後は `I` `A` なら矩形の左上（何も打たなければ、または `<Home>` などで左上より手前へ動いて打てば Esc のふつうの位置）、`c` `C` なら Esc のふつうの位置。
4. **`c` `C` のレジスタ。** `d` と同じく矩形の種類で書き（`VimNumberedRule::by_extent`）、`C` は選んだ矩形を `$` で取り直してから `c` と同じ道を通る。`$` の矩形で矩形に届かない行がレジスタに入れる空白は幅より 1 つ多い（`y` `d` `c` とも・固定 Vim の block_prep は MAXCOL から決めた右端の次の桁まで埋める）。これは既存の `$` の `y` `d` にも効く（`vim_block_range` の 1 か所）。
5. **`>` `<` は矩形の左の桁から字下げを動かす**（ADR 0015 の決定 11 の行単位とは別の形・Vim の shift_block）。空行と左の桁に届かない行は動かさない。`>` は左の桁の直前に続く空白（端に掛かった Tab も含む）から後ろへ続く空白までをまとめ、shiftwidth × 回数を足した幅を noexpandtab で作り直す。全角が左の端に掛かるときは、全角を割らずにその前へ「桁 0 から数えた shiftwidth × 回数」の空白を入れる（Vim が ws_vcol を 0 にする癖・実測）。`<` は左の桁から続く空白の幅だけ（多くても shiftwidth × 回数）左へ寄せ、手前の Tab はそのまま残し、足りない桁を空白で埋める。左の端に掛かった文字は Tab でも全角でも空白に割れる（全角の後ろに空白が無くても割れる・実測）。キャレットと `u` の戻り先は矩形の左上。レジスタは書かない。
6. **`.`** は決定 7 と補足 6 のまま（記録した大きさで選び直してから鍵を流す）。矩形の `I` `A` は入るだけで本文を変えないことがあるので、VISUAL の記録は「INSERT へ入る鍵」からも始める。`N.` の回数は VISUAL の `>` `<` の再生に使わない（実測）。
7. **差分 fuzz**: `eng/vim-fuzz.py` の `WORDS` に矩形の後の `I` `A` `c` `C` `>` `<` を 1 行ずつ足した（生成器の版は 3）。

決定 4 の「`~` `u` `U` は範囲外」を外す。矩形 VISUAL の `~` `u` `U`（ADR 0015 の決定 10 の大小文字）は、行ごとに ~~`r` と同じ範囲（`VimBlockLine.range`・端で切れた Tab や全角も含む）~~ → 矩形の仮想桁に丸ごと入る本文（`VimBlockLine.inside`・追補 #1104）の ASCII の英字だけを変え、効果は `r` と同じ `VimReplaceBlock`（行ごとの `VimBlockEdit` の列・undo 1 単位）。切れた文字は大小が無いので空白に割らずそのまま残る。`$` の矩形は各行の末尾まで、矩形に届かない短い行と幅 0 の行は飛ばす。キャレットと `u` の戻り先は矩形の左上（左上が切れた Tab ならその Tab の先頭）。レジスタは書かない。`.` は決定 7 と補足 6 の規則（記録した大きさで選び直す）のまま。非 ASCII の大小は #781、矩形の `>` `<` は #770 で、いまは鍵を拒んで矩形のまま残る。根拠は固定 Vim 9.1 の oracle の `block-case-` の fixture 10 件（`<C-v>jlU`・`<C-v>$U`・`$` の矩形と空行・`~`・`u`・短い行・全角の混在・端の Tab・左上の Tab・`.`）。

## 追補（2026-10-29・#1090 矩形の `O` は左右の仮想桁で角を決める）

決定 3 の `O` を Vim 9.1 の `v_swap_corners` に合わせる。両端の桁を入れ替えるのではなく、決定 2 と同じ左右の仮想桁（両端の文字の `virtual_column` の小さいほうと `virtual_column_end` の大きいほう）を使い直し、anchor の行を左の桁へ・caret の行を右の桁へ寄せる。caret の位置が変わらなければ逆（anchor の行を右・caret の行を左）。寄せは欲しい列の着地と同じ `offset_at_virtual_column`（全角や Tab の途中はその文字の先頭・短い行は VISUAL と同じく内容の終わり）で、欲しい列は caret の行に置いた桁になる（`$` の矩形も `O` で桁に戻る）。実装は `block_column_swapped` の 1 か所。根拠は固定 Vim 9.1 の oracle の `block-swap-corners-` の fixture 24 件（`    x1 ＡＢＣ` / `ＡＢＣ gamma` の `<C-v>jllOy` の再現・全角が左の角・右の角・両方・Tab の角・`$` の矩形・`O` を 2 回・1 行の矩形・上向きの矩形・`O` の後の `j` と `.`）。
## 追補（2026-10-29・#1067 矩形の `r` に幅 2 の文字）

決定 4 の `r` は、行ごとに矩形が覆った仮想桁の数 `w`（`$` の矩形と短い行はその行の本文の幅まで・端で切れた Tab や全角の残りは今のまま空白）を埋める。`{char}` の幅（`display_width` の表・ADR 0034）が `wide` なら `w / 2` 個の `{char}` と、`w` が奇数なら空白 1 つで埋める（Vim の `op_replace` の `numc / 2` と `endspaces`）。奇数の空白は矩形の右端に届いた行だけに足し、右端より手前で終わる短い行と `$` の矩形の行（どの行も Vim の `is_short`）には足さない。`$` かどうかは `VimBlockRange.wish` が運ぶ。ほかの幅の文字は今のまま `w` 個（Tab も 1 桁に 1 つ）。埋め方は `VimStepBlock.cpp` の `replaced_block_fill` の 1 か所。文字単位と行単位の `r` は文字ごとに 1 つのまま（Vim と一致）。`.` は変えない。キャレットと `u` の戻り先は矩形の左上で、左上が切れた Tab や全角ならその文字のあった所（埋めた空白の先頭・Vim は `oap->start` へ戻す）。半角の `r` も同じで、これまでの「空白のぶん右へ寄る」は Vim と違っていた（`block-replace-wide-tab-inside-narrow` で実測）。結合文字を `{char}` にする形は `:normal!` の Vim では結合文字が `r` に渡らず基底の文字だけで置き換わるので範囲外（実測）。根拠は固定 Vim 9.1 の oracle の `block-replace-wide-` の fixture 24 件（幅 1〜4 と `$`・`$` の 2 行・fuzz seed 23 の最小・Tab の上（左上が切れた Tab を全角と半角で）・全角の本文の上と途中で切れる形・3 行の短い行・奇数の幅の短い行と `$` の矩形と右端ちょうどで終わる行・`.`・`u`・比較の半角の `r` と文字単位の `vlr語`）。
## 追補（2026-10-29・#1089 Tab の上の VISUAL のキャレットの欲しい列）

矩形の左右の桁の決め方（両角の `virtual_column` の最小と `virtual_column_end` の最大＝ Vim の `getvvcol` の start / end）は正しく、`VimBlockRange.cpp` は変えない。違っていたのは矩形の角になるキャレットの位置で、VISUAL の移動が欲しい列に覚える桁だった。Vim の `getvvcol` の cursor は、Tab の上では最後の桁だが **VISUAL でキャレットが錨より手前か同じ所にあるときは最初の桁**になる（ADR 0034 の補足 3 の例外）。だから `\t;  abc` の `4l<C-v>0j` は `0` の欲しい列が 1 桁目になり、次の行の 1 桁目へ落ちて矩形の左は 1 桁目（Nib は Tab の最後の 8 桁目へ落ちていた）。`h` `^`（空白だけの行で Tab に止まる）も同じで、`1|` は前から回数の桁。錨より後ろの Tab は最後の桁のまま（`<C-v>jll` で Tab に乗って `j` すると 8 桁目）、NORMAL の `0j` も最後の桁のまま（Vim は NORMAL では Tab の終わりから落ちる）。文字単位の VISUAL（`v0j`）も同じ規則に従う。

決め方は core の `landed_column(text, mode, anchor, moved)` の 1 本で、着地から欲しい列を書く所はすべてこれを通す: `VimMotion` の移動（NORMAL の `landed_step`・VISUAL の `visual_moved`）・VISUAL に入る `[count]v` の広げ（`entered_visual`・回数つきの広げは錨より後ろへ伸びるので最後の桁）・検索の移動（`/` `?` `n` `N` `*` `#`）・`f` `F` `t` `T`・テキストオブジェクトの VISUAL と取消・画面送り（Ctrl-d / Ctrl-u ほか・`zt` ほか）・横送りの押し出し。`wanted_after` は着地の桁を引数に取る。Vim の出どころは `getvcol` の cursor の条件（Tab の上で `VIsual_active` かつ `LTOREQ_POS(pos, VIsual)` なら最初の桁）で、`'selection'` が `exclusive` なら錨に関係なく最初の桁になるが、Nib は `inclusive` 固定なので扱わない。Vim は `curswant` を次の縦の移動の時点で決める（`update_curswant` の遅延）が、VISUAL に入る前に NORMAL で決まった桁は実測でも Tab の最後の桁のまま（`4l0<C-v>jy` と先頭が Tab の文書の `<C-v>jy` はどちらも 8 桁目）で、Nib の「移動の時点で決める」と一致する。根拠は固定 Vim 9.1 の oracle の `block-tab-zero-` の fixture 16 件（`0` `1|` `h` `^` `?^` `F<Tab>` の後の `j` `k` と `y` `d` `r` `x`・錨より後ろの Tab・1 行・VISUAL に入る前の `0` と最初の位置）と `visual-wanted-` の 5 件（文字単位の `v0j` `v?^` `0vj`・NORMAL の `0j` と最初の `j`）。矩形の `I` の fixture は矩形の `I A c C` の PR（#1042）の後に足す。テキストオブジェクトの経路は同じ 1 本を通すが、キャレットが錨より手前の Tab に着く形の fixture は無い。

## 追補（2026-10-29・#1104 矩形の端に掛かる文字の operator ごとの扱い）

矩形の端（左右どちらでも・1 つの文字の内側に矩形が収まる形も）に半分だけ掛かる Tab や全角を、operator ごとに次のとおり扱う（Vim 9.1 の `block_prep()` の `is_del` と `op_tilde()` の `textstart + textlen`）。

| operator | 端に掛かる文字 | 範囲 |
| --- | --- | --- |
| `d` `x`（`c` `C` は下の行） | 文字ごと消し、矩形の外側だった桁を空白で埋める（決定 4・補足） | `VimBlockLine.range` と `keep_lead` / `keep_tail` |
| `r` | 文字ごと置き換え、覆った桁を `{char}` の幅で埋める（追補 #1067） | `VimBlockLine.range` |
| `~` `u` `U` | **対象にしない**。そのまま残し、空白にも割らない | `VimBlockLine.inside` |
| `y` | レジスタには丸ごと入る本文と覆った桁の空白（決定 2） | `inside` と `lead` / `tail` |
| `I` `A` | 1 行目の INSERT の本文をほかの行へ写す（#1042・消す鍵が混ざる回数の周は #1093 の `first_line_growth`） | `block_copied` |
| `c` `C` | `d` と同じく文字ごと消し外側の桁を空白で残してから左の桁で打つ。1 行目で左の端が切れて後ろに何も残らなければ、残した最後の空白の手前から打つ（追補 #1108） | `VimBlockLine.range` と `keep_lead` / `keep_tail`・打ち始めは `change_entry` |
| `y` → `p` `P` | レジスタの各行の右を幅まで空白で埋める数は Vim の `do_put` の数え方（Tab はどこでも 8・続きのバイトは 4 桁・追補 #1117）。表示の幅では数えない | `put_block_cells` と `put_lead_cells` |

`~` `u` `U` の切り詰めは `VimStepBlock.cpp` の `cased_block_edits` の 1 か所で、`vim_block_range` が決めた `inside`（端で切れた文字を外した範囲）をそのまま使い、呼び出し元で幅を数えない。丸ごと入る文字が無い行は飛ばす。キャレットと `u` の戻り先は追補 #959 のまま矩形の左上。これまでは `range`（切れた文字も含む）を変えていたので、端に掛かる全角の英字（`Ａ` ↔ `ａ`・#990 の表）が Vim と違って変わっていた（fuzz seed 33 の `fuzz-33-0210`）。根拠は固定 Vim 9.1 の oracle の `block-case-wide-` の fixture 12 件（右端に掛かる全角の `u` `U` `~`・左端に掛かる全角を 2 桁目から・`O` で角を入れ替えた形・左端に掛かる全角の右に続く英字・全角が丸ごと入る `u` `U`（変わる）・右端に掛かる全角の右に続く英字・`$` の矩形（変わる）・1 つの全角の内側に収まる矩形・fuzz seed 33 の最小）。

## 追補（2026-10-29・#1108 矩形の `c` `C` の端）

矩形の `c` `C`（追補 #1042）の各行の消す範囲・前に埋める空白・短い行の扱いは、`d` と同じ `vim_block_range` の `VimBlockLine`（`range` と `keep_lead` / `keep_tail`）と、写すときの `block_insert_edit`（左の桁に届かない行は飛ばし、内容の終わりちょうどの行は末尾に付く）のままで Vim 9.1 の `block_prep(is_del = TRUE)` と一致する（左端・右端が Tab の途中・全角の途中・下の行と 1 行目が短い・`$` の矩形・回数つき `2C` を測って確かめた）。違ったのは 1 行目に打ち始める所だけである。固定 Vim の `op_delete` は 1 行目のカーソルを `textcol + startspaces`（切れた文字の外側の空白の後ろ）に置き、`check_cursor_col` が NORMAL の規則で行末の 1 つ手前へ戻し、`op_change` は矩形の左上の文字（`oap->start.col`）がカーソルより後ろのときだけ `inc_cursor` で 1 つ進める。だから **1 行目で左の端が文字（Tab か全角）の途中に掛かって外側を空白で残し、その後ろに何も残らない**（`C`、または矩形が行の終わりを越える `c`）ときだけ、残した最後の空白の手前から打つ（`	end.` の Tab の途中から `C` で `x` を打つと `     x `）。決め方は `VimStepBlock.cpp` の `change_entry` の 1 か所で、`VimRemoveBlock.caret` と `VimBlockInsert.at` が同じ値を使い、Esc で残りの行へ写す本文（伸びたぶん）は変わらない。`d` `x` のキャレットは NORMAL の行末の規則で同じ所に寄るので変えない。`I` `A` は同じ規則で落ちる fixture が無く、変えない。根拠は固定 Vim 9.1 の oracle の `block-change-edge-` の fixture 20 件（Issue の fuzz seed 37 の `fuzz-37-0099` の `C` と `c`・左端が Tab の途中の `c` `C`・右端が Tab の途中の `c`・下の行が短い `C` `c` `A`・1 行目が短い `C`・左端に全角が掛かる `c` `C`・`$` の矩形の `c`・`2C`・下の行が短く左端が Tab の途中の `c` `C`・`u`・1 行目の全角が切れる `C`・1 行目の Tab が切れて行の終わりを越える `c` と `u` と `.`）。

## 追補（2026-10-29・#1117 矩形の `p` `P` の右の埋め）

決定 6 の「貼った矩形の各行を幅まで空白で埋める」の **埋める数** は、レジスタの行の表示の幅ではなく、固定 Vim 9.1 の `do_put()` の `MBLOCK` の枝の `spaces = y_width + 1 − Σ lbr_chartabsize` で数える。Vim はこの和を桁を毎回 0 に戻しながら **1 バイトずつ** 数えるので、Tab は行のどこにあっても tabstop の 8 桁、続きのバイトは不正なバイトの `<xx>` として 1 つにつき 4 桁、多バイト文字の先頭のバイトは全角と絵文字が 2・幅 0 の結合文字が 1・書式用文字（`<200b>`）が 6・C1 制御文字（`<85>`）が表示の 4 ではなく 1 になる（どれも oracle で実測。ASCII の制御文字の 2 は Vim のソースの読みで、測っていない）。結果として Tab の後ろに来る本文と全角（UTF-8 で 3 バイトなら 10 桁）を含む行は、表示では幅に足りなくても埋めないことが多い（fuzz seed 47 の `fuzz-47-0170`: `?	１２ :  ` の `<C-v>3wyp` は表示で 16 桁・幅 17 だが Vim は埋めない）。負なら 0。行末に貼る最後の 1 つを埋めない規則・回数・貼る桁・Tab を割る `put_lead`・レジスタの幅の持ち方（`VimRegister.width`）は変えない。数え方は `VimStepBlock.cpp` の `put_block_cells` の 1 か所で、`put_block_body` だけが読む。根拠は固定 Vim 9.1 の oracle の `block-put-wide-` の fixture 16 件（Issue の最小と最小化の前・Tab の途中で終わる矩形の `p` `P`・全角の `p` `P`・行末での貼り付け・下の行が短い矩形・`$` の矩形・貼り先が Tab を含む・回数つき `2p`・Tab だけの行・結合文字 U+0301・U+200B・U+0085・絵文字 U+1F600）。

## 追補（2026-10-30・#1159 空の 1 行だけの矩形の削除）

矩形が空の 1 行だけのとき、`x` `d`（`$` の有無を問わない）は本文もレジスタも変えない（Vim の op_delete の「1 行で行が空」の早期の戻り）。`y` と 2 行以上の矩形は今までどおり書く。決めるのは `registers_written` の 1 か所で、根拠と実測は ADR 0050 の追補（#1159）。

## 強制

- モード・効果・レジスタの種類・大きさの和型の写し漏れ: **active**（`switch` / `std::visit` の網羅性・CPP-002）
- 矩形の幾何・編集・貼付・`.`・描画の範囲が 1 本の関数を通ること: **active**（対象 unit と oracle fixture・CNF-010。描画は application の unit）
- 期待値が本物の Vim の答えであること: **不能**（CI に Vim は無い）

## 結果

得られるもの: T2 の VISUAL が 3 種類そろい、矩形の `d x y r` と貼付が Tab / 全角の上で Vim と一致する（`block-` の fixture 144 件）。範囲の列を運ぶ効果は今後の `I A c` の土台になる。
失うもの・残る穴: Vim の NORMAL / VISUAL で Ctrl+V の OS 貼付が使えなくなる（`p` と INSERT の Ctrl+V で代替）。`I A c C > < J ~` と VISUAL の中の `p`、`virtualedit`、`gv` は後続。矩形の描画は既存の行ごとの `SelectionSpan` なので、短い行の右側（本文の無い所）は塗らない（Vim も既定では塗らない）。

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| 選択の正本を「矩形専用の型」にして `EditorState` に持たせる | 選択の正本は anchor / caret の 1 つ（ADR 0009 / 0018）。矩形は読み方の違いで、型を分けると Ctrl+C / 描画 / `.` の経路が 2 本になる |
| 行ごとの削除を `VimRemoveRange` の列として複数の効果で返す | 1 鍵 1 効果を崩す（ADR 0030 の却下表と同じ）。範囲の列を 1 つの効果で運べば undo 単位も 1 か所で閉じる |
| 矩形の桁を code point で数える | Tab と全角で Vim と食い違う（Issue #91 で実測）。ADR 0034 が仮想桁を用意する |
| Vim モードでも Ctrl+V を OS 貼付のままにし、矩形は別の鍵にする | Vim と違う鍵は覚え直しになる。INSERT と通常モードの貼付は残るので不便は小さい |
| レジスタの幅を持たず貼付のたびに本文から計算する | `$` で取った矩形と短い行の埋め方が Vim と一致しない（`getregtype()` が幅を返すのは幅が本文だけでは決まらないから） |
