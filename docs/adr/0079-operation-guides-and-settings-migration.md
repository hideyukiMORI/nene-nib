# ADR 0079 — 操作の案内は操作表から描き、設定は旧版を残して移行する

- 状態: 受理
- 日付: 2026-10-07
- Issue: #304
- 影響する規則: FR-018 / D42 / ARC-001 / ARC-004 / ARC-008 / ARC-009 / ARC-010 / ARC-011 / CPP-002 / CPP-004 / CPP-011 / CPP-012 / CPP-017 / QLT-001 / QLT-012 / QLT-013 / QLT-014

## 文脈

採用済みの[操作の案内](../design/2026-10-06-guide.md)を実装する。F1 の操作一覧は ADR 0078 で実装済み。
ADR 0020 の設定は version=1 の4鍵をすべて必須にし、未知鍵を拒否する。そこへ guide を任意の鍵として足すと旧版の契約が変わり、新版の設定を旧版が読めない。
また、既存の保存は読込時の bytes と保存直前の bytes を比べ、競合時は変更を拒否する。新しいファイルへ移すときもこの保護が必要になる。

## 決定

1. **設定の所有と保存の道は変えない。** `EditorSettings` に閉じた2値の `GuideVisibility`（`shown` / `hidden`）を足す。既定は shown。`same_settings` に含め、フォントやテーマの変更では元の値を保つ。Ex の `set guide` / `set noguide` は設定候補を返し、既存の `persist_settings` が保存に成功したときだけ状態を替える。同値なら保存しない。本文・選択・undo は変えない。候補と補完は既存の `ex_command_candidates` に足し、Ctrl+P の `:` も同じ経路を使う。
2. **正本は `settings.v2`。** 同じ `%LOCALAPPDATA%/NeNeNib/` に置き、UTF-8、上限4096 bytes、`version=2` と従来の3設定および `guide=on` / `guide=off` の計5鍵をすべて必須にする。未知・重複・欠落の鍵と不正な値は失敗。BOM・空白・LF/CRLFの扱いは従来どおり。DTO と codec は adapters の一組を拡張し、domain 検証を複製しない。
3. **v2 が無いときだけ v1 を読む。** `settings.v1` の4鍵の厳密な契約は保ち、guide は shown にする。v2 が在るが壊れている・読めない場合は v1 に戻らず、型付きの失敗と保存禁止を返す。両方が無ければ設定無し。ファイル名と版は一致を要求し、v2 に置いた version=1 も拒否する。codec は期待する版を閉じた値で受け、解析と検証を共用する。
4. **移行で v1 を書き換えない。** 読込・起動・終了だけでは保存しない。設定の最初の実変更で v2 だけを書き、v1 は保存された bytes のまま残す。新版で v2 が作られた後は、旧版と新版の設定は独立する。以後の v1 の変更は v2 に取り込まない。この版の移行は互換読込であり、並行する製品実装や feature flag を設けない。
5. **移行の競合も拒否する。** adapter へ注入する `SettingsPaths` は current と previous の2つの検証済みパスを持つ。v2 を読めた場合は従来同様 v2 の bytes だけを記憶・比較する。v2 が無かった場合は v2 の不在と v1 の bytes（不在も含む）を記憶する。保存は v2.lock、移行時だけ続けて v1.lock を、共有無し・待機無しの固定順で取得する。両方の現在値を記憶と比べ、他の窓が v2 を作った、または旧版が v1 を変更・作成・削除したときは `changed_externally`。lock または書込の失敗も従来の失敗として返し、表示値を替えない。成功後は v2 の bytes だけを記憶し、v1 を読まない・lock しない。書込そのものは既存の `FilePort::write` に限る。外部エディタが比較後に lock を無視して書く競合まで保証しない点は ADR 0020 と同じ。
6. **文字と鍵は操作表が正本。** `OperationText` に短い表示名を足す。`list_files` は「一覧」、`list_operations` は「ヘルプ」、未指定なら通常名を使う。本文の案内は list_files と open_file の通常名、list_operations の短い名。ステータスは短い名。案内に載せる操作IDの列だけを定義してよいが、名前や鍵文字列の別表は作らない。鍵は `shown_chord` と `key_chord_label` から導く。F1 の一覧の名前・検索は変えない。
7. **表示する条件は application が決める。** frame に本文とステータスの案内の可否を載せ、renderer は本文や履歴を判定しない。共通条件は guide=shown、入力session・1行の知らせ・録画・IME変換が無いこと。面が開いている間も案内は隠す。本文はさらにアクティブな文書が無題・本文0 bytes・履歴の size が0であることを要求する。undo で空に戻しても履歴が残るので再表示しない。新しい無題へ切り替えればその文書の条件で表示する。「案内を見たか」という永続状態は足さない。
8. **配置は core の純関数。** 本文の案内は `BodyLayout` に基づき横中央、本文の上から約3分の1に置く。最初の本文行と現在行の面より下に離し、案内一式を収められない狭幅・低い窓では表示しない。3行の鍵は右端を揃え、説明まで20 DIP、行間12 DIP、下の「打ち始めると消えます」まで20 DIP。鍵12.5 DIP・説明13.5 DIP・補足11.5 DIPは本文の拡縮に連動させずDPIだけを掛ける。色・枠は採用案の既存トークンを使う。ヒット領域やクリック動作を追加しない。
9. **ステータスの案内は余白に収まるときだけ描く。** 右3項目と左の既存表示は動かさず、右項目の左へ28 DIP空け、その左に2つの案内を16 DIPの間隔で置く。鍵は text、説明は muted、12 DIP、枠無し。モードの領域との間も余白を確保し、全体が収まらないなら案内全体を消す。この幅の判断も core に置く。360 DIPでは案内は消える。既存項目の幅や縮退方式を本件で作り替えない。
10. **描画資源は renderer の既存所有に置く。** keycap は F1 の一覧と本文の案内で共通の描画口を使い、書式・矩形・面の色・余白を入力にする。一覧の既存寸法と画素は保つ。案内用の固定サイズのUI書式は `create_text_formats` が作り、DPI変更とdevice再生成で更新する。本文の書式や本文layoutの保持へ混ぜない。
11. **ステータスの保持は最大10枠。** ADR 0070 の7枠という上限だけを置き換える。案内は鍵と説明を2組、既存 `write_status` の4呼出しで描く。通常時の既存6枠と合わせて最大10、録画時は案内が無く従来の7。新たな色付きlayoutの保持経路は作らない。全文・書式・幅・高さの照合、UI書式作り直し前の全破棄、色と原点を毎回反映する規則は不変。
12. **設定を扱う検証道具も移行する。** v1からの引継ぎを調べる入力はv1のまま、保存結果の確認はv2を読む。各道具は自分のprofileだけを使う。試行前のsession/history/bookmarksの整理で、v1/v2の設定を消さない。設定adapterの対象だけを選ぶ検証口を足してよい。無関係なアプリの全件試験は実行しない。

```text
version=2
colorscheme=system
font_family=Cascadia Code
font_size=13.5
guide=on
```

## 検証計画

- 設定: v1/v2の厳密な解析、往復、v1不変、v2優先、壊れたv2の保存拒否、両方無し、初回移行の両側の競合・lock・書込失敗、移行後のv1非参照を対象のcodec/adapterで確認する。
- 中核/application: Ex・補完・Ctrl+P経由のguide切替、保存失敗と同値、他設定の変更でguideを保持、本文/履歴/選択の不変。案内の表示条件、96/120/192 DPI、狭幅・低高さ・本文拡縮時の離隔を専用scopeで確認する。
- ui: ライト/ダークと組み込み9テーマ、入力開始とundo、空の既存ファイル、新しいタブ、Vimの入力・検索・録画・通知・IME中の非表示、最小幅、設定保存後の再起動を必要な画で確認する。候補一覧の既存keycapは前後の画素比較を行う。
- 起動と空文書の1打鍵を直接変えるので、採用済みの性能基準値を変えず正式な速さのゲートで確認する。測定前に同じ機械のビルドを止め、負荷の条件を確認する。無効な測定も残す。
- 変更ソースのビルド・lint・整形、型/依存境界の規約とシンボル検査。成功済み結果は関連入力が不変なら再利用する。

## 却下と限界

- v1へ任意鍵を追加: 旧版の厳密なschemaを壊す。
- v2の失敗でv1へ戻る: 正本が読めない事実を隠し、後の保存で設定を失う。
- v1の内容をv2作成時に照合しない: 旧版で行った変更を古いsnapshotで固定してしまう。
- v2移行後もv1と同期する: 正本が2つになる。旧版と新版を併用したとき、移行後の変更は互いへ反映されない。
- 案内の文言と鍵をrendererへ直書き: 操作表と食い違う。
- 初回利用の記録、案内用のクリック動作、説明文の利用者設定は本件に含めない。
