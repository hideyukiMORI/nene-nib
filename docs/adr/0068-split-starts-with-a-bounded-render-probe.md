# ADR 0068 — split は文書タブを維持する案と限定した描画試作から判断する

- 状態: 受理（下準備と実験方法。製品のsplit採用・状態所有の移行は未決）
- 日付: 2026-10-03
- Issue: #290
- 影響する規則: FR-003 / FR-005 / D6 / D12 / D22 / D40 / ARC-001 / ARC-003 / ARC-004 / ARC-007 / ARC-009 / ARC-011 / CPP-002 / CPP-012 / QLT-001 / QLT-012 / QLT-013 / QLT-014

## 文脈

hideは速度を維持できるかを判断してからsplitを進めたいとし、区切りのタグ、範囲と採用条件、限定試作という順を了承した。タブは現在の文書タブを維持する推奨案で進め、利点・欠点も説明するよう指示した（D40）。

現状はADR 0056によりアクティブ文書の本文・履歴・カーソル・スクロールを一つの束で扱う。枠ごとにEditorControllerを持つ案は本文やundo、Vimのレジスタ、保存位置を重複させる。これを先に全面移行してから性能を見ると、見込みの悪い分割描画のために大きな変更を抱える。

## 決定

1. **比較点を固定する**。注釈付き`checkpoint/pre-split-20261003`は`088481b0c79436e9616445559aa4268225bd2ac0`。製品実装は#286と同じで、注釈に検証済みReleaseの生成元とSHA-256、gate-proofs 5-ch / 5-ciを記録した。
2. **今回の範囲は下準備と描画実験**。最大2枠・上下または左右・文書タブ維持を準備案とする。製品の初版範囲とADR 0056の所有構造をまだ変更しない。閉じる操作と将来の所有分離は[準備資料](../design/2026-10-03-split-preparation.md)に案として明記する。D12の製品の見た目の選定も後続。
3. **描画は既存の一本を使う**。隔離した実験ブランチでDirect2DRendererの本文矩形を1個または2個へ割り、既存の`draw_body` / `draw_line`を同じ1窓・1device・1swap chain・1回のPresentで使う。同じ表示値を再利用するため、別文書や独立スクロール・二つ目のframe生成の費用は未測となる。
4. **単画面の比較も残す**。元版と、同じ試作経路を1枠で通る版を比較する。これは描画経路の試作による差だけであり、将来の文書/枠の所有分離による差の証明にはしない。
5. **先に判定方法を固定する**。試行数、順番、本文、窓、指標、欠測とノイズの扱い、前進/保留の条件を準備資料に書いてから測る。既存の性能基準値とゲートを変更・採用し直さない。成功するまで繰り返さない。
6. **試作を製品に残さない**。描画試作のソースは実験ブランチと差分で追跡し、製品mainには統合しない。通常版の機能スイッチや並行した描画器を増やさない。実験用の切り替えを製品へ移すには新しい実装Issueと、単一の状態所有を決めるADRが必要。

## 判定の限界

この実験で判断できるのは、同じ表示値を既存DirectWrite経路で二つの矩形へ描く追加費用と、描画経路を変えた1枠版との差である。結果が良くても、本文の所有移行・inactive枠の位置補正・IME・hit test・undo・保存・閉じる挙動の正しさや性能は未検証。結果が悪ければ、全面移行に進まず、原因を特定して採用を保留する。

## 却下

- 既存速度ゲートの合格だけで速度維持とすること。現在の小さい入力値には2msの許容床が大きすぎる。
- 二つのEditorController、二つの本文/履歴、二つのswap chain。既存の意味と資源の所有者が増える。
- 測定前の大きな所有移行や、試作を隠しスイッチ付きでmainに残すこと。下準備の範囲を越える。
