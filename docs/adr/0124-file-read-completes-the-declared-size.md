# ADR 0124 — 宣言サイズを取得し終えるまで読込を成功にしない

- 状態: 受理（#463の対象139契約・Debug/tidy/ASan/UBSan・境界検査確認済み）
- 日付: 2026-10-13
- Issue: #463
- 影響する規則: ARC-001 / ARC-003 / ARC-007 / ARC-008 / ARC-010 / ARC-012 / CPP-003 / CPP-005 / CPP-007 / CPP-008 / CPP-012 / CPP-016 / QLT-001 / QLT-002 / QLT-004 / QLT-008 / QLT-012 / QLT-013

## 文脈

`Win32FileAdapter::read` は `GetFileSizeEx` と呼出し元の上限を確認してから一度だけ同期 `ReadFile` を呼ぶ。ADR0080決定5は、成功して返った長さだけを所有stringの長さにする契約だった。このため、宣言サイズより短い成功readや、非空要求に対する0 bytesも完成した本文として返る。#450の所有設計で必要な「宣言された全bytesを得てから公開」と整合しない。

Microsoftの `ReadFile` は、要求がEOFを超えた場合に短い成功readを返し得る。短い成功を完了と同一視しないことは本プロジェクトの判断であり、OSが必ず要求長を返すという仮定に頼らない。[ReadFile](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-readfile)

## 決定

1. **既存の `FilePort::read` は、受け入れた宣言サイズ全体を取得した場合だけ成功する。** API型、7か所のcaller、同期の呼出し方、文字コードを知らない境界を維持する。成功値は所有stringであり、部分的な本文を返す別の経路を作らない。
2. **短い成功readでは残りを取得する。** 初めに得たサイズを超えて読まず、進んだ位置から次の要求を出す。一回のOS要求は `DWORD` に収まる範囲へ制限し、通常の64MiB以下の完全readを任意の小ブロックへ分割しない。非空要求の0進捗、OS失敗、不正な返却長は `FileFailure::unreadable`。部分取得後でも所有stringを成功値にしない。
3. **空と上限を反復の前に確定する。** 負の宣言サイズと呼出し元の上限超は既存の `too_large`。空はreadを呼ばず成功する。確保には引き続き `resize_and_overwrite` を使い、検査済みの要求長だけを扱う。未初期化の末尾を読まず、コールバックから例外を投げない。
4. **反復の正本をadapter内に一つ置く。** 実際のWin32呼出しと決定的な故障注入は同じ反復を使う。注入は同期呼出し中だけの低層読込操作とし、core/applicationへOS handle・可変buffer・遅延I/O callbackを渡さない。製品の公開FilePortへ試験用設定を加えない。
5. **これはsnapshotや大容量受理の保証ではない。** 読込handleの `FILE_SHARE_READ`、64MiBの本文上限、判定済みbytesの所有境界は維持する。最初の宣言サイズ以後の追加、同サイズの変更、読み終わり時点の同一性を検知する契約は加えない。割当失敗、取消、退避資源、非同期処理、2GiB対応は別単位である。

## 強制と検証

- **active（選択したadapter契約）**: 短い成功→残り成功、複数回の進行、0進捗、部分取得後の失敗、空、返却長の上限を製品の反復への注入で確認する。実ファイルの既存 `nib_adapter_tests --files` と合わせて139 checks成功。空・NUL・正確な上限・上限超・通常の往復も確認した。[コマンド・原ログ・限界](../quality/complete-file-read-2026-10-13.md)。
- 固定toolchainの変更target Debug buildで警告・clang-tidy・ASan/UBSanを適用する。変更C++の整形と規約を確認する。成功した検証は、関連実装・入力が不変なら統合まで再利用する（QLT-001/012）。
- この変更は完了判定の契約修正であり、速度改善の主張をしない。通常の完全readの要求回数を維持することは小さい注入試験で確認し、性能/GUI測定や2GiB試験をこの単位の受理条件に加えない。#452の性能受理は別に保留する。

## 既存決定との関係・結果

ADR0080決定5のうち「短い読み込みの意味を保つ」「成功して書かれたバイト数だけをstringの長さにする」を、この全量成功の契約へ置き換える。同ADRの所有・文字コード判定・BOM・確保の決定、ADR0010の型付き失敗と上限を維持する。

完了前のEOFを従来の短い成功ではなく `unreadable` として通知する。本文・設定・テーマ・履歴・セッション・ブックマークも共通readを通るため、同じ失敗を受け取る。各caller既存の失敗処理は変更せず、「失敗時に全アプリ状態が不変」とは宣言しない。特に開く前のIME変換破棄と復元タブの失敗処理は従来どおりである。

## 却下した選択肢

| 選択肢 | 理由 |
| --- | --- |
| 短い成功を直ちに完成本文にする | 末尾が欠けた本文を正常に開いた値と区別できない |
| 短い成功を必ず即失敗にする | 続きを取得できる合法な進行を拒否する |
| 大容量用の別readだけ全量取得する | 同じ取得の意味を二つの実装へ分ける |
| 今回から1MiBごとに同期readを分割する | この契約に不要な通常経路の呼出し回数変更になり、取消やworker公平性の保証にもならない |
