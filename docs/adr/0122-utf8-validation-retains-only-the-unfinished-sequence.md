## 文脈

#450の[所有と読込失敗の設計案](../design/2026-10-12-large-file-source-ownership.md)では、adapterが取得した有界の断片を同じUTF-8検証へ順に渡す必要がある。現在の`validate_utf8`は渡された末尾をEOFとして扱うため、正しい多バイト文字を途中で分けても拒否する。全文連結や独立した大容量用validatorでは、メモリ条件またはARC-001を守れない。

2026-10-12はhideの試験保留と継続指示に従い、実装・契約試験の準備までをdraftで保存した。2026-10-13 00:50の再開指示を受け、対象検証を進める。本ADRはFilePort・退避・ワーカー・TextBufferの所有を変更しない。

## 決定

1. **進捗は`core::Utf8Validation`の不変な値。** 非公開constructorと`empty()`、`with_bytes(string_view) const`、`finish() const`を持つ。`with_bytes`は`expected<Utf8Validation, TextFailure>`で次の値を返し、受け手を変更しない。失敗した追加も、元の値を変更しない。入力は呼出し中だけ借用し、未完の末尾だけを私有配列へコピーする。状態の可変参照や可変pointerは公開しない。
2. **空の断片とEOFを区別する。** 空の`with_bytes`は進捗を変えない。`finish`だけがEOFを宣言し、未完列が残っていれば`invalid_utf8`、無ければ完成したcode pointの総数を返す。`finish`は観測なので、同じ進捗を分岐させたり、その後に別の断片を追加したりできる。
3. **走査は既存`Utf8.cpp`の一つ。** `Utf8Validation`の内部更新関数が従来のASCII連続走査・長さ・継続byte・復号・scalar範囲の判定を使う。一括の`validate_utf8(string_view)`は`empty → with_bytes → finish`の薄い入口へ置き換え、旧ループを残さない。途中まで来た符号列と、完成した不正列を区別する。過長符号化・surrogate・U+10FFFF超の最終拒否は維持する。
4. **保持量は入力長に依らない。** 呼出し間で保持するのは、最大3 bytesの未完列・その長さ・既に受け取ったbyte数・完成したcode point数だけ。完結させる局所処理には最大4 bytesの配列を使う。完成した本文や断片の列を蓄積しない。既存の8-byte ASCII走査は十分な残りがあるときだけ`memcpy`する規則を維持し、SIMDやCPU依存選択を追加しない。
5. **不正入力を成功した本文とは扱わない。** 断片末尾では符号点が未完成のことがあるため、`with_bytes`の成功だけを全文検証成功とみなさない。形の不正な継続は判明した時点で拒否し、scalarの範囲は符号列が完成してから判定する。EOFで残る未完列は拒否する。どの分割でも最終的な受理/拒否と符号点数が一括入力と一致する契約にする。
6. **累積長のoverflowを拒否する。** 追加前に`incoming.size() > size_t_max - bytes_seen`を確認し、超える場合は既存の`TextFailure::too_long`を返す。保持するcode point数は受理したbyte数以下なので、byte数の検査で計数のoverflowも防ぐ。入力長上限を2GiBや製品の64MiBへ暗黙に固定しない。
7. **進捗は本文の証明書ではない。** この値は完成済み本文を所有せず、後から渡す別bytesの妥当性を証明しない。`DetectedText`の防御コピーと判定済み所有列からのTextBuffer生成を維持する。検証フラグや進捗を添えて任意bytesからTextBufferを作る公開口を追加しない。退避の封印・検証対象との同一性は後続の読込ADRで扱う。
8. **文字コードと改行を混同しない。** UTF-8としてのBOMはU+FEFFの1 code pointで、NUL・CR・LFも数える。BOMを本文から外すのは既存のDetectedText→TextBufferの境界。BOM優先、UTF-8優先、CP932への判定順はTextEncodingのまま。分割検証自体はCP932判定・改行変換・I/Oを行わない。

## 実装範囲と後続の読込契約

新しい状態型は`Utf8Validation.hpp`の一つ。状態更新は既存`Utf8.cpp`へ集約するため、文字集合の表や復号処理を別ファイルへ複製しない。新しい契約はscope単位の`Utf8ValidationTests.cpp`へ置き、既存`--utf8`と既定実行の同じ入口から呼ぶ。

FilePortで断片を供給する実装は本件に含めない。後続では、要求した長さに満たない成功readを直ちにEOFにせず、残りを取得するか型付き失敗にする。宣言した入力の取得完了時だけ`finish`を呼び、I/O失敗・取消で途中まで読んだ進捗を完成した文書へ採用しない。元本文ID/範囲と所有bytesを結ぶ契約は#450の順序で別ADRへ具体化する。

**以下は計画であり、成功記録ではない。** 実行結果と失敗は[検証記録](../quality/streaming-utf8-2026-10-12.md)へ残す。

| 対象 | 確認する退行と最小の範囲 |
| --- | --- |
| 分割した文字列 | 既知の正しい2/3/4-byte文字、ASCII、NUL、BOM、CRLFを全ての2分割と3分割へ渡し、既知の符号点数と照合する。分割位置の正しさを本体実装から生成しない |
| 拒否 | 孤立継続、不正先頭、不正継続、過長、surrogate、最大値超、最後の未完列を分割して与える。拒否が追加時かfinish時かを区別し、未完の途中をEOF扱いにしない |
| 不変性・寿命 | 空断片、途中のfinish、同じ進捗からの分岐、失敗後の再利用、借用元を書き換えた後の末尾再開。公開される状態の所有を確認する |

| 静的・安全性 | 対象targetのDebug/clang-tidy/ASan/UBSan、symbols、conformance、変更C++のformat。抑制・allowlist・閾値は変更しない |
| 性能 | ASCII/日本語の既存UTF-8 probeと直接の読込ベンチ。対象版・入力・順序・回数を測定前に固定し、試験再開時期を調整する。改善を目的とする変更とは区別し、既存の退行条件を守る |

`size_t`の上限まで入力を積む試験は現実的でない。状態の偽造口や試験専用setterを追加せず、減算してから比較するguardと、code point数がbyte数以下である不変条件を自己レビューで確認する。これはoverflow境界を実行済みという意味ではない。

## 強制と限界

型の非公開状態とconst操作で可変aliasを狭める。変更版の対象検証を完了するまでdraftを維持し、強制の状態をactiveへ変更しない。

最大3 bytes以外の本文を保持しないため、後段へ本文を供給する所有は別に必要。大容量の退避、範囲取得、非同期化、読込上限、2GiB実測は未対応のまま。初回と2案目の局所性能比較は悪化したため不採用。3案目は拒否時点を含む`--utf8`13,939 checksが成功し、2026-10-14にclean版6c2c13fの固定比較を各1回実行。対応比はASCII1.105407、日本語1.033577で、性能悪化の解消とは判断しない。全値と失敗候補を保持する。

4案目は`scan`が境界確認と継続byte判定の直後に値を組み立て、同じbyteの検査後再読込と長さ分岐を省く。値への追加primitiveは既存`decode`と共用し、別のvalidatorは作らない。scalar範囲の判定は完成後だけで、途中の不正scalar候補を新たに早期拒否しない。ASCII走査・pending/overflow契約・flags・閾値は維持する。ASCII内側ループはbefore/3案目で同じ命令列だったため、その観測された増加の原因は断定せず、この変更での改善も保証しない。[品質記録](../quality/streaming-utf8-2026-10-12.md)に比較と対象検証を残し、4案目の性能・GUI openが成立するまでdraftを保持する。以前のUTF-8実装の成功値をこの変更版の成功として再利用しない。

## 既存決定との関係

ADR 0086のASCII走査と拒否条件を維持し、一括だけだったAPIを分割進捗で拡張する。ADR 0080の判定済み本文の所有と防御コピーは変更しない。公開APIの追加を本ADRに記録し、ARC-001/008とCPP-003/014を維持する。waiverなし。
