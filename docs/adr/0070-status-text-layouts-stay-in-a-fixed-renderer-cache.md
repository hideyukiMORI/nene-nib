# ADR 0070 — ステータスの文字組みは描画器の固定枠に保持する

- 状態: 受理
- 日付: 2026-10-05
- Issue: #291
- 影響する規則: FR-015 / ARC-001 / ARC-004 / ARC-005 / ARC-008 / ARC-011 / CPP-003 / CPP-012 / CPP-016 / CPP-017 / QLT-001 / QLT-012 / QLT-013 / QLT-014

## 文脈

hideから、対象処理を小さな区画に閉じ、内部を速度と安定性優先で最適化する試行を依頼された。
まず現在候補と同じ処理順の計測版 `5476c66` を作り、既存TimingPortでステータス描画と前フレームの本文layout解放を分けた。
空文書・1280×800 / DPI120 / Cascadia Code 13.5pt、新規profile、既存keys_trialを固定12回、欠測なし。
単打のステータス区間は中央値0.282ms・最大0.321ms、本文layout解放区間は中央値0.001ms・最大0.002ms。
原記録は `D:/NeNeNib/outputs/291-render-capsule-diagnosis-before-20261005/diagnosis.json`。
この値は区間の経過時間で、OSの割込みやDirectWrite内部の内訳を分離したものではない。

ステータスは同じ文字でも毎回 `write` → UTF-16変換 → `DrawTextW` を通る。
描画中の再変換と文字組みの生成を減らすため、この区画だけに固定数の再利用枠を置く。
可変な資源は既に描画器の責務であり、規約の除外・緩和は必要ない。

## 決定

1. 所有者は既存 `Direct2DRenderer`。文書・モード・状態・表示文字列の正本を移さない。
2. ステータスの通常ラベルは `write_status` の一経路を通る。layoutの作成は既存 `text_layout` を使い、同じ原点と書式で `DrawTextLayout` に渡す。
3. 保持枠は右側3項目と、通常/Vimの2ラベル・モード・録画表示の4ラベルの合計7。動的な枠追加・連想表・全画面のキャッシュを作らない。
4. 各 `draw_status_bar` の開始で枠の位置を0へ戻し、描く順に1枠ずつ使う。コマンド入力や通知に切り替わって順が変わっても、文字列全文・書式の同一性・幅・高さを照合し、一致しない枠だけを置き換える。色と画面上の原点は毎回反映する。
5. 枠は自身の文字列とComPtrを所有する。変更のない描画では文字列のコピー・UTF変換・layout作成・ComPtrのコピーを行わない。作成失敗ではその枠を空にして古い表示を出さず、次の描画で再作成する。
6. UI書式を作り直す前に全枠を破棄し、古い書式のアドレスが再利用されても誤一致しない。DPI変更はこの経路を通る。本文だけのフォント変更ではUI書式は不変。device再生成では描画器と共に破棄する。
7. コマンド入力のキャレット・IME・補完、タイトルバー、行番号、palette、本文のADR 0069のcacheには変更を加えない。ステータス内の通知と録画文字列は通常ラベルの同じ経路へ渡す。録画位置を求める既存のmetrics計算は維持する。
8. 解放を計測終了後へ移して見かけの速度を上げる変更をしない。計装は診断枝だけに保持し、通常版の比較には含めない。

## 検証

ビルドと対象ソースの整形・規約検査で所有と固定枠の実装を確認する。
通常/Vim、行桁の桁上がり、通知、録画、コマンド入力への切替、幅変更、フォント・テーマ変更を同一入力で比較し、本文/ステータスの画素一致を確認する。
空文書の既存単打/200文字比較に加え、事前に回数を固定した連続する独立単打の分布を観測する。
最大値・遅延閾値超過件数・全試行を保持し、少数の試行から絶対的な最悪時間を保証しない。
既存の性能基準値・受入条件は変更しない。今回の計装診断で性能合格を代替しない。

## 限界

変更された文字列の文字組みとGPU提示の費用は残る。OSやGPUの待機時間は固定枠では保証できない。
最後に使った7枠を保持する分のメモリが増える。状態切替後の未使用枠も、再使用・UI書式変更・描画器破棄まで最大7枠内で残る。
書式の借用ポインタは比較専用であり、UI書式の作り直しより先に全枠を消すことが寿命の条件となる。

## main構成への分離（Issue #295・2026-10-06）

幅索引だけの#294 `36a1c9c`へステータス固定枠だけを載せた`1883e27`で検証した。
上の文脈・決定7にある本文のADR 0069のcacheはこの独立構成には含まれない。
Releaseと22場面の本文/ステータス画素一致は成功したが、空文書単打の前後半差は
基準A 0.276ms > 0.11305ms、候補S 0.112ms > 0.1ms。中央値が改善しても事前の安定条件を
満たさないため**性能受理・main統合は保留**。本文経路の異なる過去の分布を独立構成の合格へ流用しない。
