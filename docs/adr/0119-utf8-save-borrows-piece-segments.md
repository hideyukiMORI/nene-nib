# ADR 0119 — UTF-8保存は本文の断片を同期呼出し中だけ借用する

- 状態: 受理
- 日付: 2026-10-12
- Issue: #442
- 影響する規則: ARC-001 / ARC-003 / ARC-004 / ARC-005 / ARC-007 / ARC-009 / ARC-010 / ARC-012 / CPP-013 / CPP-014 / QLT-001 / QLT-008 / QLT-012 / QLT-013

## 文脈

[段階1Aの計画](../plans/2026-10-12-release-scope-and-large-file-probe.md)は、2GiB級の本文を既存TextBufferで編集し、全文コピーを繰り返さず保存する試作を求める。現在はEditorControllerが`TextBuffer::text()`の全文を`encoded`へ渡し、BOM付きならその文字列へBOMを挿入してからFilePortへ渡す。Win32FileAdapter内の32MiB分割だけでは、その前の全文連結を避けられない。

本件は同期保存の入口を変える最初の単位である。元本文の所有、行索引、64MiB読込上限、UIスレッドでの同期I/Oは現状を保ち、2GiB対応の完成扱いにしない。

## 決定

1. `TextBuffer::segments() const &`は本文順の`std::vector<std::string_view>`を返す。列だけを所有し、文字はoriginal/addから借用する。空本文は空列。右辺値からの呼出しは禁止する。所有者の破棄・代入・移動後は使わない。既存のaddの追記は確保済み領域を越えず、既存prefixを書き換えないため、所有者を保持する同一スレッドの別版の編集で借用範囲は変わらない（ADR 0044）。公開APIは並行編集時の借用を許可しない。
2. FilePortの唯一の仮想書込は`write(path, span<const string_view>, mode)`とする。断片を順に連結したbytesを書き、空列・空断片を許す。bytesの文字コードを解釈しない。列とその参照先は呼出し終了まで有効であることを呼出し元が保証し、実装は保持しない。従来の文字列引数は1断片へ包む非仮想の薄い入口に移し、独立した書込経路を残さない。
3. EditorControllerはUTF-8保存でsegmentsをそのまま借用し、UTF-8 BOMでは静的BOMを先頭の1断片に置く。改行・文字を再解釈しない。Shift_JISは既存CodePagePortの検証付き全文変換を維持し、変換成功した所有文字列を同じFilePortへ渡す。変換失敗ならファイルへ触れない。大容量Shift_JISの解決は含めない。
4. Win32FileAdapterは全断片を同じ一時ファイルへ順に書く。各断片のWriteFileは既存の最大32MiB単位、全断片を書けた後にFlushFileBuffersを1回行い、handleを閉じてから既存の置換/create_new処理へ進む。どの断片で失敗しても成功を返さず、置換前の元ファイルを保持し、自分の一時ファイルだけを除く。create_newの衝突保護を維持する。
5. 文書情報と保存済み履歴位置は、従来どおり全書込・Flush・配置成功後にだけ更新する。非同期化も新しい保存形式も導入しない。将来のワーカー保存では別ADRで不変な所有版を要求へ渡す契約を定め、この借用列だけを仕事へ保存しない。

## 強制

- **active**: コンパイラが一時TextBufferからの借用と、旧仮想書込だけを実装したFilePortを拒否する。中核のOS非依存は既存のシンボル検査、文字コードの閉じた分岐は既存の網羅性警告が守る。
- **planned**: 借用を呼出し後に保持しないこと、全文連結を追加しないことはレビュー事項。完全な寿命/割当検査が実装されるまでactiveとしない。断片・スナップショット・保存の内容一致、失敗後の状態、実ファイルの置換拒否を対象テストで確認する。

## 結果

UTF-8保存時に本文と同じサイズの一時文字列が不要になり、一時領域は断片数に比例する。本文断片ごとにOS書込があるため、非常に細かく分断した本文のI/O回数は後続試作で評価する。保存中の画面停止、外部変更検知、Flush/部分書込の故障注入、2GiBでの実測は未解決である。小さな契約の成功を速度・大容量・電源断耐性の保証にしない。

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| UTF-8保存専用のadapterや直接WriteFile呼出し | FilePortの一時ファイル/失敗処理を二重化する |
| 一旦全文を連結してから一定長へ分割 | 保存前の大きな私有コピーが残る |
| 借用列だけをワーカーへ渡す | 本文所有者の寿命と保存済み版が保証されない |
