# ADR 0189 — 探して見る面: プレビュー欄は面の配置の 1 つの値で、中身は worker が読む窓。待ちの間の演出は合図で進む純関数

- 状態: 受理（施主決定 D95 / D96・2026-11-16。実装は段 P1〜P3・受理は D41 の形）
- 日付: 2026-11-16
- Issue: #1751（形）・採用案 [`docs/design/2026-11-16-finder-look.md`](../design/2026-11-16-finder-look.md)
- 規則: FR-026、ARC-001 / ARC-003 / ARC-004 / ARC-007 / ARC-011 / ARC-012、CPP-002 / CPP-005 / CPP-013、QLT-014、ADR 0008 決定 8（色はトークン）/ 0060 / 0062（面の候補は 1 列・見えている行だけ・worker 1 本と券）/ 0078（操作の表）/ 0150（面の行の保持・配色のプレビュー）/ 0154（拡張子 → 言語）/ 0167（全文検索）/ 0170 の 2026-11-16 の追補（`settings.v5`）

## 文脈

D95: Ctrl+P の面で、選択を上下で動かすと隣のプレビュー欄に中身がすぐ切り替わる。攻殻機動隊・マトリックスを思わせる演出は、検索の対象が多くて待ちが出るときだけで、結果を演出で遅らせない。2026-11-16 に施主が `/design` の案から選んだ（D96）: 置き方は案 A（右に並べる）・演出は案 2（解読）で、もっと速く・走査の線は無し・形は自動に加えて手でも切り替える・鍵は Ctrl+Shift+P。

今の面は幅 640 DIP・上 96・入力 52・行 40 × 最大 8・下 34 DIP で、配置は core の `palette_layout` の 1 本（描画と当たりが同じ値を読む）。候補は開くときに作る 1 つの列で、見えている行だけを作る（ADR 0062）。ファイルに触れてよいのは `src/adapters/win32` だけ、現在時刻とスレッドも同じ（ARC-007）。

## 決定

1. **プレビュー欄の置き方は閉じた値 `FinderPreview{automatic, right, below, off}` の 1 つ。** 状態（窓全体で 1 つ）と設定（`settings.v5` の鍵 `finder_preview=auto|right|below|off`・既定 `auto`）に持つ。配置は `palette_layout` が置き方と窓の大きさから決める 1 本のままで、ui と当たりの判定は同じ値を読む。
   - `right`: 面の幅は min(1000 DIP, 窓の幅 − 32 DIP)。左の当たりの欄 400 DIP・右がプレビュー欄。行は今と同じ 40 DIP × 最大 8。プレビュー欄の高さは行の欄と同じ。
   - `below`: 面の幅は今の 640 DIP。当たりは最大 5 行。その下にプレビュー欄（見出し 28 DIP ＋ 残りの高さ・最小 6 行ぶん）。
   - `off`: 今の面のまま。
   - `automatic`: `right` が入れば `right`、入らなければ `below`、それも入らなければ `off`。「入る」は、`right` ならプレビュー欄の幅が 360 DIP 以上（窓の幅が 792 DIP 以上）、`below` なら当たり 3 行 ＋ プレビュー 6 行が窓の高さに入ること。
   - 手で `right` を選んでいても、入らない窓ではその場だけ `below`（さらに入らなければ `off`）で描く。覚えた値は変えない。
2. **プレビューが在る出どころだけ、欄を出す。** ファイルを指す候補（タブ `#`・履歴 `@`・同じフォルダ `/`・全文検索の当たり `!`・後で足す行と見出し）は欄を出す。設定 `:` と操作の一覧 `?` は欄を出さず、今の面の形になる（配色・字体のプレビューは本文そのものが変わる・D59 / D93）。出どころごとに「欄を持つか」を返すのは core の `PaletteScope` の表の 1 か所。
3. **切り替えは操作 `cycle_finder_preview`。** 面が開いている間の Ctrl+Shift+P が `right → below → off → right` の順に、今描いている形の次へ置き方を変える（`automatic` でも手で選んだ値でも同じ。手で `right` を選んでいて細い窓で `below` に落ちていれば次は `off` で、押せば見た目が必ず変わる・2026-11-17 の設計席の決め・V-1792 の 3）。F1 の一覧の行は鍵なし（Ctrl+Shift+P は面が閉じているときの `list_files` の行が持つので、面が開いている間の鍵は ui の入力行の鍵）。面が閉じているときの Ctrl+Shift+P は今までどおり面を開く。プレビュー欄の見出しの右端の印を押しても同じ。Ex は `:set finderpreview=auto|right|below|off`（`fpv`）。F1 の一覧にも載せる。変えたときに `settings.v5` へ書く。
4. **中身は「窓」`PreviewSnippet` で、読むのは worker。** `PreviewPort{request(PreviewRequest{path, anchor, ticket}), cancel(ticket), collect() -> std::vector<PreviewBatch>}`（`FolderPort` と同じ形・仕事の種類ごとの port・ADR 0062）。`anchor` は「先頭から」か「この行を中心に」。adapter はファイルを先頭から読み、`anchor` の行の前 7 行から最大 40 行ぶんを返す（1 行は 512 バイトで切る・コードポイントを割らない・読むのは最大 16 MiB まで・NUL を含むものと 16 MiB 超は「プレビューできません」の 1 行）。文字コードの判定と改行の扱いは文書を開く道と同じ 1 本を呼ぶ。完了の知らせは `WorkCompleted` → `collect`（新しい合図は足さない）。
   - **開いているタブの文書は port を呼ばず、application が手元の本文から同じ形の窓を作る**（未保存の中身が見える）。まだ読んでいないタブ（`UnloadedDocument`）は port で読む（`reach_tab` は呼ばない・タブを読んだことにしない）。
   - 選択が動くたびに新しい券で要求し、前の券の結果は捨てる。直近 8 つの窓を application が持ち（鍵は path と窓の中心の行・窓の本文と色だけを持つ）、戻ったときは port を呼ばずに出す。当たりの印は保持から出さず、今の当たりの値から毎回付け直す（`marked_lines`・検索語を打ち足して同じ行の範囲が変わっても前の印を残さない・V-1794 の必須 2）。面を閉じると全部捨てて `cancel` し、届いていた結果は次の `WorkCompleted` の `collect` で捨てて棚を空にする（全文検索の `project_draining_` と同じ形・棚に残すと「届いた」の合図が次から出ない・V-1794 の必須 1）。
   - 選択が動いた瞬間に見出し（名前・場所・行・言語）は新しい候補のものになり、中身は届くまで空（前の中身を残さない・違うファイルの中身を一瞬でも見せない）。
5. **描画は ui の `PreviewPanePainter`。** 字体は本文と同じ族で、大きさは面の行の文字と同じ（`fontsize` に追従しない）。行番号は `gutter`、当たりの行は `current_line` の面、当たりの文字は `search` の面 ＋ `accent` の 1 DIP の枠（D17 と同じ）、欄の地は `background`、境と見出しの下の線は `panel_border`、見出しの名前は `text` の semibold、ほかは `muted`。構文の色は窓の行だけを既存の色付けの 1 本に通す（窓の先頭が複数行のコメントや文字列の途中でも、先頭から色を始める・限界）。**新しい色のトークンは足さない。** 文字組みは欄の専用の保持（最大 40 行）で、`BodyTextLayouts` と面の行の保持（ADR 0150）には入れない。
6. **待ちの間の演出は「解読」で、進めるのは合図・形は core の純関数。**
   - 出る条件: 全文検索の途中（`progress` がまだ終わりでない）で、要求から 200 ms を超え、見えている行のうちまだ当たりが届いていない行が在る。その行にだけ出す。届いた行・プレビュー欄・入力欄には出さない。
   - 形: 届いていない行に、乱れた文字（半角カタカナ・数字・記号の固定の表）の列を `gutter` の色・不透明度 55% で描く。40 ms ごとに文字が入れ替わる。当たりが届いた行は、左から本物の文字に解ける（先頭の 1 字だけ `accent`）。解ける時間は 1 行 200 ms 以内（40 ms × 5 回・1 回に行の 1/5）。**行は届いた瞬間から選べて、Enter で開ける**（解けている途中でも当たりの中身は確定している。結果を演出で遅らせない・D95）。走査の線は描かない。
   - 進め方: ui のタイマー（40 ms）が意図 `FinderTick` を送る。`FinderTick` は使う人の操作ではない合図（`detail::is_signal`・`keeps_tab_walk`・`begin_intent` に書く・`AutosaveTick` と同じ側）。application は通し番号を 1 つ進めるだけで、乱れた文字の列は core の `finder_noise(ticket, tick, row, length)`（券と番号と行から決まる純関数・乱数と時計を読まない）が返す。タイマーは frame が「演出が出ている」と言う間だけ動かし、出ていないときは止める（面が閉じている・待ちが無いときの費用は 0）。200 ms の境も合図の回数で数える（要求の後の 5 回目から）。
   - 止める条件: Windows の「アニメーション効果」がオフ（`SPI_GETCLIENTAREAANIMATION`・起動時と設定の変更の知らせで読むのは adapters）か、設定 `finder_effect=off`（`settings.v5`・既定 `decode`・`:set finderfx=decode|off`）。止めているときは入力欄の右の「探しています… N / M ファイル」の文だけ。
7. **費用。** UI スレッドは要求・`collect`・見えている行と欄の描画だけ。打鍵・切り替え・保存・起動の道で `PreviewPort` を呼ばない（`verify_quiet_paths`）。面の既定のベンチ `key-to-frame-palette-5000` は悪化なし（既定のベンチは欄を持つ出どころ `files` で開くが、既定の窓 640 × 360 DIP は `right` にも `below` にも入らず `off` で描くので、欄の表示値を作らない今の道のまま・V-1792 の 1。そのため、欄を持つ出どころの任意ベンチ `palette-preview-move`（選択を 1 つ動かしてから見出しが出る frame まで・中身が届く frame まで）を足す）。演出の 1 回の frame は見えている行の数に比例するだけ。
8. **契約。** core: `--finder-layout`（置き方 × 窓の大きさの表・入らないときの落とし方・当たりの判定と描画が同じ矩形・切り替えの順）と `--finder-noise`（同じ引数で同じ列・行の長さ・解ける順）。application: `--finder-preview`（替え玉 `ScriptedPreview`: 券・古い結果を捨てる・直近 8 つ・開いているタブは port 0 回・未保存の中身・まだ読んでいないタブを読んだことにしない・面を閉じると `cancel`・設定への保存 1 回）と `--finder-effect`（5 回目から・届いた行に出ない・届いた瞬間に選べる・止める条件・`FinderTick` が Ctrl+Tab の歩き・Vim の待ち・`.`・undo を動かさない）。adapters: 一時フォルダの本物のファイルで窓（先頭・中ほど・最後・CRLF・Shift_JIS・NUL・16 MiB 超）。ui: `nib_window_tests` の画素（`right` `below` `off`・演出の 1 コマは通し番号を固定して）。
9. **段。** P1 = 置き方の値・配置・切り替え・設定（中身は開いているタブだけ）。P2 = `PreviewPort` と構文の色。P3 = 演出。全文検索（ADR 0167 の G1〜G3）と並べて進められ、演出 P3 は全文検索の後。

## 強制

- 面の配置は `palette_layout` の 1 本・描画と当たりが同じ値: **active**（段 P1・#1785 の契約 `nib_tests --finder-layout`: 置き方 × 窓の大きさの表・落とし方・行と印の当たりと描画の矩形・切り替えの順。画素は `nib_window_tests --finder-preview`）。
- UI スレッドでファイルを読まない・打鍵などの道で port 0 回: **active**（段 P2・#1793。読むのは `Win32PreviewAdapter` の worker の仕事 `PreviewRead` だけ・`nib_tests --finder-preview` の券と保持と取消・`verify_quiet_paths` の `PreviewPort` 0 回・`ctest -R nib_adapters_preview`）。
- 演出は合図と純関数・core に時計と乱数を入れない: **planned**（P3 の契約と `eng/symbols.py` で active）。
- 色はトークンだけ: **active**（ADR 0008 決定 8・既存の検査）。
- 8 本の速さ: **active**（QLT-014）。

## 結果

得られるもの: 当たりと中身を同時に見て選べる。窓の形に合わせて欄が動き、手でも変えられる。待ちが長いときだけ、まだ届いていない所が動いて「探している」ことが分かる。
失うもの・残る穴: プレビューの構文の色は窓の先頭から始めるので、複数行のコメントの途中から始まる窓は色が違うことがある。境のドラッグで割合を変える操作は無い（後続）。プレビュー欄の中はスクロールできない（選択の行が中心・後続）。画像・Markdown の描画したプレビューは出さない（本文の文字だけ）。`settings.v5` を読まない 1.0.0 からは、置き方と演出の設定が見えない（D91）。段 P1 の限界のうち、書式用の文字の見え方（窓の行も本文と同じ `core::display_line` の形）と改行で終わる本文の最後の空の行（窓に入れない）は段 P2（#1793）で直した。残る限界: 未保存の編集があるタブでは、全文検索の当たりの印（ディスクの行と範囲）が本文とずれ得る。プレビューの読みは全文検索と同じ worker の列に並ぶ（優先の仕組みは無い・1 塊 1 仕事なので塊の間に入る）。窓の 1 行は 512 バイト（`finder_preview_line_bytes`）で切り、構文の色は切った行の上で付ける。開いているタブの窓は frame のたびに作り直す（最大 40 行の切り出し・`display_line`・字句器。保持は無い・ベンチ `palette-preview-move` を足すときに測り、要れば application の `FinderPreviews` に置く）。テキストでないかの判定は最初の 1 MiB の塊だけ（全文検索と同じ）。

## 却下した選択肢

| 選択肢 | 却下の理由 |
|---|---|
| 案 B（下に開く）を既定に | 当たりが 5 行しか見えず、中身の横幅が狭い。細い窓の落とし先と、手で選ぶ形として残した |
| 案 C（本文の場所に映す） | 編集中の本文が隠れる・「開いたのか見ているだけか」が分かりにくい・本文の描画を別の文書で回す作りが大きい（アクティブな文書だけに触る ADR 0056 とぶつかる） |
| 演出 1（雨）・走査の線 | 施主が案 2 を選び、走査の線は要らないと決めた。雨は動く範囲が広く、届いた行の隣で気が散る |
| 届いた行を解け終わるまで選べなくする | 結果を演出で遅らせる（D95 に反する） |
| 乱れた文字を ui が乱数で作る | 画素の試験が決まらない。時計と乱数は adapters だけ（ARC-007） |
| 鍵を Alt+P に | 鍵の表 `KeyChord` に Alt が無く、Windows の Alt のメニューの動きに触る。Ctrl+Shift+P は今「Ctrl+P と同じ」だけの行で、面が開いている間の役が空いていた |
| プレビューを UI スレッドで読む | 大きいファイル・遅いドライブで選択の移動が止まる（D67 の条件） |
| プレビューに `reach_tab` を使う | 見ただけのタブが「読んだタブ」になり、読めないタブが帯から外れる |
