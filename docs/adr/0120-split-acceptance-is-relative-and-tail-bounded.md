# ADR 0120 — splitは単画面との差とp95を分けて採用判断する

- 状態: 受理（採用条件。実測は 2026-10-19 に完了・製品採用は hide の試用（D41）の後。2026-10-21: hide の試用 OK・最終版でも 12 対 pass（[記録](../quality/split-speed-2026-10-21.md)）・#688 #687 #692 が main `e383fe0`）
- 日付: 2026-10-12
- Issue: #443
- 影響する規則: QLT-001 / QLT-010 / QLT-012 / QLT-013 / QLT-014
- 施主決定: D45。hideが[初版試験計画](../plans/2026-10-12-release-scope-and-large-file-probe.md)の条件案に「この条件を採用する」と回答。

## 文脈

ADR 0075決定5は、旧split試作の総2ms以内という条件について、再開時に条件の立て方からhideと決め直すとしていた。旧条件のholdは当時の結果として残る。2026-10-12の開始指示に基づく段階0で、単画面の既存基準を守りながら分割による追加時間と遅い打鍵を別に見る案を示し、hideが採用した。

## 決定

1. **既存の単画面ゲートを維持する。** `eng/perf-reference.json`の基準値・許容・QLT-014の意味を変更しない。splitの新条件を単画面の退行許容の拡大に使わない。
2. **中央値の追加時間**は、同じ条件の単画面の中央値を`S` ms、splitの中央値を`P` msとして、`P - S <= max(1.0ms, 0.25 * S)`を満たすこと。比率だけ、または絶対値だけへ読み替えない。
3. **splitのp95は16.7ms以内**とする。中央値とp95の両方を満たす必要がある。p95は固定100打鍵の実値を昇順にした95番目（nearest rank）、中央値は50/51番目の平均。最大値と16.7ms超の件数も残し、100打鍵の標本から全利用状況の95%を保証しない。
4. **独立した2文書と、同じ文書の2表示を別群で判定する。** 各本文/表示条件について単画面100打鍵、各split群100打鍵を固定する。群を混ぜた集計だけで合格としない。同一文書では編集が両表示へ反映された提示までを測り、共有本文・undo・保存状態と独立したカーソル/選択/スクロールの正しさも別に確かめる。
5. **時間の境界は同じにする。** 既存の「入力受信から、その入力を反映したPresentが戻るまで」に揃える。OSの入力待ち・実際の発光までを含む値とは呼ばない。1打鍵ずつ次の提示を待つ。単画面とsplitで版・入力列・操作中の枠の本文表示寸法・字体/サイズ/DPI・折り返し等を揃え、別枠の表示内容と追従条件を記録する。
6. **測定前に具体的な試験計画を固定する。** 対象版/Release exe・機器/画面・本文とSHA・配置・操作列・試行順・warmup・測定器と信号の照合方法をcommitへ残す。実画面/性能測定はhideの他案件と時間帯を調整する。これは新条件の決定であり、いま測定を始める許可ではない。
7. **失敗・欠測・外れ値を保持する。** 到達/提示の確認が欠けた値を0や成功試料に替えず、固定試行が完了しなければ未成立とする。外れ値を除外したり成功まで繰り返したりしない。欠陥修正後の新測定は原因と旧結果を保持し、対象/回数を次の実行前に固定する。小さな差が測定の揺れと同程度ならADR 0075決定3の保留判断も適用する。
8. **旧結果と新しい採用を分離する。** ADR 0068、ADR 0075、旧実測JSONとholdを修正しない。新しい条件で旧値を合格へ置き換えない。条件の受理だけではsplitの製品採用を決めず、新測定・振る舞いの検証・必要なレビューに基づいて別途判断する。

## 強制

- **active**: 既存の単画面の性能ゲートはQLT-014記載の範囲で維持する。
- **active**: `eng/measure-speed.py` の `split-single-key-100` と `split-pane-key-100-*` の bench（固定 100 打鍵・1 打鍵ずつ次の提示を待つ）と `--split-verdict`（中央値の差 ≤ max(1 ms, 0.25 S)・p95 ≤ 16.7 ms・群別・欠測は未成立）が #681 で入り（main `209add2`）、2026-10-19 の本測定（`docs/quality/split-speed-2026-10-19.md`・12 対 pass）で動いた。回すのは split に関わる差分のときと `-Full` の明示実行で、CI の必須 check と基準値 `perf-reference.json` には入れない。

## 結果

長行の単画面が既に総2msを超えることと、splitによる追加負担の判断を分けられる。1msの床と25%の比率に加えてp95の絶対上限を守る。条件内でも機能の欠陥を受理せず、満たせない場合は根拠をhideへ示す。split・Markdownの実装順と大容量の先行はロードマップどおり。

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| 旧実験の総2msを今回の式へ書き換える | 測定後の条件変更で旧証拠を歪める |
| 中央値だけで採用する | 遅い打鍵の増加を見落とす |
| 同一文書と独立文書を合算する | 共有本文の両表示更新の費用を隠す |
