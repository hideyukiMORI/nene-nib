# ADR 0093 — 検索の照合は文字位置ごとに優先順を保った状態を一度ずつ評価する

- 状態: 実験設計（2026-10-10・製品採用は計測とD41の受理後）
- 日付: 2026-10-10
- Issue: #350

## 文脈

`VimPattern::matched`は開始位置を一つずつ進め、`matched_atoms`は`*`の停止位置を列へ作って長い方から再帰する。`a*b`を`a`だけの行に掛けると同じ後半を何度も調べる。反復が連続すると組合せが増え、反復がなくても原子ごとの再帰は長い語から作る検索値に比例して深くなる。入力行の256bytes上限は`*`/`#`が本文の語から作る値には適用できない。

検索の対応構文と貪欲な選び方はADR0032が正本。検索移動と強調の非重複列挙はADR0037（#349）が正本で、この実験では変えない。

一般的な手法の参考はRuss Coxによる[優先順を保つ状態列の説明](https://swtch.com/~rsc/regexp/regexp2.html)。同じ入力位置と命令位置の候補では先に現れた候補を残し、一致を得た後もそれより優先する候補を評価する。この考え方をNibの連結・原子の反復・幅のない条件だけへ限定して設計した。外部の実装やVimソースを取り込まない。

## 事前の設計確認

`D:/NeNeNib/outputs/20261010-pattern-design/ordered-model.py`で、単純な貪欲探索の定義と下記の順序つき評価を比較した。原子は`a`/`b`/任意文字/それぞれの反復/行頭/行末、原子数0〜4、本文は`a`/`b`の長さ0〜5、開始位置は末尾の次まで。1,797,504組の開始・終端が一致した。全入力と結果のSHA256は`ddee014d850be04d0a31bc2f40833ca5cb11d817223f0579803ab9546cc07569`。

これは有限の設計モデルの一致であり、Vim oracleや製品C++の正しさ、UTF8/語境界、速度の実測を代用しない。原子列へ直接渡すためparserの解釈も検証していない。スクリプト・出力・初回ログを恒久証拠へ収載する。

## 決定

1. 公開の`parse`/`matched`、不変な原子列・集合の範囲列、未対応構文の拒否は維持する。`matched`だけが評価の入口で、UTF8の原始、文字集合、語境界、行頭/行末の判定も既存の一つを共用する。
2. 反復がない列には選択肢がない。各開始位置で原子を順に反復評価し、再帰せずに終端か失敗を返す。この場合に状態列の確保を持ち込まない。反復の有無は原子列そのものから決め、設定や可変cacheで別実装を選ばない。
3. 反復を含む列は、同じ文字位置にいる候補を優先順で評価する。候補が持つのは次の原子位置と一致の開始byteだけ。現在位置の列と次位置の列を呼出し内で所有し、同じ位置・同じ原子へ達した候補は先頭の一つだけを残す。開始byteは将来の判定に影響しないため、後の候補を捨てても優先する答えは失わない。
4. 幅のない条件は成立したときだけ次原子へ進める。反復原子は「一文字消費して同じ原子へ戻る」を先に並べ、「0回で次原子へ進む」を後に並べる。Nibのこの部分集合では幅のない遷移は原子位置を増やすだけなので、その展開も再帰を使わない。
5. 一致を見つけたら開始と終端を覚え、それより低優先の候補を止める。既に列にある高優先の候補は継続し、さらに一致したら結果を更新する。一致がまだない間だけ、新しい開始位置を既存の候補の後ろへ足す。高優先の候補がなくなった時点で覚えた結果を返す。最初に見えた空一致を即座に返して貪欲さを失わない。
6. 原子の消費判定はVimPatternのprivate原始一つへ集め、連結用`stepped`と優先状態列が共用する。文字取得と前進は既存`code_point_at`/`next_code_point`、幅のない条件は既存の判定を使う。別decoder、別word分類、別parserを作らない。`matched_atoms`と`repeated_stops`の旧再帰/停止列経路は同じ差分で除く。連結だけの場合と反復を含む場合に共通の意味判定を複製しない。
7. 評価状態は`matched`の一回に閉じ、本文/パターン/EditorStateへcacheや所有者を増やさない。coreの外へ可変な集合や評価builderを返さない。新しい補助型が必要なら1ファイル1型と最小可視性を守る。実スレッド・ワーカー・時計は不要。
8. 反復を含む評価の保持量は原子数に比例し、本文長×原子数の表を確保しない。各位置の重複除去の初期化も原子数以下に閉じる。本文長N・原子数A・集合の総範囲数Rに対し、この評価で各文字位置に必要な仕事はA+Rで上限を説明できる。固定の短い系列で実際の伸び方と要求容量を別に記録し、RSSを未測定ならその旨を書く。

### 補助型の可視性と所有（実装前の設計席判断）

`VimPatternEvaluation.hpp/cpp`に評価呼出しの状態を持つ1型を置く。`VimPattern`と相互friendにし、constructorと評価入口をprivateへ閉じる。外から生成・操作できるbuilderは公開せず、`VimPattern::matched`だけが生成して結果を読む。パターンはconst借用、行は呼出し内のstring_viewで、所有/借用を状態や別呼出しへ保存しない。

現在/次の優先順は原子indexのvectorを2本、各原子の最初の開始位置はoptional<size_t>のvectorを2本で持つ。後者の値の有無を同位置での訪問済み判定にも使い、新たなthread型や独立したseen列を増やさない。原子数Aに対し優先順の要求容量は各A、訪問/開始列のサイズは各A+1（受理位置を含む）。毎位置のfillもO(A)であり、実容量とsizeofを記録しRSSとは区別する。

原子の消費判定は下記のprivate共用原始を使う。幅のない条件の既存`anchored`本体はVimPatternのprivate判定へ移し、分類も既存の一つへ委譲する。判定やdecoderの複製はしない。新cppはCMakeのcore explicit source listへ追加し、別target/依存を作らない。

### 同位置の消費判定の共有（固定比較後・追加実装前の決定）

初期候補の固定比較ではstar不一致と長literalの安定性が改善した一方、`a.*a`/4096個の`a`の成功は16照合の中央値1282.5→2066µs、30対応組すべてで悪化した。記録を消さず、次の局所変更を別commit/別の固定比較として試す。効果は未確認であり採用の根拠へ先取りしない。

消費原子のliteral/any/set判定だけをprivate `consumes(atom, code)`へ移し、幅のない原子はfalseとする。既存`stepped`は末尾拒否と既存UTF8原始による文字/次位置の取得を保ち、この判定へ委譲する。`VimPatternEvaluation::advanced`は呼ばれる位置が末尾より前である既存条件の下、同位置の文字と次位置を一度ずつ取得して、各候補の判定へ共用する。decoderの内部やraw byteの意味を変えず、途中byteからの呼出しも既存原始の意味を保つ。

優先順・訪問済み列・幅のない遷移・一致時の低優先破棄・4vectorの所有/初期化は変更しない。特定patternの分岐、旧再帰へのfallback、探索打切り、世代tag/追加cacheを導入しない。直接検索3scopeと公開APIの同じ有限系列をこの変更後に確認し、影響する反復5条件だけを初期候補との同一harnessで比較する。共用原始へ委譲した連結側の費用も短/長literalの既存2条件で別に確認する。旧baselineのlong literal失敗を再試行せず、正常な初期候補と新候補を比べる。

## 比較と受理

- `a*b`の不一致を長さ1024/2048/4096で比較する。反復の組合せは短い本文の`a*a*a*a*b`で確認し、旧版の長時間停止を待つ試行は作らない。
- 成功する貪欲な検索、空一致、普通の短いliteralと長いliteralを分ける。解析や入力生成は区間外、戻り値の完全照合と破棄も区間外。同じharness・固定反復・固定順・全試料保存で比較する。
- 検索・強調・入力中検索の直接契約と既存oracle期待値を維持し、開始/終端/行末/空行/from超過/日本語・補助平面/語境界/文字集合/複数反復を確認する。長いliteralでは再帰を除いた安定性も確認する。テストの期待値を新評価器から作らない。
- 設計モデルの有限比較と製品試験を区別し、計測前に固定workloadをADR0082の正規harnessへ追加する。普通の検索への悪化や容量の代償があれば採否へ含める。
- mainへの採用はD41の独立レビュー、正式速度ゲート、実機試用、CIによる。失敗や保留の原記録を書き換えず、基準値/許容/fixture期待値/抑制/allowlist/schemaは変更しない。

## 採らない案

- 全開始位置×全原子のmemo表: 大きな本文や本文の語から作る検索値で保持量が積になる。
- 一定の探索回数で一致なしへ変える: 結果の意味が入力長で変わる。
- 別の正規表現ライブラリや新構文: 依存と対応範囲を広げる必要はない。
- 反復のない短い検索にも汎用状態列を必ず確保する: 選択肢がない処理へ余計な確保を足すため、連結の同じ判定を反復する。

## 残る限界

原子数も本文長も大きい入力の仕事量は積になる。未対応の後方参照・分岐・グループ等を後から足す場合、本設計の重複除去の証明をそのまま流用できない。空でない多byte入力の製品検証、速度量、実メモリ量、採用の可否はこの事前文書の時点では未確認である。
