# ADR 0139 — text の表示では、巨大な行を折り返さず、キャレットの周りの窓だけを文字組みして印を付ける

- 状態: 提案（設計席 2026-10-16・施主決定 D53 の「いいえ」の側。試作 `experiment/giant-line-window` 7444f6e で open 4862 → 217 ms・1 打鍵 4504 → 1.5 ms）。実装は #547（土台は #544）
- 日付: 2026-10-16
- Issue: #527・#547・#542（D53）
- 規則: ARC-003 / ARC-010、CPP-002 / CPP-005、QLT-014、ADR 0034 / 0053 / 0073 / 0114 / 0138 / 0140

## 文脈

本文の文字組みは「行の完全な表示文字列を 1 つの DirectWrite layout に出し、描画と位置解決が同じ layout を使う」正典（ADR 0114）。1 行 16 MiB では DirectWrite の `GetMetrics` が約 4 秒で、渡す文字列の長さでしか決まらない（#527）。hide は D53 で「開くときに格子表示にするか聞く。しない場合はその行は折り返さず印だけ付ける。表示形式はコマンドで切り替えられる」と決めた。格子は ADR 0140。ここは「いいえ」の側＝いつもの表示（`text`）で巨大な行をどう出すか。

ADR 0114 が却下したのは「描画と位置解決が**別の**文字列で別々に整形して食い違う」形。ここで決めるのは、描画も位置解決も同じ 1 つの窓の layout を使う形で、2 本目の経路を作らず、正典の layout に渡す文字列の範囲を絞るだけ。

## 決定（提案）

1. **巨大な行の定義は core の定数 1 つ（ADR 0140 と共用）。** 表示文字列が `giant_line_threshold`（16,384 コードポイント）を超える行。
2. **`text` の表示では巨大な行だけ折り返さず、行番号の所に印を付ける。** 設定 `wrap` が on でも巨大な行は 1 画面行（行の全体を字形づけしないと折り返しの行数が決まらない）。印は gutter の色のトークン 1 つ（ADR 0008 の採用案の表に足す）と、行番号の隣の 1 文字。
3. **窓は状態を持たず、錨の丸めで決める。** 錨はキャレットがその行にあればキャレットの位置、無ければ横の送り量から字幅（`TextViewGeometry` に載せる・試作の穴 1）で見積もった位置。窓の中心は錨を 2,048 コードポイント刻みに丸めた位置で、前後 4,096（計 8,192）を `text_range` で読む（行の全体を写さない）。境界は Vim の 1 文字の境目（ADR 0053）。錨が刻みをまたげば次の要求で別の窓になる（試作の穴 2・状態なしで決定を満たす）。
4. **窓の layout は正典の 1 つ。** `TextLayoutRequest` に窓の始まり（行の中の位置と見積もった x）を足し、`BodyTextLayouts` は窓の文字列を鍵に layout を 1 つ作り、描画と位置解決が共用する。窓の外の位置（Home / End・`0` `$`・検索の当たり）は見積もった桁と `offset_of` で解き、次の要求で窓がそこへ動く（試作の穴 4）。
5. **横の送りは窓からの相対で、巨大な行だけ横に追従する。** x と送り量は float のまま、窓の始まりからの相対にして桁落ちを避ける（試作の穴 5・行末でキャレットが右端の外に出た件）。wrap on で巨大な行だけ横に追従し、普通の行のクリックの x を壊さない（穴 3）。
6. **行の中の歩きは塊の部分和で O(塊)。** `position_of` / `offset_of` が行の長さに比例して歩かないよう、ADR 0140 の決定 4 の仮想桁の部分和（64 KiB の塊）を使う（穴 6・#544）。
7. **記録と見張り。** `open-giant-line-16mib` と `key-to-frame-single-giant-line-16mib` を「いいえ」で測った値も記録する。既存 8 本は退行なし（6 KB 行はしきい値の下）。

## 却下した選択肢

- 行の全体を layout のまま保持を改訂で引く: 打鍵のたびに文字列が変わるので効かない。初回の 4 秒も残る。
- 窓を描画だけに使い位置解決は行の全体: ADR 0114 が却下した食い違い。
- 窓を状態として覚える: `VisualTextView` は位置解決ごとの一時物。錨の丸めで十分（試作で確認）。
- 巨大な行も折り返す（行数を見積もる）: 行数が実測と違うと縦の送りと `j` `k` が食い違う。折り返したいときは格子（ADR 0140）。
- 巨大な行を開かない・読み取り専用にする: 外部講評 P2 に応えない。
- 横の送りを double にする: 相対で足りる。型を増やさない。

## 検証

- core: 窓の純関数の表（#544）。application: 巨大な行の `LineView` が窓の長さしか持たない・刻みをまたぐと窓が変わる・Home / End が窓の外を解く。ui: 窓の layout で `locate` / `hit` の往復が一致。速さ: 2 本のベンチと既存 8 本。見た目: 16 MiB の 1 行で `j` `k` `$` `0` `G`・横の追従・印（hide の試用）。

## 限界

- 窓の境界をまたぐ合字・カーニング・双方向の並べ替えは行の全体の layout と違い得る（境界は見えている範囲から 2,048 以上遠い）。
- 巨大な行の中の Tab の位置は窓の始まりからの tab stop。
- 窓をまたぐ選択は窓の終わりを行末とみなして塗り、検索の当たりの強調は窓の中だけ（当たりへの移動は本文の照合なので正しい）。
- 巨大な行は折り返さない。折り返して見たいときは `:set display=grid`。
