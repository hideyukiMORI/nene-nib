# ADR 0140 — 巨大な行を含む文書は、聞いてから格子表示で開く

- 状態: 提案（設計席 2026-10-16。施主決定 D53 の形。実装は試作の数字を見てから Issue に分ける）
- 日付: 2026-10-16
- Issue: #527（内訳と直す順の 3）・#513（D52）・#542（D53）
- 規則: ARC-003 / ARC-010、CPP-002 / CPP-005 / CPP-012、QLT-014、ADR 0034（仮想桁）/ 0040（制御文字）/ 0053（Vim の 1 文字）/ 0114（本文の文字組み）/ 0138（ベンチ）/ 0139（いいえの側）

## 文脈

1 行 16 MiB の文書は open 6 秒・1 打鍵 5 秒で、残る 4 秒は DirectWrite が行の全体を字形づけする床（#527）。hide は D53 で「改行なしで巨大なものを開こうとしたら格子にするか聞く。しない場合はその行は折り返さずマークだけ付ける。表示形式はコマンドで切り替えられる」と決めた。ヘックスエディタのように文字を固定幅の升目に置けば、行数と位置が割り算で決まり、文字組みは見えている行だけで済む。

## 決定（提案）

1. **巨大な行の定義は core の定数 1 つ。** 本文の行（ソース）のコードポイントの数が `giant_line_threshold`（16,384）を超える行。`^M` `<200b>` などの表示の展開の前の数で数える。6 KB の日本語行（ADR 0075・2,077 コードポイント）は超えない。
2. **開くときに 1 回聞く。問いは最初の本文の文字組みより前。** 文書がアクティブになった直後（起動引数・Ctrl+O・Ctrl+P・復元・まだ読んでいなかったタブへの切り替え）に、application の `asks_grid` が判定する。まず改行の索引が 512 byte の塊ごとに持つ行の長さの要約を畳んで最長の行のバイト数を出し（O(塊)・`TextBuffer::longest_line_bytes`・Issue #553）、それがしきい値以下なら行を 1 つも見ない。超えるときだけ改行の索引から各行のバイトの長さを出し（O(行数)）、バイトでしきい値を超える行だけ行の内容を読んでソースのコードポイントを数える（コードポイントの数はバイトの数を超えない）。1 行でも超えれば ui が `MessageBoxW`（はい / いいえ）で「改行の無い巨大な行があります。格子表示で開きますか。」を 1 回聞く。答えは必ず意図で返す: はい → `SelectDisplay{grid}`、いいえと問いを出せなかったとき → `SelectDisplay{text}`（ADR 0139: その行は折り返さず、窓で文字組みし、行番号の所に印）。
   - 判定と問いの段階は文書ごとの閉じた enum `DisplayInquiry { unjudged, unneeded, waiting, raised, answered }`（`DocumentState` の `inquiry`）。判定は controller の `ask_display` の 1 本で、文書がアクティブになる入口（開いて無題に入れたとき・`enter_document` の先頭）と `apply` の終わりと起動の終わりから呼ぶ。起動の途中（コンストラクタの中）は判定せず、最後にアクティブになった文書だけを起動の終わりに判定する。Ctrl+Tab で歩いている間は判定して `waiting` に留め、確定で聞く。問いの印 `display_question` は `close_request` と同じく 1 意図だけ立つ。
   - `waiting` と `raised` の間（答えを待つ間）は本文の文字組みをしない。位置解決は幅の無い窓として答え（`TextLayoutPort` を呼ばない）、先頭行の収め直しとキャレットの追従はしない（復元した画面行を保つ）。frame は本文の行を持たず `display_pending` を立て、renderer は本文の背景と行番号の帯の面だけを塗って本文を描かない（判定は `draw_body` の 1 か所）。帯・ステータスバーはいつもどおり描く。答えの `SelectDisplay` が段階を `answered` にし、先頭行を収めてキャレットを追う（ここで初めて本文を組む）。
   - ui は `deliver` の終わり（無効化を積んだ後・frame を作る `WM_PAINT` より前）で問いを出す。問いの間に `MessageBoxW` のループで来る `WM_PAINT` は本文の無い frame を描く。起動の文書は、最初の frame（本文の無い frame）を出した後、`initialize` の終わりで同じ `ask_display` を呼ぶ（合図の窓メッセージは使わない）。問いの無い文書の起動と開く道に足されるのは `asks_grid` の判定だけ。
   - 問いは文書ごとに 1 回で、答えは文書の状態（`DocumentState` の `display`）に持つ。設定にもタブの一覧にも保存しない。
3. **表示形式は文書ごとの閉じた enum `DisplayForm { text, grid }` で、コマンドで切り替える。** Ex の `:set display=grid` / `:set display=text`（補完と Ctrl+P の `:` の一覧は既存の `set wrap` と同じ表に 1 行ずつ）。ステータスバーの右側に `grid` の印。巨大な行の無い文書でも切り替えられる（等幅で見たいときに使える）。
4. **格子の決め方は core の純関数。** 1 升の幅は等幅フォントの字幅、1 画面行の升数 `columns = floor(本文の幅 / 升の幅)`。各文字の升数は ADR 0034 の仮想桁（幅 1・幅 2・Tab は次の 8 の倍数まで・制御文字は `^M` `<200d>` の表示の長さ・幅 0 の結合文字は前の文字の升）。行 `L` の画面行数 `rows(L) = max(1, ceil(virtual_width(L) / columns))`、位置 → (画面行, 升) と (画面行, 升) → 位置は累積の仮想桁から。累積の仮想桁は、改行の索引と同じ形で **64 KiB の塊ごとの部分和**を持ち、編集で塊だけ作り直す。全バイトが表示できる ASCII と改行だけの塊（plain）は走査せず、塊の中の桁と序数は改行の索引で行頭を引いて `位置 − 行頭` で出す。Tab と制御文字（改行以外の 0x20 未満と 0x7F・`
` を含む）は ASCII でも 1 バイト＝1 桁でないので、それを含む塊は plain にしない（含むかは作るときの 1 回の走査で分かる）。text の索引は**要る文書だけが持つ**。`TextBuffer` の既定は索引無しで、`TextBuffer::with_virtual_columns()` が索引を一から作って持つ写しを返す（読んだばかりの 1 本の piece は写さずに読む）。持つ本文の `TextBuffer::replaced` だけが触れた塊を作り直し、持たない本文の編集は索引の費用が 0（`rebuilt_column_chunks()` が数える）。索引は改行の索引と同じく不変の値で `shared_ptr` で値のあいだに共有する。読む口は `has_virtual_columns()` と `virtual_columns()`（持たない本文に問うのは呼び出し側の誤りで、閉じた enum `VirtualColumnsFailure::not_held` を `std::expected` で返す）。索引を持つのは**巨大な行を含む文書と格子の文書だけ**で、`with_virtual_columns()` を呼ぶのは application の 2 か所: 判定（`ask_display`）が巨大な行を見つけたとき（答えに依らず持つ・いいえの窓の文字組みも使う）と、索引を持たない文書を `SelectDisplay{grid}`（問いの「はい」・`:set display=grid`）で格子にするとき。application は索引を作り直さず借りる。升の送り（2 升以上の文字が画面行の右端に収まらず次の画面行へ送る空き）は幅 `columns` に依るので索引には持たせず、application の `GridCells` が 1 回の位置解決の間だけ、行の中の plain でない塊の部分を 1 文字ずつ置いて数える（置き方は core の `grid_placed_cell` の 1 本）。plain の塊は長さを足すだけで、表示できる ASCII だけの行は割り算で答える（16 MiB の ASCII の 1 行で 1 打鍵の位置解決が歩く塊は 0）。core の `VirtualColumnIndex::for_grid`（升の送りを持つ索引）は core の表と application の契約の参照としてだけ使い、製品の道では作らない。常に持つ形（#544 の差し戻し 2）は、改行を含む塊を plain にしなかったため 16 MiB・200,000 行の文書で開く・連打が遅くなった（open 215→234 ms・200 打鍵 14.8→22.5 ms）ので採らない。塊は作るときに 64 KiB（code point の先頭へ寄せる）で切り、編集で触れた範囲が 128 KiB を越えたら 128 KiB 以下の等しい長さに切り直し、16 KiB を下回るなら次の塊と合わせて切り直す（1 打鍵で読み直すのは 1〜2 塊）。塊の要約は桁・升・行頭からのコードポイントの序数の始まりと、塊より前と塊の中の改行の数を持つ。位置を引くときに写すのは「塊の始まりか、塊の中で位置より前の最後の行頭（改行の索引から引く）」から位置までだけ。格子で送りの余り（桁の 8 の余りと升の `columns` の余り）が変わった後ろの全角の塊は読み直し、余りが揃ったままなら要約から足す。Tab の止まりの値は `VirtualColumn.hpp` の `vim_tab_stop` の 1 つ。
5. **文字組みは見えている画面行だけ。** 格子では `TextLayoutPort` の `rows` / `locate` / `hit` を core の純関数で答え、DirectWrite には描く画面行の文字列（升数ぶん）だけを等幅の format で渡す（`BodyTextLayouts` の保持の鍵は文字列と書式（表示形式を含む））。字形は升の左端に置き、幅 2 の文字は 2 升の左端。描画と位置解決は同じ格子を使う。字形を描く経路は本文と同じ `BodyTextPainter`（`GridRowPainter` は字形のループを持たず、clip を押して `draw_body_text` を呼ぶ・#569）。
6. **等幅フォントは core / ui の定数 1 つ。** 候補の列 `Cascadia Mono` → `Consolas` → 本文の字体で、設定には出さない。`:set guifont` は本文の字体のまま、格子では使わない。右から左に書く文字は並べ替えない（左から右の升に置く・限界）。
   - 追記（2026-10-17・#597・施主決定 D58）: 設定の字体が等幅ならそれを使う。格子の字体は `BodyTextLayouts::grid_family` の 1 関数が決め、設定の `font_family` が機械にあり既定の face が `IDWriteFont1::IsMonospacedFont` で真ならそれ、無いか等幅でなければ上の定数の列に落とす。呼び出し元は等幅かを問わない。字体は書式の鍵に入っているので、変えると格子の書式・升の幅・`FontFallbackCache` は text 形と同じく作り直す。
7. **Vim と通常の鍵の意味は変えない。** `j` `k` は画面行でなく本文の行（今日どおり）。`gj` `gk` は未対応のまま。横の送りは格子では無い（折り返すため）。
8. **ベンチと基準値。** `open-giant-line-16mib` と `key-to-frame-single-giant-line-16mib` は「はい」で開いた格子の値を測る（道具は問いに「はい」と答える引数を持つ）。D52 の基準値はこの形で採用する。

## 却下した選択肢

- 行ごとに格子と比例幅を混ぜる: 見た目が揃わず、横の位置の意味が行で変わる。文書単位。
- 問わずに自動で格子にする: D53 は「聞く」。切り替えはコマンドで。
- 格子でも比例幅フォントを升に置く: 字が升からはみ出す・重なる。等幅だけ。
- 格子の累積の仮想桁を毎回 O(n) で数える: 16 MiB で 1 打鍵ごとに 10 ms 以上。塊の部分和。
- 格子の行数を見積もりにする: 割り算で正確に出るので見積もりは要らない。

## 検証

- core: 格子の純関数の表（ASCII・全角・Tab・結合文字・制御文字・升の境目にかかる幅 2 の文字（次の行へ送る）・空行）。部分和の編集での作り直し。逆引き（桁・升・序数 → 位置）を複数の塊の行で、編集の後と塊の境目の前後で順引きと往復させる（幅 2 の 2 升目・送りの空き・画面行をまたぐ Tab の続きも同じ文字へ戻る）。切り直し（128 KiB 以下）と合わせ（16 KiB 以上・塊が本文を隙間なく覆う）を塊の列で、送りの余りが変わる側と揃う側の読み直しの数を `rebuilt_chunks` で確かめる。通常の複数行の文書で位置を引くとき写すのが行の一部だけ（`VirtualColumnCursor.copied`）。各契約は実装を一時的に壊して落ちることを確かめてある（#544）。
- application: 問いの 1 回・`SelectDisplay` の往復・`DocumentState.display` の保持と切り替え・quiet paths（問いの判定は改行の索引だけでファイルに触れない）。答えを待つ間（開く・寸法の変更・起動の最初の frame）は `TextLayoutPort` を 1 回も呼ばず frame の本文の行が空で、答えの後に組む。索引を持つのは巨大な行の文書（いいえの後も）と格子にした文書だけで、普通の文書の編集は索引の費用 0。`GridCells` は塊をまたぐ全角・Tab・制御文字・結合文字の行で core の `for_grid` と同じ升を答え、16 MiB の ASCII の 1 行では歩く塊 0。格子の 1 打鍵は同じ索引を借り、編集で作り直すのは触れた 1 塊。各契約は実装を一時的に壊して落ちることを確かめてある（#545）。
- ui / 実機: `verify-window.py --grid`（16 MiB の 1 行を「はい」で開く → 格子・`End` `Home` `j` `k`・クリックでキャレット・`:set display=text` で戻る）。速さ: 2 本のベンチと既存 8 本の退行なし。

## 限界

- 格子では右から左の文字を並べ替えない。合字は等幅フォントの字形に従う（升は 1 つずつ）。
- 幅 2 の文字が行末の 1 升に収まらないとき、その升は空けて次の行へ送る（Vim と同じ）。
- 格子の等幅フォントが無い機械では `Consolas` → それも無ければ OS の既定の等幅。
- 格子の升の送りは位置解決のたびに行の中の plain でない塊を歩く。全角だけの 16 MiB の 1 行では、1 回の位置解決が行頭から位置までを歩く（O(行)）。送りの余りを塊ごとに覚える形は、数字を見てから決める。
- 格子の検索の当たり（hlsearch の全一致・incsearch の preview・今の当たりの枠）は、見えている画面行の本文の範囲に「一致の長さの上限」（食べる原子 1 つにつき 4 バイト・core の `VimPattern::longest_bytes`）の余裕と文脈の 1 文字を前後に足した窓だけを読み、`vim_window_matches` で照合する（#556・数える口 `EditorFrame::grid_searched`）。text の表示の巨大な行の窓（ADR 0139）の当たりも同じ照合（窓の前後の 1 文字を文脈に読む）で出し、照合の経路は 1 本で限界も同じ。`^` は行頭でだけ、`\<` `\>` は窓の外の隣の文字を見て当たる。上限が決まらない検索（`*` の繰り返し）の余裕は `giant_line_half_width` の数（4,096）を **バイト**として使い（text の表示の窓は同じ数の **コードポイント**）、窓より外へ延びる一致は窓の境目で切れる。数え始めが行頭でなく窓の始まり（行の任意の位置）なので、一致が連続しうる検索（例 `/aa` `/\w\w` `/..`）は行頭から数えた区切りと位相がずれ、見えている範囲の頭でも違う位置に塗ることがある（移動は本文の照合なので正しい）。
- 格子の位置解決は変換中の文字列（IME の composition）を升に数えない（text は差し込んだ行で解決する）。描画で升に写すのは #546。
