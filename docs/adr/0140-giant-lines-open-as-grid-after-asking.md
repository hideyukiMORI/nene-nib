# ADR 0140 — 巨大な行を含む文書は、聞いてから格子表示で開く

- 状態: 提案（設計席 2026-10-16。施主決定 D53 の形。実装は試作の数字を見てから Issue に分ける）
- 日付: 2026-10-16
- Issue: #527（内訳と直す順の 3）・#513（D52）・#542（D53）
- 規則: ARC-003 / ARC-010、CPP-002 / CPP-005 / CPP-012、QLT-014、ADR 0034（仮想桁）/ 0040（制御文字）/ 0053（Vim の 1 文字）/ 0114（本文の文字組み）/ 0138（ベンチ）/ 0139（いいえの側）

## 文脈

1 行 16 MiB の文書は open 6 秒・1 打鍵 5 秒で、残る 4 秒は DirectWrite が行の全体を字形づけする床（#527）。hide は D53 で「改行なしで巨大なものを開こうとしたら格子にするか聞く。しない場合はその行は折り返さずマークだけ付ける。表示形式はコマンドで切り替えられる」と決めた。ヘックスエディタのように文字を固定幅の升目に置けば、行数と位置が割り算で決まり、文字組みは見えている行だけで済む。

## 決定（提案）

1. **巨大な行の定義は core の定数 1 つ。** 表示文字列が `giant_line_threshold`（16,384 コードポイント）を超える行。6 KB の日本語行（ADR 0075・2,077 コードポイント）は超えない。
2. **開くときに 1 回聞く。** 文書を開いた直後（起動引数・Ctrl+O・Ctrl+P・復元）に、いちばん長い行（改行の索引から各行の長さを出す・O(行数)）がしきい値を超えていれば、ui が `MessageBoxW`（はい / いいえ）で「改行の無い巨大な行があります。格子表示で開きますか。」を 1 回聞く。はい → 意図 `SelectDisplay{grid}`。いいえ → `text` のまま（ADR 0139: その行は折り返さず、窓で文字組みし、行番号の所に印）。問いは文書ごとに 1 回で、答えは文書の状態（`DocumentState` の `display`）に持つ。設定には保存しない。
3. **表示形式は文書ごとの閉じた enum `DisplayForm { text, grid }` で、コマンドで切り替える。** Ex の `:set display=grid` / `:set display=text`（補完と Ctrl+P の `:` の一覧は既存の `set wrap` と同じ表に 1 行ずつ）。ステータスバーの右側に `grid` の印。巨大な行の無い文書でも切り替えられる（等幅で見たいときに使える）。
4. **格子の決め方は core の純関数。** 1 升の幅は等幅フォントの字幅、1 画面行の升数 `columns = floor(本文の幅 / 升の幅)`。各文字の升数は ADR 0034 の仮想桁（幅 1・幅 2・Tab は次の 8 の倍数まで・制御文字は `^M` `<200d>` の表示の長さ・幅 0 の結合文字は前の文字の升）。行 `L` の画面行数 `rows(L) = max(1, ceil(virtual_width(L) / columns))`、位置 → (画面行, 升) と (画面行, 升) → 位置は累積の仮想桁から。累積の仮想桁は、改行の索引と同じ形で **64 KiB の塊ごとの部分和**を持ち、編集で塊だけ作り直す。全バイトが表示できる ASCII と改行だけの塊（plain）は走査せず、塊の中の桁と序数は改行の索引で行頭を引いて `位置 − 行頭` で出す。Tab と制御文字（改行以外の 0x20 未満と 0x7F・`` を含む）は ASCII でも 1 バイト＝1 桁でないので、それを含む塊は plain にしない（含むかは作るときの 1 回の走査で分かる）。text の索引は**要る文書だけが持つ**。`TextBuffer` の既定は索引無しで、`TextBuffer::with_virtual_columns()` が索引を一から作って持つ写しを返す（読んだばかりの 1 本の piece は写さずに読む）。持つ本文の `TextBuffer::replaced` だけが触れた塊を作り直し、持たない本文の編集は索引の費用が 0（`rebuilt_column_chunks()` が数える）。索引は改行の索引と同じく不変の値で `shared_ptr` で値のあいだに共有する。読む口は `has_virtual_columns()` と `virtual_columns()`（持たない本文に問うのは呼び出し側の誤りで、閉じた enum `VirtualColumnsFailure::not_held` を `std::expected` で返す）。誰が `with_virtual_columns()` を呼ぶか（巨大な行を含む文書を開いたとき・`:set display=grid` のとき）は application（#545）が決め、application は自分で作り直さない（升は `columns` に依るので格子は `for_grid`）。常に持つ形（#544 の差し戻し 2）は、改行を含む塊を plain にしなかったため 16 MiB・200,000 行の文書で開く・連打が遅くなった（open 215→234 ms・200 打鍵 14.8→22.5 ms）ので採らない。塊は作るときに 64 KiB（code point の先頭へ寄せる）で切り、編集で触れた範囲が 128 KiB を越えたら 128 KiB 以下の等しい長さに切り直し、16 KiB を下回るなら次の塊と合わせて切り直す（1 打鍵で読み直すのは 1〜2 塊）。塊の要約は桁・升・行頭からのコードポイントの序数の始まりと、塊より前と塊の中の改行の数を持つ。位置を引くときに写すのは「塊の始まりか、塊の中で位置より前の最後の行頭（改行の索引から引く）」から位置までだけ。格子で送りの余り（桁の 8 の余りと升の `columns` の余り）が変わった後ろの全角の塊は読み直し、余りが揃ったままなら要約から足す。Tab の止まりの値は `VirtualColumn.hpp` の `vim_tab_stop` の 1 つ。
5. **文字組みは見えている画面行だけ。** 格子では `TextLayoutPort` の `rows` / `locate` / `hit` を core の純関数で答え、DirectWrite には描く画面行の文字列（升数ぶん）だけを等幅の format で渡す（`BodyTextLayouts` の保持の鍵は今日どおり文字列）。字形は升の左端に置き、幅 2 の文字は 2 升の左端。描画と位置解決は同じ格子を使う。
6. **等幅フォントは格子の設定 1 つ。** `grid_font`（既定 `Cascadia Mono`・無ければ `Consolas`）。`:set guifont` は本文の字体のまま、格子では使わない。右から左に書く文字は並べ替えない（左から右の升に置く・限界）。
7. **Vim と通常の鍵の意味は変えない。** `j` `k` は画面行でなく本文の行（今日どおり）。`gj` `gk` は未対応のまま。横の送りは格子では無い（折り返すため）。
8. **ベンチと基準値。** `open-giant-line-16mib` と `key-to-frame-single-giant-line-16mib` は「はい」で開いた格子の値を測る（道具は問いに「はい」と答える引数を持つ）。D52 の基準値はこの形で採用する。

## 却下した選択肢

- 行ごとに格子と比例幅を混ぜる: 見た目が揃わず、横の位置の意味が行で変わる。文書単位。
- 問わずに自動で格子にする: D53 は「聞く」。切り替えはコマンドで。
- 格子でも比例幅フォントを升に置く: 字が升からはみ出す・重なる。等幅だけ。
- 格子の累積の仮想桁を毎回 O(n) で数える: 16 MiB で 1 打鍵ごとに 10 ms 以上。塊の部分和。
- 格子の行数を見積もりにする: 割り算で正確に出るので見積もりは要らない。

## 検証

- core: 格子の純関数の表（ASCII・全角・Tab・結合文字・制御文字・升の境目にかかる幅 2 の文字（次の行へ送る）・空行）。部分和の編集での作り直し。逆引き（桁・升・序数 → 位置）を複数の塊の行で、編集の後と塊の境目の前後で順引きと往復させる（幅 2 の 2 升目・送りの空き・画面行をまたぐ Tab の続きも同じ文字へ戻る）。切り直し（128 KiB 以下）と合わせ（16 KiB 以上・塊が本文を隙間なく覆う）を塊の列で、送りの余りが変わる側と揃う側の読み直しの数を `rebuilt_chunks` で確かめる。通常の複数行の文書で位置を引くとき写すのが行の一部だけ（`VirtualColumnCursor.copied`）。各契約は実装を一時的に壊して落ちることを確かめてある（#544）。
- application: 問いの 1 回・`SelectDisplay` の往復・`DocumentState.display` の保持と切り替え・quiet paths（問いの判定は改行の索引だけでファイルに触れない）。
- ui / 実機: `verify-window.py --grid`（16 MiB の 1 行を「はい」で開く → 格子・`End` `Home` `j` `k`・クリックでキャレット・`:set display=text` で戻る）。速さ: 2 本のベンチと既存 8 本の退行なし。

## 限界

- 格子では右から左の文字を並べ替えない。合字は等幅フォントの字形に従う（升は 1 つずつ）。
- 幅 2 の文字が行末の 1 升に収まらないとき、その升は空けて次の行へ送る（Vim と同じ）。
- 格子の等幅フォントが無い機械では `Consolas` → それも無ければ OS の既定の等幅。
