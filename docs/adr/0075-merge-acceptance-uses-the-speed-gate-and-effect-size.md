# ADR 0075: 性能改善の統合は正式な速さのゲートと効果の大きさで受理し、事前実験の保留は記録として残す

- Status: accepted
- Date: 2026-10-06
- Issue: #291
- 影響する規則: D41 / QLT-001 / QLT-010 / QLT-012 / QLT-013 / QLT-014 / ADR 0016 / ADR 0068

## 文脈

#291 の改善一式（ADR 0069・0070・0071・0073・0074）は、長い日本語行の 1 打鍵を main の約 326 ms から 7.2695 ms に縮めた。最後の固定比較は、文字組みとステータスの再利用まで入った `0dfad49`（O）と一式の `311e78b`（A）で、1 打鍵 28.534 → 7.2695 ms、200 文字 175.1165 → 91.5315 ms。
表示は 22 場面で 0 画素差、IME の変換と確定も確かめてある。それでも PR #293 は Draft のまま 2 日止まり、分離した #294 / #295 も同じ理由で止まった。

止めていたのは、#290（ADR 0068）の split の実験のために置いた**測定の揺れの条件**である。
「同じ版の 6 本のうち前半 3 本と後半 3 本の中央値の差が `max(床, 中央値の 10%)` を越えたら、その本文の判定を保留する」。
これは 0.5 ms の増分のような**小さな差を揺れから守る**ための条件で、Issue #291 の事前計画がそのまま引き継いだ。

2026-10-06 に設計席が保存済みの 90 本（[render-capsule-2026-10-05.json](../quality/render-capsule-2026-10-05.json)）を計算し直した。新しい測定はしていない。

| 版・指標 | 6 本の値 ms（測った順） | 許容 ms | 前後半の差 ms |
| --- | --- | ---: | ---: |
| 比較元 O・長行 1 打鍵 | 28.020 / 28.645 / 32.491 / 27.459 / 29.337 / 28.423 | 2.8534 | 0.222 |
| 改善一式 A・長行 1 打鍵 | 7.633 / 8.107 / 6.906 / 6.833 / 7.990 / 5.690 | 0.72695 | 0.800 |

1. **外れたのは 12 指標のうち A の長行 1 打鍵の 1 つだけ**。空文書と 16 MiB 短行は O / A の 8 指標すべてが条件内で、A の中央値は O 以下。ただし O は main ではないので、main からの悪化が無いことは決定 4 のとおり正式なゲートで示す。
2. **順に沿った悪化ではない**。A の 6 値は約 1 ms の幅に散っていて、単調に増えても減ってもいない。6 本を 3 本ずつに分けるどの分け方でも許容を越えるので、「前半と後半」という時刻の分け方が効いたのではなく、値の散らばりそのものが許容より広い。
3. **許容は値に比例して縮む**。O は 5 ms 散っても許容 2.85 ms に収まり、A は 1 ms の散らばりで許容 0.73 ms を外れる。速くするほど外れやすい条件であり、改善した版の受理を止める向きに働く。
4. **効果は揺れの 20 倍を越える**。差は 21.26 ms、対応する 6 組すべてで短縮。別の固定実験（各 240 打鍵）では A の観測最大 7.978 ms が、O の 240 件すべて（16.7 ms 超が 240 / 240）より小さい。

前の席は「測定後に閾値を変えない」「合格まで繰り返さない」を守って保留を続けた。その規律は正しい。足りなかったのは、**その条件が何を守るためのものか**を統合の判断と切り分ける決定である。

## 決定

1. **事前実験の判定は書き換えない。** [gate-proofs 5-ck / 5-cl / 5-cm / 5-cn / 5-co](../quality/gate-proofs.md) と実測 JSON の `hold` は、その実験の事前条件に対する結果としてそのまま残す。閾値・試行数・除外を後から変えない。再測定で合格を取りにいかない。
2. **main への統合を決めるのは次の 4 つ。**
   1. 書いた席とは独立の席のレビューで、統合を止める所見が無い（または直してある）。
   2. 正式な速さのゲート（QLT-014・`eng/measure-speed.py --check`・`eng/perf-reference.json` の実機の基準値・許容 25% / 床 2 ms）が通る。基準値と許容は変えない。
   3. 必須 check（CI）が緑。
   4. 施主の実機の試用で問題が無い。
3. **測定の揺れの条件は「小さな差の判定を保留する」ためにだけ使う。** 差が許容幅と同じ桁のとき（split の増分・空文書の 0.1 ms 台）は今までどおり保留の根拠になる。効果が揺れを大きく越え、対応する組のすべてで同じ向きで、分布が重ならないときは、改善の有無の結論を止めない。この切り分けは個別の PR で設計席が根拠の数字とともに書く（QLT-010 の「明示的な根拠」）。
4. **悪化が無いことは、条件内の比較か正式なゲートで示す。** 改善を狙った本文以外（空文書・短行）で揺れの条件が外れたときは、正式なゲートの該当ベンチで判定する。どちらも無いまま「悪化なし」と書かない。
5. **split の採用は別の判断のまま保留。** 「合計 2 ms 以内」は長行では単画面でも満たせない（A 単体で 7.27 ms）。split を再開するときは、条件の立て方から施主と決め直す（ADR 0068 は変えない）。
6. **分離した #294 / #295 は #291 の統合で役目を終える。** 中身は #291 の一式に含まれる。PR #296 / #297 は統合せずに閉じ、ブランチと証拠は消さない。
7. **長い行の速さを守るベンチを足す。** いまの 7 本には長い行が無く、統合した後の 7 ms を守る機械が無い。別 Issue で `eng/measure-speed.py` に 1 本足し、実機の基準値を採用する（ADR 0016 の手順）。

## 却下

- **揺れの条件の許容を広げる・床を上げる。** 事前に固定した実験の条件を後から動かすことになる。条件は動かさず、何の判断に使うかを決める。
- **条件を満たすまで測り直す。** QLT-012 が禁じる「成功するまでの反復」。値の散らばりが許容より広いので、通ったとしても偶然である。
- **保留を続ける。** 確かな改善が main に入らず、作業木 17 個と Draft PR 3 本が残り、後続の作業が同じファイルで衝突する。
- **速さのゲートの合格だけで受理する。** ゲートは長行を測っていない。長行の改善は保存済みの対比較と 240 件の分布で示し、ゲートは「既存の 7 本が悪化していない」ことに使う。

## 限界

- 対比較と分布は「入力を受けてから Present が戻るまで」で、OS の入力待ちと画面が光るまでを含まない。
- A の 1 打鍵が約 1 ms の幅で散る理由は特定していない。
- 物理 DPI の遷移・device lost・確保失敗の実再現は #291 の未了のまま（gate-proofs 5-cm）。
