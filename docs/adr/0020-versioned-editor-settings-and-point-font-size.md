# ADR 0020 — 版付き設定と pt の本文フォント

## 文脈

C1 はテーマの値と名前の表まで。C2 は D14 / FR-017 のフォント変更と設定の保存を同時に入れる。既存の本文は `13.5 DIP` だが D14 は `13.5 pt` なので、同じ数を別の単位として保存してはならない。ポートが 5 本になるため、EditorController の 4 引数の入口も移行する。

## 決定

1. **所有者は EditorState。** `core::EditorSettings` は本文の `FontSize`、フォント名の `DisplayText`、任意の `BuiltinTheme` を持つ。テーマ無しは system という一つの意味。既定は 13.5 pt / Cascadia Code / system。`FontSize::from_points` が有限の 8〜40 pt だけを受ける唯一の生成口。浮動小数の NaN / 無限大も範囲比較で拒否する。フォント名は既存の DisplayText の UTF-8・長さ・制御文字の検証を使う。
2. **外部契約は SettingsPort。** `read() → expected<optional<EditorSettings>, SettingsFailure>` と `write(EditorSettings) → expected<void, SettingsFailure>`。無しは設定ファイルが無い場合だけ。失敗は型付きで返し、UI が理由を表示する。合成ルートから渡す `EditorPorts` は名前付きのポート参照を束ね、controller の入口はこれを受ける一つに移行する。
3. **永続化は adapters/win32。** `%LOCALAPPDATA%/NeNeNib/settings.v1` を UTF-8 の小さいテキストとして読む。上限 4096 bytes。場所の解決と保存形式は adapters に閉じ、バイトの読み書きは注入した既存 FilePort を使う。他の具象 adapter を直接呼ばない。初回の実変更時だけディレクトリとファイルを作る。普通の文字入力や終了では保存しない。
4. **version=1 の全体を一度に検証する。** 4 キー `version` / `colorscheme` / `font_family` / `font_size` をそれぞれ一つ必須にする。LF / CRLF、UTF-8 BOM、行端の空白と空行を受ける。値の前後の ASCII 空白は除く。名前中の空白と `=` は値の一部。未知のキー・重複・欠落・不正な数値は拒否し、未知の version は非互換として拒否する。数値はロケール非依存の十進 pt、保存は std::format。DTO と codec は adapters に置き、domain の検証とテーマ名の表は再実装しない。未対応の版への移行は無い。将来の版は別 ADR で移行を定める。
5. **失敗した設定を保存で潰さない。** 読めなかった場合は明示した理由とともに、その起動では既定設定で本文の作業を続けられる。設定の変更は保存失敗として拒否し、元のファイルを保つ。成功時は保存してから設定状態を置き換え、保存失敗時は元の見た目を保つ。設定のエラーは文書のエラーと別の表示値にする。起動エラーは最初の表示行数通知で消えないよう窓が控えて告知する。
6. **競合した設定を上書きしない。** adapter は最後に正常に読んだ／書いた bytes（無しも含む）を記憶する。保存時は同じ場所の lock ファイルを共有無しで開き、現在の bytes が記憶と一致することを調べてから FilePort の一時ファイル置換を呼ぶ。他のプロセスの変更・ロック中・書込失敗は拒否する。lock は RAII で解放する。これは同じ保存手順を使うプロセス間の保護で、外部エディタとの比較後の競合までは保証しない。
7. **フォント変更は独立した意図。** Ctrl+`+` / Ctrl+`-` / Ctrl+`0` と Ctrl+ホイールが、増減・既定復帰の閉じた意図へ写る。主キーとテンキーを受ける。増減は 1 pt ずつ、端では 8 / 40 に止まり、同じ値なら書かない。ホイールは 120 単位を 1 step とし、小さい差分を UI で累積する。通常と Vim の両方で使え、本文・レジスタ・undo は変えない。IME の変換中は鍵を奪わない。C3 の Ex / Ctrl+P はこの slice に入れない。
8. **pt と DIP は区別する。** 本文は `pt × 96 / 72` DIP として、renderer が DPI を一度だけ掛ける。本文の行高は、この DIP に 1.6 を掛けて整数 DIP へ丸める（既定 29 DIP）。行番号の欄は既定 56 DIP から pt に比例し、行番号の文字と右余白も比例する。タイトル・ステータス・上余白・細いキャレットの幅は固定。既存の 13.5 DIP / 24 DIP の本文から見た目が変わることを設計比較と実機に記録する。計画の「フォントサイズ×1.6」は、この単位変換を明示して更新する。
9. **レイアウトは一つ。** `body_layout(width,height,dpi,font_size)` を窓・描画・クリックが共有する。フォント変更時には表示行数の既存意図を通し、Vim の半画面量リセットと caret の追従も既存経路を使う。renderer が持つフォントは描画資源のキャッシュで、表示値との比較と DPI 変更で更新する。クリック前にも現在の表示値へ同期し、描画待ちで古い字幅を使わない。IME の変換中は成功した描画の後に、更新された caret 矩形から候補窓を再配置する。行番号の欄・文字・右余白の基準は、13.5 pt でそれぞれ 56 / 12 / 16 DIP とし、比例係数は core::font_size_ratio が唯一の経路。保存失敗や上限など実際のサイズが変わらない場合は表示行数を通知せず、スクロール位置を保つ。
10. **テーマは既存の表から決める。** system は OS の外観を使い、指定テーマはその明暗と Palette を使う。OS の観測値は EditorState が保ち、表示値で指定テーマに解決する。テーマ名は既存の `theme_named` のみ。OS の外観から既定テーマへの対応は `theme_for` に一本化し、既存の `palette_for` も同じ関数を使う。C2 ではファイルから選び、対話的な選択は C3。未インストールの本文フォントの代替は DirectWrite の既存の fallback とし、設定名は書き換えない。専用フォント選択 UI と存在確認は C3 の設計時に扱う。

```text
version=1
colorscheme=system
font_family=Cascadia Code
font_size=13.5
```

## 検証と未確認

単体 3,992 checks と adapter の往復・失敗検査が成功。サイズ境界・非数・読込/保存失敗・本文/undo/選択の不変・system と指定テーマ・96/120/192 DPI の geometry を検査した。実機は Windows 11・120 DPI・Microsoft 日本語 IME で、拡縮/復帰・Ctrl+ホイール・通常/Vim・再起動・拡大後のクリックと変換/確定・無変更時のスクロール保持が成功した。カバレッジは 1,454 / 1,588 分岐（91.56%）。実測と再利用の根拠は quality/gate-proofs.md と PR が正。検証頻度は ADR 0021 に従い、合格基準・閾値・除外は変えない。別モニターへの DPI 移動、変換中の拡縮に伴う候補窓の目視、他の IME は未確認。

## 却下した選択肢

- core / UI が設定ファイルを読む: プラットフォーム境界と状態の所有を崩す。
- 設定専用の原子的保存をもう一つ書く: FilePort と同じ意味の経路を増やす。
- 読めない版や値を無言で初期化: ARC-009 に反し、元の設定を失う。
- フォントだけ UI が保持して倍率を掛ける: クリック・表示高・保存値の意味が分かれる。
- Ex やフォント選択ダイアログも一緒に作る: C3 の対話設計まで範囲を広げる。
