# ADR 0168 — Ex の `:s` の族は 1 回の `Edit` で、入力中の当たりは見えている行だけの preview

- 状態: 受理（施主決定 D67・FR-027・2026-10-28。実装は 2〜3 席・受理は D41 の形・fixture は oracle で Vim 9.1 と合わせる）
- 日付: 2026-10-28
- Issue: #1007・計画 `docs/plans/2026-10-28-editing-features-roadmap.md` §1 の 9
- 規則: FR-027、ARC-001 / ARC-003 / ARC-004、CPP-002 / CPP-005 / CPP-011 / CPP-012、QLT-014、ADR 0012（oracle）/ 0022（Ex の評価は core の 1 本）/ 0030（`.`）/ 0032（検索の照合器 `VimPattern`・`magic` の部分集合）/ 0041（incsearch の preview は engine の外）/ 0052（undo のキャレット）/ 0057（Ex の失敗の形）/ 0152（`''`）

## 文脈

Nib の Ex は設定・タブ・文書・窓の命令だけで、`:s` が無い（ヴァニラの穴・hide の指摘で一番痛い）。照合器 `VimPattern` は `magic` の部分集合で、群 `\(` `\)` と後方参照は未対応。incsearch は入力中の当たりを engine の外の preview として見せる形（ADR 0041）がある。oracle は `:normal!` に `:s` を流せるので fixture で Vim と合わせられる。

## 決定

1. **受ける形。** `:[range]s/{pat}/{rep}/[flags]`・`:[range]s` と `:&`・`:&&`（直前の置換の繰り返し）・`g&`（全行で `:s//~/&`）・`:[range]g/{pat}/d`・`:[range]g/{pat}/s//{rep}/`・`:[range]v/{pat}/d`・`:[range]sort [i][u][n]`・`:[range]d [x]`・`:[range]y [x]`・`:[range]normal {keys}`（後続）。区切りは `/` のほか `#` `|` `@`（Vim と同じ・`pat` に `/` を含めるため）。`{range}` は `%`・`N`・`N,M`・`.`・`$`・`'<,'>`（VISUAL から `:` で入る）・`'a,'b`・`N;M`（後続）・相対 `+N` `-N`。
2. **flags。** `g`（行の全部）・`i` `I`（大小）・`c`（確認・決定 6）・`n`（数えるだけ・報せ）・`&`（前の flags を保つ）・`e`（当たりが無くてもエラーにしない）。既定は行の最初だけ（`gdefault` は持たない）。
3. **`{rep}` の特殊。** `&`（当たり全体）・`\0`〜`\9`（群）・`~`（前の `{rep}`）・`\n`（NUL → Nib では改行として受けない・限界: Vim の `\n` は NUL）・`\r`（改行を入れる）・`\t`・`\`・`\&`・`\u` `\l` `\U` `\L` `\e` `\E`（大小）。`magic` の既定。
4. **照合器に群を足す（ADR 0032 の範囲の拡張）。** `VimPattern` に `\(` `\)`（最大 9 群・入れ子可）と後方参照 `\1`〜`\9`（照合の中・後続）を足し、`matched` が群の範囲を返す。性質の試験（`--vim-pattern-property`）に群の往復（群の範囲は当たりの中・入れ子の包含）を足す。既存の検索（`/` `?` `*`）の答えは変わらない（契約で固定）。
5. **置換は 1 回の `Edit`。** 範囲の行を順に走り、行ごとに当たりを `{rep}` で置き換えた本文を組み、全体を 1 つの `Edit`（undo 1 単位・`restore` は `:` を打ったときのキャレット・ADR 0052）にする。キャレットは最後に置換した行の最初の非空白（Vim の実測・fixture）。当たりが無ければ `E486: Pattern not found: {pat}`（`e` 無し）。`''` を置く（jump・Vim の `:s` は `''` を置く・fixture で確かめる）。`:g` は 1 回走って該当の行の集合を決め、`d` はその行を 1 つの `Edit` で消す・`s//` は決定 5 の置換を該当の行に。`:sort` は範囲の行を並べ替えた本文を 1 つの `Edit`（`i` は大小を畳む・`u` は重複を消す・`n` は数で・安定・`std::stable_sort` は使わず自前の併合で決定的に）。`:d` `:y` はレジスタ `x`（省けば無名・ADR 0050 の規則で `"1` へ）。
6. **`c`（確認）。** 当たりごとにステータスバーに `replace with {rep} (y/n/a/q/l)?` の問い（Vim の文言のまま英語）を出し、`y`（置く）`n`（飛ばす）`a`（残り全部）`q` / Esc（止める）`l`（置いて止める）。確認の途中はコマンド入力の状態（Vim の鍵は通らない・IME は閉じる）。置いた分は決定 5 と同じ 1 つの `Edit` に畳む（途中で止めても 1 単位）。
7. **入力中の preview。** `:s/pat` を打っている間、見えている行の `pat` の当たりを incsearch と同じ面（`search`）で見せ、`/rep/` まで打てば当たりの右に置換後の本文を薄く（`muted`・engine の外の preview・本文は変えない・Neovim の `inccommand=nosplit` の形）。Esc で消える。preview の計算は見えている行だけ（60 行・D67）。
8. **oracle の fixture。** `ex-substitute-` の接頭辞で Vim 9.1 と合わせる（`:s/a/b/`・`g`・`i`・`%`・`'<,'>`・`&`・`\1`・`~`・`\r`・`\U`・`:g/x/d`・`:v`・`:sort u`・`:2,3d a`・`E486`・キャレットと `''`）。`c` は oracle で測れない（対話）→ 契約。
9. **費用。** 置換は範囲の行数 × 当たりの数に比例（`:%s` の 16 MiB は数百 ms の見込み・1 回の `Edit` なので undo も 1 回・巨大な文書の `:%s` は段 5 の worker の後続）。打鍵の道は変えない（`:` の入力行の中だけ）。preview は見えている行だけ。
10. **限界（後続）。** `:[range]normal`・後方参照の照合（`\1` を `pat` の中で）・`\n` の NUL・`:s` の `p` `#` `l` の表示 flags・`:global` の中の `normal`・`gdefault`・巨大な文書の worker 化。

## 強制

- Ex の評価が core の 1 本（`evaluate_ex`）に載ること・置換が 1 回の `Edit`: **active**（契約）。
- fixture: **active**（oracle・`c` 以外）。
- 群を足した照合器の既存の答えの不変: **active**（fixture 全件 ＋ `--vim-pattern-property`）。
- 8 本の速さ: **active**（QLT-014・打鍵の道は不変）。

## 結果

得られるもの: Vim の置換の日常（`:%s/a/b/g`・`:'<,'>s`・`:g/x/d`・`:sort`）が Vim と同じ答えで動く。入力中に当たりと置換後が見える。
失うもの・残る穴: 巨大な文書の `:%s` は止まる（段 5 まで）。`c` の対話は oracle で測れず契約の値。

## 却下した選択肢

| 選択肢 | 却下の理由 |
|---|---|
| 行ごとに `Edit` を積む | undo が行の数になる。Vim は 1 単位 |
| 外部の正規表現（`std::regex` / PCRE） | `std::regex` は例外と遅さ・PCRE は外部。`VimPattern` に群を足す方が ADR 0032 の 1 本を保つ |
| preview を別の窓（`inccommand=split`） | 2 枠の仕組みと衝突。見えている行の中だけで足りる |

## 追補（2026-11-12・#1007 段 1・実装席）

段 1（`:s` `:&` `:&&` `:~` と NORMAL の `&` `g&`）を、10-28 の後に入った木（ADR 0174 の置換の本体・#1376 の上限・#1547 の範囲つきの入力行・ADR 0181 の変更の印・ADR 0052 の `Edit.restore`）に寄せて実装した。Vim 9.1 の実測は `docs/quality/vim-substitute-2026-11-12.md`（163 形 ＋ レビュー V-1564 の 14 形）で、fixture は `substitute-` の 170 件。

1. **置換の本体は 1 本。** ADR 0174 の `substituted_all` を一般化した core の `substituted(text, pattern, replacement, SubstituteRequest{first, last, every, count_only, limit})`（`SubstituteAll.hpp`）が行ごとの編集（`VimBlockEdit`）を返し、通常モードの「すべて置換」は同じ本体の答えを 1 つの `Edit` に畳む（`substituted_all`・literal の置き換え）。第 2 の置換の経路は作らない。上限は #1376 と同じ（1 周目で数え、本文を作る前に `too_large`）。
2. **行の当たりの順は Vim の `do_sub`。** 前の当たりの終わりから探し、前の当たりにぴったり続く長さ 0 の当たりは数えずに 1 文字進め、行の終わりで止める（`:s/x*/-/g` は `abc` を `-a-b-c`・実測）。通常モードの語は literal で長さ 0 にならないので答えは変わらない。`--substitute-property` の模型もこの規則に直した。
3. **置き換えの本文は `SubstituteReplacement`。** 決定 3 の特殊のうち `\n` は Vim の実測どおり NUL のバイト（決定 3 の「改行として受けない」を NUL を入れる形に改める）、`\b` は BS、`\<CR>` は CR の文字、末尾の `\` は `\`。`\u` `\l` `\U` `\L` は VimCase の写像（`ß` はそのまま・`ǆ` は `Ǆ`・実測）。`~` は `vim_tilde_expanded`（Vim の regtilde）で前の広げた置き換えに解く。`\=` は断る。
4. **群（決定 4）。** 群は原子の列に入れず `VimPatternGroup` の列で持つので、既存の照合の答えは変わらない（契約で固定）。群の範囲は置き換えが `\1`〜`\9` を読むときだけ `VimPattern::captured`（`VimPatternCapture`・照合器と同じ優先順の道を 1 本・試した所の印で 2 度試さない）で引く。上限を超える一致の扱いは 13。`\(` の直後の `*` は文字・`^` は錨、`\)` の直前の `$` は錨、群の繰り返し `\(ab\)*` と 10 個目の群は断る。
5. **範囲は `parsed_ex_range` の 1 本。** #1547 の `range_length` もここから長さを取る。行に解くのは engine（`resolved_lines`）: 本文の外は E16、マークが無ければ E20、逆向きは E493（Vim の `:normal` の中の答え）、0 行目は 1 行目。`;` の後ろは前の番地から数える。
6. **engine の入口は `vim_substituted` の 1 本。** controller は Ex の答えの `substitute` を `VimStepSource` に入れて `:N` と同じ写しの道で流す（E486 などの失敗は #1547 と同じく再生を打ち切る）。`&` は回数つきなら `:.,.+(N-1)s`、`g&` は `:%s//~/&` を同じ入口へ。`&` `g&` は `.` の記録に積まない（`x&j.` は `x`・実測）。VISUAL の `&` は鳴らすだけ、`g&` は NORMAL と同じ（実測）。オペレータの後ろの `&` は失敗。
7. **効果は `VimReplaceBlock`（行ごとの編集）。** controller の `apply_block` が 1 つの置き換えに畳む（undo 1 単位は決定 5 のまま）。行の間の本文は文書のバイトのまま写し、置き換えの改行だけを文書の改行（CRLF）に直す。`\r` を含む置き換えでも下の行のマークは行のずれで動き、同じ行のマークは動かない（実測）。
8. **キャレットと undo の戻り先。** キャレットは最後に置き換えた行（置き換えが入れた改行の後ろ）の最初の非空白、空白だけの行は最後の文字（Vim の `beginline(BL_WHITE | BL_FIX)`）。`$` の後の繰り返し（`:s` `&` `:&` `:~`）は行末（Vim の endcolumn）。**`restore` は決定 5 の「`:` を打ったときのキャレット」ではなく、最初に置き換えた行の頭**（Vim の u_savesub の uh_cursor・`u` と Ctrl-r は (2,1) に着く・実測）。`''` は置換の前のキャレット（実測）。ADR 0181 の印は `changed`。`'[` `']` は Nib に無いので置かない。
9. **前の置換と直前の検索。** 打った置き換え・広げた置き換え・フラグ・置換のパターン（Vim の old_sub・reg_prev_sub・subflags・RE_SUBST）は `VimState.last_substitute`（不変の値を `shared_ptr` で共有）。置換のパターンは直前の検索（RE_LAST・`n` が探す）にもなり、向きは前の検索のまま、`:nohlsearch` で止めた強調を戻す。空の pat・`:~`・`r` は直前の検索、`:s` `:&` `&` は置換のパターン。前の置換が要る形で無ければ E33、パターンが無ければ E35。
10. **報せ。** 置き換えは 3 つ以上のときだけ `N substitutions on M lines`（Vim の 'report' の既定 2）、`n` はいつも `N matches on M lines`（`VimSearchNotice` の文の 1 か所）。`e` は当たりが無くても何もしない。
11. **段 1 で断る形（閉じた失敗・1 行の知らせ）。** `c`（段 2・決定 6）と `p` `#` `l`（決定 10）のフラグ、`\=`、`\/` `\?` `\&` の区切り、ASCII の外の区切り。照合器が受けない構文（`\n` の行またぎ `:%s/\n//`・`\|`・`\{}`・パターンの `~`）は「Unsupported pattern」の報せ。`[/]` の中の区切りは受ける（`:s/[/]/X/` は Vim と同じく `a/b` を `aXb`・実測）。`?` を区切りにした `\?` は `?` の文字（Vim の skip_regexp_ex・`:s?a\?b?X?`・実測）。
12. **速さ。** 置換を使わない打鍵の道は、`.` の記録が変更の鍵を確定するときの `&` の判定 1 つ（`changes_text` が真のときだけ）と、`VimState` の写しの `shared_ptr` 1 つ（置換を使う前は空）だけ。入力中の preview（決定 7）は段 2。10 万行の `:%s/a/b/g` は `nib_perf_probes` の probe に記録した（Debug ASan で 4.0 s・当たり無し 1.6 s。Release は測っていない。当たりの無い行の速い拒否は後続）。
13. **群を引けない当たりは置換全体を断る（V-1564 の M1）。** 群の道の探索（`VimPatternCapture`）は明示の積みで歩き（再帰しない）、`*` は 1 文字食べる枝と 0 回の枝を 1 段ずつ試すので、仕事は升の数（原子の数 + 1）×（一致の長さ + 1）に比例する（前の版は升ごとに残りの長さを歩いて 2 乗だった）。升の数が `vim_capture_cell_limit`（4 Mi・確保は升 1 つ 1 bit の印（0.5 MiB まで）と、先に確保する道の段（一致の長さ + 原子の数 + 1）× 16 バイト（`\(.*\),\(.*\)` の上限の一致で約 16 MiB）・`\(.*\),\(.*\)` なら約 1 Mi 字の一致まで）を超える当たりがあれば、群を空にせず、1 周目のうちに置換全体を `SubstituteFailure::too_complex` で断る。本文・レジスタ・マーク・変更の印は変えず、`E363: pattern uses more memory than 'maxmempattern'` を 1 行知らせ、失敗は再生を打ち切る。上限は試験だけが `VimEditorView.capture_limit`（`SubstituteRequest.capture_limit`）から小さな値を置く。`\1`〜`\9` を読まない置き換えは群を歩かないので上限に当たらない。群の歩きは当たり 1 つにつき 2 回（1 周目の大きさの勘定と 2 周目の本文）走る。上限の判定は本文を作る前に要り、1 周目の答えを当たりごとに覚えると確保が当たりの数に比例するので、もう 1 回歩く方を取る（仕事は升の数に比例のまま）。
14. **回数の端（V-1564 の M2・M3・Vim 9.1 の実測）。** 回数が 2147483647（INT_MAX）以上は E1510（`E1510: Value too large`・字面で断る・2147483646 は受ける）。回数 0 は `e` が無ければ E939（engine が決める・`e` は `&` で前のフラグからも来る）、`e` があれば範囲が空になって何もせず、続きの鍵は流れる。E939 と E35 の後は、打った置き換えとフラグだけを覚え、置換のパターン・直前の検索・広げた置き換え（`~`）は変えない（`:s/1/Q/` の後の `:s/a/X/ 0` の後の `:&` `:~` `n` は前のパターン・実測）。範囲の最後の行 + 回数 - 1 が INT_MAX を越える形（`:3s/a/X/g 2147483646`）は Vim の 32 ビットの行番号が溢れて範囲が空になるので、Nib も空の範囲として扱う（`e` が無ければ E486 で続きを打ち切り、`e` があれば黙って続く・`:6s/a/X/g 2147483642` はちょうど INT_MAX で置換する・実測・設計席の決め）。
16. **乗せ替え（まとめ枝 27）で足した形・Vim 9.1 の実測。** オペレータ待ちの `:s`（`d:s/a/b/` `c:` `y:`）は置換を先に流し、置換の前のキャレットから後のキャレットまでを exclusive な移動としてオペレータを閉じる（`jd:s/a/X/` は `  b a` を `b X` に・`jjd:%s/a/X/` は 3〜5 行目を消す）。engine は保留のオペレータを残したまま置換し（`rested`）、controller が `VimCommandMotion.origin` に置換の前のキャレットを渡す。置換が断られれば（E486 ほか）オペレータを捨てて続きを打ち切る。`c` のフラグは段 2a の追補 13 で断る。INSERT の `<C-o>:s/a/X/` の後は置換の着地（最初の非空白）で INSERT を始め直す（ADR 0182）。マクロの中の `:s` は打った鍵として録られ、`@a` `3@a` `5@a` が行ごとに置換を繰り返す（失敗は Ex の失敗と同じく再生を打ち切る）。変更の印は `changed`（`n` は印を立てない）。
15. **上限の判定は文書の改行の形で数える（V-1564 の軽い 3）。** 置き換えが入れる改行は CRLF の文書では 2 バイト（`SubstituteReplacement::expanded_bytes` の `newline_bytes`）。

## 追補（2026-11-14・#1007 段 2a・#1652・実装席 E3）

決定 6（`c`）を入れた。Vim 9.1 の実測は `--not-a-term` の Vim に `:normal!` の同じ鍵の列で答えを続けて流した 45 形（非 Ex モードの問いは plain_vgetc で 1 字ずつ読むので `:normal!` の鍵が答えになる・`feedkeys(…, 'tx')` の 4 形は undo の単位の数だけを見た）で、表は作業木の `out/1652-impl/vim-confirm.md`。読みは `ex_cmds.c` の `do_sub`（v9.1.0004）。fixture は作らず、契約 `--substitute-confirm` で守る。

1. **当たりの列は元の本文から 1 回で計画する。** core の `substitute_matches`（`substituted` と同じ当たり・同じ順を当たりごとの範囲と広げた置き換えで返す）を `vim_substituted` が呼び、問いの値 `SubstituteConfirmation`（列は共有・問うている番号・前に置いた当たりの増減・数・戻り先）を効果 `VimConfirmSubstitute` で返す。答えは application が engine の `vim_substitute_answered` へ `SubstituteAnswer`（`VimStepSource` の 1 値）で渡し、engine は純関数のまま。問いの状態は入力行の和型 `CommandInput` の 1 値 `SubstituteQuestion` で、プロンプトは `InputLinePrompt::substitute_confirm`。上限の判定は増やす当たりを全部置いた大きさで問う前に 1 回（どの答えの組もこれを超えない）。
2. **本文への反映は `y` のたび（逐次）。** 置く当たりは矩形と同じ `apply_block` で写し、置いた本文がすぐ見える。問いを開いたときの履歴と本文を `SubstituteQuestion` に持ち、終えるときに再生（`merge_replayed_edits`）と同じ `covering_edit` で 1 つの undo の単位に畳む（途中の `q` Esc と割り込みでも 1 単位・何も置かなければ単位を作らない）。新しい履歴の道は作っていない。**Vim との違い**: 打った答えの Vim は答えのたびに u_sync するので、行ごとに 1 単位になる（`feedkeys` の実測で 3 行なら 3 単位）。1 本の `:normal!` の中では 1 単位。Nib は決定 6 のとおり 1 単位。
