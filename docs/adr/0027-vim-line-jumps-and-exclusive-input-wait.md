# ADR 0027 — 指定行移動は既存motionへ接続し、次キー待ちは排他的に持つ

- 状態: 受理
- 日付: 2026-09-20
- Issue: #76
- 影響する規則: ARC-001 / ARC-004 / ARC-007 / CPP-002 / CPP-004 / CPP-006 / CPP-011 / CPP-012 / QLT-001 / QLT-008 / QLT-012 / QLT-013 / CNF-010

## 文脈

行内文字検索の次に、仕様FR-003・第5節にある `gg` / `G` と指定行移動を接続する。現在のengineは次の検索対象文字を待てるが、命令の接頭キーを待つ状態はない。
`G` は回数未指定と明示した `1` で到達先が異なる。既存 `VimState::count` と `VimPendingOperator::count` はoptionalで、この違いをすでに保持している。
本文の行索引、最初の非空白への移動、行範囲とoperator、VISUALの選択、カーソル追従は正典の経路を持つ。

## 決定

1. `awaiting_character` を `optional<VimInputWait>` に置き換える。`VimInputWait` は文字検索種別と `VimPrefix` の和型で、prefixは今回 `g` の一種だけ。検索待ちと接頭キー待ちを同時に持てないようにする。待ちと最後の検索記憶の寿命を分けるADR 0026の判断は維持する。
2. 待ちは通常の数字・命令解釈より先に受ける。和型は各選択肢への型付きの写し先を持つ `std::visit` で扱う。`fg` / `fG` の次文字を命令に取り違えない。UIの待ち状態や新しい文字配送を作らない。
3. `gg`の成立時と`G`を閉じたaction/motionへ写し、既存の `moved_by` / `motion_range` / `performed` を使う。NORMALは `VimMoveTo`、VISUALはanchorを保つ `VimSelect`。operatorは行単位の `lines_between` に流す。
4. motionが受ける回数は一箇所で解決する。明示回数の有無は既存optionalから読み、operatorとmotion双方が指定されれば既存の飽和する積を使う。`G`の未指定時だけ本文最終行を既定にし、指定値は本文内へ制限する。先頭・末尾・指定行の位置は行索引から求め、`j/k`を回数分繰り返さない。
5. 後方への行ジャンプを伴うyankでは、同じmotionが解決した到達列を一時的な `wanted_column` として `performed` へ渡す。既存 `yanked_caret` がその列を読み、直後のrestingで解消する。今回のdocument motion・yank・到達行が現在より前、の組だけが対象。前方・同一行は元の状態を使う。専用yank効果や範囲の第2の解釈は足さない。
6. g待ちの取消・未対応次キーは、そのキーを消費してwait/count/operatorを解除し、元のモード・選択・欲しい列・検索記憶を維持する。文字検索待ちでも同じ寿命の解除処理を使う。通常の命令として次キーを再解釈しない。

## 実測した境界

固定Vim 9.1で48件の入力を一度ずつ `measure` へ渡し、採用42件とした。各測定は既存の通常/+Esc比較を含む。g待ち後の続行は6件の別probeで `normal!` を分けて観測した。記録は `out/line-jump-oracle/`。Vimソースは読んでいない。

- 未指定 `gg` は1行目、未指定 `G` は最終行。明示回数はどちらも絶対行番号で、本文外は最終行へ制限する。`0`は回数ではなく行頭移動として独立する。
- `4GdG`は4〜6行、`4G1dG`と`4Gd1G`は1〜4行を削除する。`4G2d3G`と`4G2d3gg`は6行目を対象として4〜6行。明示有無はoperator側も含めて判断する。
- `d/c/y`は両端の行を含む行単位範囲。defaultのstartoflineでは到達行の最初の非空白、空白だけなら最後の空白、空行・空本文なら列1へ置く。UTF-8の列は既存のbyte/code point変換を使う。
- VISUALはanchorと種別を維持してcaretだけを動かし、範囲は既存 `vim_visual_range` から求める。
- 元が4行目の列3、先頭行の字下げが4文字の場合、`ygg`後は1行目の列5。前方への`yG`は元の行・列を保つ。これが決定5の根拠である。
- `$vg<Esc>`と`$vg<PageDown>`はVISUALを保ち、行末の欲しい列も保つ。`gZ` / `g3` / `gG`は第2キーを消費し、別に送った次の命令は有効。文字待ちの `fg` / `fG` は検索対象を意味する。
- 不正なg後続キーのあとで同じ `normal!` に続けたキーをVimが捨てる場合は、通常の対話入力の意味と混同しない。取消後の続行は分割probeを根拠に手書き単体テストする。
- CRLFは到達行と列を確認した。Vimの `getline` による報告本文はLFへ正規化されるため、元bytesの保持は既存TextBufferと単体/nativeで確認する。

nostartoflineの参考3件は設定対応が範囲外なので採用しない。同じnormal内の不正prefix後続2件と重複したVISUAL到達点1件も除外した。名前だけの3件の訂正は対応表を記録し、再測定していない。

## 限定検証

`line-jump-`の実測済み42件を既存 `fixture_row` / `header_from_rows` で整形し、main `2e222818230e591a58a28040ec67735ccb693366` の389件は既存parserと測定ソース比較で来歴を検証して逐語維持する。新規入力と実測時入力全体の一致も確認する。生成器は変更せず、確認のためだけに同じ実Vim測定を繰り返さない。将来の再生成は既存の `--only line-jump-` を使う。
新規fixture、途中の待ち状態と明示countの手書き境界、待ち表現が直接変わる既存文字検索、共通motion/operatorの代表だけを単体再生する。
変更targetのDebug build/tidy、core/applicationのsymbols、型・依存・生成物のconformanceを確認する。
nativeはg待ち/取消、長い本文の行ジャンプと追従、operatorの保存とundoに絞る。無関係な設定・テーマ・全oracle再測定・ファイル性能は対象外。

実装後の限定検証では、既存の `entered_visual` が `$v` の時点で行末希望列を落とす問題を検出し、Issue #77へ分離した。この関数はbase `2e22281`から不変。今回の取消後の縦移動は、VISUALに入ってから希望列を設定する `v$g<Esc>jj` で確認する。固定Vimの追加比較と検証側の修正はgate-proofs 5-qに記録した。

## 範囲外

他のg命令、ジャンプ履歴やマーク、全文検索、テキストオブジェクト、矩形選択、複数タブ、startofline設定、新UIは含めない。

## 却下

- g待ちと文字待ちを別々のboolean/optionalで足す: 同時に存在できない入力状態を表せてしまう。
- `G`の未指定を回数1へ早期に潰す: `G`と`1G`、`dG`と`1dG`の意味が失われる。
- UIがgを覚えて次の入力や行番号を処理する: 純粋なengineと状態所有が分岐する。
- 既存の行編集・選択・undoとは別にgg/G専用の効果を足す: 現在の効果と範囲で表せる。
