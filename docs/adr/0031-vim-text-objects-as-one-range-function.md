# ADR 0031 — テキストオブジェクトは 1 本の範囲関数で d c y と VISUAL に同じ範囲を渡す

- 状態: 受理（実測 364 ケースで決定 1〜8 を確かめ、食い違った 4 点を実測に合わせて直した。2026-09-22 に Issue #99 が残る 3 点を 208 ケース測って閉じ、決定 2・4 を直した＝下の「補足」）

- Issue: #93 / #99
- 影響する規則: ARC-001 / ARC-004 / ARC-007 / ARC-009 / CPP-002 / CPP-004 / CPP-006 / CPP-011 / CPP-012 / QLT-001 / QLT-008 / QLT-012 / QLT-013 / CNF-010

## 文脈

FR-003 の T2「テキストオブジェクト `iw aw i" a" i( a( i{ it`」を実装する。engine はオペレータの範囲を `VimMotionRange`（範囲＋文字/行の種類）1 本で決め（ADR 0015 の決定 2）、VISUAL の選択も同じ型で描画・Ctrl+C・`d x y c` に渡す（ADR 0018 の決定 4）。次キー待ちは排他的な `VimInputWait`（ADR 0027 / 0029）。`.` は鍵の列を再生する（ADR 0030）ので、テキストオブジェクトは鍵として記録されれば追加の記録なしに再生対象になる。

`i` / `a` は NORMAL では挿入命令で、オペレータ保留中と VISUAL でだけ「内側 / 周り」の接頭辞になる。固定 Vim 9.1 の help（`:help text-objects`）と実測を根拠にし、Vim ソースは読まない。実測で食い違ったら決定を直し、fixture を都合よく変えない。

実測は実装の前に固定 Vim 9.1 を 364 ケース起動した（`out/issue93-oracle/probe.py` 202 ＋ `probe2.py` 63 ＋ `probe3.py` 71 ＋ `probe4.py` 28）。ビープする命令の後ろの鍵は `:normal!` が捨てるので（Issue #87 の教訓）、どのケースも命令の切れ目で区切って測っている。決定 1・2・5・6・8 は提案のまま一致し、次の 4 点が食い違ったので**決定の側を直した**（fixture は測った値のまま）。

1. **VISUAL は行単位にならない**（決定 4）。行単位になる `i(` の範囲でも、VISUAL は文字単位のままで caret が最後の行の内容の終わり（NUL の桁）に載り、選択が改行まで届く。行単位 VISUAL から `Vi(` としても文字単位へ落ちる。
2. **括弧は中に居なくても前の塊を使う**（決定 7）。後ろに対応の開きが無ければ、前へ次の開きを探す。間に対応の取れていない閉じがあれば取消。向きは最初の 1 回で決まり、外へ向かい始めた走査は折り返さない（`d3i(` が 2 段しか無い所で取消になるのはこれ）。
3. **`i(` の 2 つの寄せは独立している**（決定 7）。開きが行の最後なら中は次の行から、閉じの前が空白だけなら中は前の行の終わりまで。**両方が起きたときだけ**行単位で、片方だけなら文字単位のまま寄る。寄せた結果が逆転したら中は空。
4. **`y` のキャレットは範囲の先頭の桁**（決定 3）。行単位の範囲でも `yy` のように桁を保たず、範囲の先頭（＝行頭）へ載る。

受理の時点で実測と合わせていない点が 2 つ残り、どちらも fixture を採っていなかった。(a) 回数が本文を越えた `d9iw` のキャレット、(b) 塊の外から数えた回数の入り方。**この 2 つと決定 4 の後ろ向きの選択は、Issue #99 が 208 ケースを測って閉じた**（下の「補足」）。

## 決定

**テキストオブジェクトの範囲は純関数 1 本が決め、オペレータの後ろでも VISUAL でも同じ範囲を使う。`i` / `a` は保留中と VISUAL だけの排他的な次キー待ちとして持つ。**

1. `VimInputWait` に `VimTextObjectScope`（`inner` / `around`）を足す。オペレータ保留中と VISUAL / 行単位 VISUAL の `i` / `a` でこの待ちに入り、次の鍵を閉じた `VimTextObject`（`word` / `big_word` / `double_quote` / `single_quote` / `backtick` / `paren` / `brace` / `bracket` / `angle`）に表で写す。`b` は `paren`、`B` は `brace`、閉じ括弧の鍵 `)` `}` `]` `>` もそれぞれ同じ表の行（`di)` が `di(` と同じであることは実測）。表に無い鍵と Esc は取消で、既存の待ちと同じくモード・選択・希望列・検索記憶を保つ。`it` / `at`・`is` / `as`・`ip` / `ap` はこの縦切りに入れない。
2. 範囲は新しい純関数 `vim_text_object_range(text, selection, request, count)` が閉じた和型 `VimTextObjectOutcome`（`VimTextObjectSpan` | `VimTextObjectCancel`・Issue #99 で `std::optional<VimMotionRange>` から変えた）で返す（`src/core/VimTextObjectRange.cpp`・1 ファイル 1 型・CPP-011）。`selection` は NORMAL では畳んだ位置、VISUAL では今の選択で、決定 4 の「広げる」意味を 1 本の関数の中に閉じる（引数 4 つの上限のため `scope` と種類は `VimTextObjectRequest` に畳む）。語の種類は既存の `VimCharacterRange` の表（ADR 0012 の決定 5）を `vim_character_class` として VimWordMotion から公開して使い、`iW` はその畳み方の違いだけにする。通常モードの `moved_caret` には触れない。範囲にならなければ `VimTextObjectCancel` で、そこに残る選択（＝取消のあとのキャレット）まで返す。
3. オペレータの後ろでは既存の `performed` に渡す。`adjusted_for_exclusive` は通さない（テキストオブジェクトは exclusive / inclusive の motion ではない）。`whole_lines_for_delete` の Vi 互換規則は d にだけ既存どおり通す（空行の `daw` と末尾の無い `da(` が行単位になるのは実測で確認）。`cw` の特例（`word_end_for_change`）は `ciw` に適用しない。`y` はキャレットを範囲の先頭へ戻す。**行単位の範囲でも桁を保たず範囲の先頭へ載る**ので、`performed` には希望列を空にした状態と範囲の先頭を渡す（既存の `yanked_caret` の行単位の枝は `yy` のための桁保持なので、そこは通さない）。
4. VISUAL では選択を範囲に置き換える（anchor = 範囲の先頭、caret = 末尾の文字）。**VISUAL は常に文字単位**で、行単位になる範囲（決定 7）でも caret を最後の行の内容の終わり（NUL の桁）に置いて選択を改行まで届かせる。行単位 VISUAL で使うと文字単位へ切り替わる。選択が 1 文字より大きいときは Vim と同じく「今の選択をもう 1 つぶん広げる」意味になり、語は caret 側へ 1 単位（`viwiw` は語と空白を交互）、引用符と括弧は「新しい範囲が今の選択より広くなければ回数を 1 つ増やす」で 1 段外側（`vi(i(` / `vi"i"`）にする。caret が選択の小さいほう（後ろ向きの選択）のときは、**種類ごとに両端の置き方が違う**（Issue #99 の補足 3）。両端まで範囲関数が決め、engine はそれを置くだけにする。
5. 回数は積（`2di(` = `d2i(`）。語は語と空白の塊を交互に数え、引用符は 2 で引用符を含む（空白は含まない）、括弧は段の数。
6. 引用符は行内だけを見る。`\` の直後の引用符は数えない（`quoteescape` の既定）。キャレットが引用符の上なら行頭から数えて対になる側を決め、行内の最初の引用より前なら最初の対を選ぶ。`a"` は後ろの空白を含み、無ければ前の空白を含む。`i"` は引用符の内側だけ。対が無ければ取消。
7. 括弧は入れ子を飛ばして後ろへ未対応の開きを探し、前へ対になる閉じを探す。複数行をまたぐ。**後ろに未対応の開きが無ければ、前へ次の開きを探してその塊を使う**（間に未対応の閉じが来たら取消）。回数の向きは最初の 1 回で決まり、外向きに始めた走査は前へ折り返さない。キャレットが開きの上なら 1 つ右から探し始める（＝自分が開きになる）。閉じの上なら後ろへの走査が自分の対を見つける。`i(` の中は 2 つの寄せを独立に受ける。開きが行の最後なら中は次の行の先頭から、閉じの前がその行で空白だけなら中は前の行の内容の終わりまで。**両方が起きたときだけ**行単位で、片方だけなら文字単位のまま寄り、逆転したら中は空。`a(` は括弧を含む文字単位（d のときだけ既存の Vi 互換規則で行単位になり得る）。
8. 記録・再生（ADR 0030）・UI・IME・描画・保存形式は変えない。VISUAL でのテキストオブジェクトも鍵として記録されるが、VISUAL の変更の `.` は #91 の範囲。

## 強制

- 網羅性: **active**（`VimTextObject` の switch・`VimInputWait` の visit・`VimTextObjectScope` の switch。選択肢が増えたらコンパイルが落ちる）
- 範囲の正しさ・取消・VISUAL の置換・再生: **active**（oracle fixture と `--vim-text-objects` の対象 unit・CNF-010 で生成物の一致）
- 期待値が本物の Vim の答えであること: **不能**（CI に Vim は無い。ADR 0012 のとおり）

## 結果

得られるもの: `diw` `ciw` `di"` `ci(` など T2 で最も使う編集が d/c/y と VISUAL と `.` の全部で使える。範囲の規則が 1 か所なので、`> < gu gU` を足すときも範囲は再利用できる。語の種類の表は `vim_character_class` 1 つに寄り、`iW` の「空白だけで切る」もその表の畳み方として同じ場所にある。
失うもの・残る穴: タグ・文・段落は後続。後ろ向きの選択で引用符の対を選ぶ規則は、行の引用符が奇数のときと対と対の隙間に caret があるときだけ合っていない（Issue #99 の補足 3 の末尾）。Vim の `iw` は `iskeyword` に従うが、いまの語の種類表は ADR 0012 の範囲（ハングル・絵文字は未測）。`quoteescape` と `matchpairs` の設定は既定固定。

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| テキストオブジェクトを `VimMotion` の列挙に足す | motion はキャレットから 1 方向へ伸びる範囲で exclusive / inclusive の補正を通る。テキストオブジェクトはキャレットを含む両側の範囲で補正が違う。表を分けたほうが分岐が閉じる |
| `i` / `a` を `VimPrefix` に足す | `VimPrefix` は NORMAL の接頭辞（g / r）。`i` / `a` は NORMAL では挿入なので、保留中 / VISUAL だけで意味を持つ別の待ちにする |
| VISUAL の拡張規則を最初から全部実装する | `viwiw` / `vi(i(` の拡張は実測で閉じてから。閉じなければ 1 文字のときだけに絞る |
| 範囲関数をオペレータ用と VISUAL 用に分ける | 同じ意味に 2 つの経路ができ、片方だけ直す事故が起きる（ARC-001） |

## 補足（2026-09-22・Issue #99）

受理のときに合わせていなかった (a)(b) と、決定 4 の後ろ向きの選択 (c) を、実装の前に固定 Vim 9.1 で **208 ケース**測って閉じた（`out/issue99-oracle/probe.py` 113 ＋ `probe2.py` 79 ＋ `probe3.py` 16）。どのケースも命令の切れ目で区切って測っている（Issue #87 の教訓）。**新しい ADR は書かず、決定 2・決定 4 を直してここに実測を残す。**

**1. (a) 回数が尽きたときのキャレットは「走査が止まった端」**。語は取消でもキャレットが動き、前向きの走査は本文の終わり（最後の行の内容の終わり。NORMAL ではその 1 つ手前の文字に寄る）、後ろ向きの走査は本文の先頭に残る。`d9iw` / `d9aw` / `y9iw` / `c9iw` はどれも同じ所に着き、複数行でも空行でも末尾が空白でも「本文の終わり」で一致した（走査が尽きるのはそこだけだから）。VISUAL では**作りかけの選択がそのまま残る**（`v9iw` は anchor が語の先頭へ動いて選択が行末まで届き、前向きの選択は anchor を保ち、後ろ向きの選択は anchor を保って caret が本文の先頭へ動く）。行単位 VISUAL は行単位のまま。**引用符と括弧の取消はキャレットも選択も動かさない**（`d9i(` / `d3i(` / 括弧が 1 つも無い `d9i(`）。引用符は回数が 2 以上なら常に引用符を含む形になるので、そもそも尽きない。

この 2 つを 1 つの形で持つため、返り値を `std::optional<VimMotionRange>` から閉じた和型 `VimTextObjectOutcome = std::variant<VimTextObjectSpan, VimTextObjectCancel>` に変えた。`VimTextObjectCancel` は取消のあとに残る `Selection` を持ち、engine は NORMAL では `VimMoveTo`、VISUAL では `VimSelect` に写し、値が変わっていなければ `VimNoEffect` にする（どちらも本文を変えないので `.` の記録はそのまま捨てられる・ADR 0030 の決定 3）。

**2. (b) 塊の外からの回数は実装が既に正しかった**。`x ((a)) y` の `y2i(` は内側の `a`、`y3i(` は取消でキャレットは動かない。`x (a) (b) y` の `y2i(` は取消（隣の塊へは渡らない）、`x (a (b (c) d) e) y` は `yi(` / `y2i(` / `y3i(` が 1 段ずつ内へ入り `y4i(` で取消、内側から始めた `y4i(` は外向きに尽きて取消。開きの上・行をまたぐ塊・`a(`・`{` も同じ。**決定 7 の「向きは最初の 1 回で決まり、折り返さない」がそのまま外向きにも内向きにも効く**ので、決定は直さず fixture だけ足した。

**3. (c) 後ろ向きの選択（caret < anchor）は種類ごとに置き方が違う**。決定 4 の「伸ばさずに取り直す」を次の 3 つに置き換えた。

- **語は anchor を動かさず、caret だけが 1 単位ずつ手前へ**進む（前向きの伸ばしの鏡像）。1 単位は Vim の decl のあと、前向きと同じ条件 `(caret の種類が空白) == (a か)` で 2 つに分かれ、真なら同じ種類の連なりの先頭へ（`bck_word` の stop = TRUE）、偽なら手前の語の末尾の 1 つ後ろへ（`bckend_word` ＋ incl）戻る。`9l vhh` から `iw` を重ねると 7 → 6 → 1 桁と語と空白を交互にさかのぼり、`aw` は 6 → 2 → 本文の先頭で取消になる。行もまたぐ（またいだ先は前の行の最後の文字）。空行と `iW` も同じ表で動く。**選択の anchor は最後まで動かないので、範囲と選択が一致しないことがある**（`5l v h iw` は語の範囲が 1〜5 桁でも選択は 1〜6 桁）。
- **括弧は必ず前向きに置き直す**（anchor = 範囲の先頭・caret = 末尾）。後ろ向きの選択から `i{` を使うと選択は前向きになり、続く `l` が右へ伸びる。行をまたぐ塊でも同じで、caret は最後の行の内容の終わりに載る。
- **引用符は今の選択の向きを保つ**（後ろ向きなら caret が範囲の先頭に残る）。`vhh i"` のあとの `l` は左端を右へ動かす。「選択がちょうど引用符の内側と同じなら引用符ごと取る」枝は前向きと同じに効く。

残る穴: 後ろ向きの選択で**どの対を選ぶか**は、行の引用符が奇数のときと、対と対の隙間に caret があるときだけ Vim と違う（`a "bb" c "dd" e` の 7 桁から `vh i"` は Vim が手前の `bb` を取り、本実装は隙間 ` c ` を取る）。前向き・畳んだ位置・対の中に居る後ろ向きは一致しているので、この 1 点だけを穴として残し fixture を採らない（`out/issue99-oracle/probe3.txt`）。

**fixture**: 候補 35 件を「区切った形」と「1 回の `:normal!` の形」の両方で測り、**食い違いは 0 件**で 35 件を `text-object-residual-` の接頭辞で採った（`out/issue99-oracle/add-fixtures.py`）。VISUAL の取消はビープが後続の鍵を捨てるので 1 回の `:normal!` に乗らず、`--vim-text-objects` の対象 unit の契約 7 件で engine に固定している。
