## 文脈

hide は 2026-11-23 の朝に 3 つの飾りを頼み（#1975 インデントガイドとレインボー・#1976 ブラケットペアガイド・#1977 不可視文字）、同じ日に見本を見て次を決めた（3 つの Issue のコメント）。

- 3 つとも既定はオフ。表示・非表示は `:set` と設定の画面で切り替える。
- インデントガイド: 基本は虹 4 色＋キャレットのいる段を強める。色の数と単色 / 虹は設定の画面で変えられる。字下げの段の幅は、開いたときに中身から推し当てる（2 / 4 / 8・Tab）。当たらなければ設定の値。折り返した行では最初の画面行にだけ引く。
- 括弧: ペアガイドと色分けは別々のスイッチ。色はインデントガイドの虹と同じ並び。「インデントの線とかぶらない工夫をしたい」。
- 不可視文字: 種類ごとのスイッチ（改行・Tab・空白・全角空白）。空白は なし / 行末だけ / 全部。印は見本の A（`·` `→` `↵`）で、改行と Tab の印は字体の字ではなく renderer が線で描く。CRLF は `↵` の前に小さな `←`。#1011（行末の空白の強調）は「空白: 行末だけ」に取り込む（`:set stripws` は #1011 に残る）。`:set list` / `nolist` を全体のオン・オフに当て、`listchars` は当てない。

現物（下調べ §1）: 本文の行は `EditorController::visible_lines` が `LineView`（`text` `display` `colors` `diagnostics` `bracket` `labels` `window` `left` `screen_row(s)`）にし、renderer の `draw_plain_line` が「検索の面 → 選択 → 本文の字（構文の色）→ 置き換え → 診断 → 枠 → キャレット」の順に描く。行の字下げの桁・行ごとの改行の形・括弧の深さはどこにも持っていない。Nib の字下げの幅は `vim_shift_width = 8` の固定（`src/core/VirtualColumn.hpp`）で、4 桁・2 桁のコードでは 8 桁ごとのガイドは役に立たない。折り返しの 2 行目以降は字下げしない（`breakindent` に当たる物が無い）。`settings.v5` は 1.1.0 で閉じ、`settings.v6` はまだ公開していない（ADR 0192 の決定 1）。

## 決定

### 共用する形

1. **3 つとも、application が `LineView` に桁の区間の欄を足し、renderer は保持した layout の外に重ねて描く。** `BodyTextLayouts` の鍵（表示の文字列・幅・書式）を変えない。印の字（`·` `→` `↵` `←`）を本文の layout に混ぜない（混ぜると表示の文字列が変わり、桁の対応・キャレット・折り返しが全部動く）。線と印は renderer が geometry（矩形・線分・path）で描き、字体に依らない。本文の色の付け方（字形 run を切る道・ADR 0156 の決定 11 / 0073）は括弧の色分けにだけ使い、`SetDrawingEffect` を使わない。欄は段ごとに次のとおり（名前は実装の段で決めてよいが、欄は 1 つの飾りに 1 つ）:
   - インデントガイド: `IndentGuides{ cells; step; levels; active }`（行の字下げの仮想桁・段の幅の桁・引く段の数・強める段。`step` は renderer が段の x を出すため・2026-11-23 の追補）。
   - 括弧の色分け: `std::vector<BracketMark{ Column at; std::uint8_t depth }>`（文字列とコメントの区間の外の括弧）。
   - ペアガイド: frame に 1 つの `std::optional<BracketGuide>`（キャレットを囲む最も内側の対の、開きの行・閉じの行・閉じの桁・線の桁）。
   - 不可視文字: `std::vector<InvisibleSpan{ Column begin; Column end; InvisibleKind kind }>`（`kind` は閉じた enum: `space` `trailing_space` `tab` `ideographic_space`）と `std::optional<LineBreakMark>`（`lf` `crlf`）。
2. **描く順は 1 か所。** `draw_plain_line` の中の 2 本の関数（下調べの案の `draw_decorations_under` と `draw_decorations_over`）だけが順を知る: 現在行の面（今のまま `draw_line`）→ 検索の面 → 選択 → **下の飾り（インデントガイド → ペアガイド）** → 本文の字（括弧の色を含む・置き換えの字は括弧より上）→ 置き換え → **上の飾り（不可視文字の印）** → 診断の波線 → 当たりと matchparen の枠 → キャレット → キャレットの動きの層（ADR 0192・`draw_body_area` の後のまま）。ガイドは選択と検索の面の上に見え、キャレットと枠はガイドと印より上。格子の行（後の段・決定 15）は `GridRowPainter` に同じ順を写す。
3. **オン・オフは `features=` の名前の列（設定の版を上げない）。** ADR 0170 の 2026-11-18 の追補 1 の形で、`feature_costs` に 4 行を足す（どれも `FeatureStorage::listed`・既定オフ・測るまで費用 0 と段の印なし・追補 3）。名前は `indentguides` `bracketpairs` `bracketcolors` `list`。`:set <名前>` `no<名前>` `<名前>?` と Ctrl+P の `:` の候補は表から作る（ADR 0170 の決定 4。表から作る工程がまだなら、その段の PR が表の行から作る形で足し、名前の別表を書かない）。1.1.0 の codec は知らない名前を往復で残すので、1.1.0 で開いても消えない。`list` は Vim の `:set list` / `nolist` と同じ綴りで、Vim のモードでも通常モードでも同じ値（窓全体の設定・文書の値ではない）。`:set listchars=…` は受けない（Nib の知らない option と同じ失敗）。
4. **形の値は `settings.v6` の鍵。** v6 は未公開なので鍵を足してよい（ADR 0192 の決定 1。v6 を書く最初の公開版で鍵の集合を閉じる）。並びは `caret_motion_time` の後ろ・`lsp.<language>.command` の前で、下の表の順。後から足す鍵の形（ADR 0170 の追補）に従い、無い v6 は既定を補って読み、有れば厳密に読み（範囲の外・形の違いは拒否）、書くときは必ず書く。v5 以前に在れば未知の鍵として拒否する。値の読みは core の 1 本ずつ（`*_of`）で Ex と共用する。設定の画面は「表示」の節（`SettingsSection::display`）に、スイッチ（`EditorFeature` の 4 行）と、それぞれの下に形の行（`SettingsValue` に値を足す・段の上下か選択）を置く。画面の文は `ui_text` の表（CNF-016）。

| --- | --- | --- | --- |
| インデントガイドの表示 | `features=indentguides` | `indentguides` `noindentguides` `indentguides?` | 既定オフ |
| 単色 / 虹 | v6 `indent_guide_style` | `indentguidestyle=rainbow\|plain` | `rainbow` |
| 虹の色の数 | v6 `indent_guide_colors` | `indentguidecolors=N` | 3〜6・既定 4 |
| キャレットのいる段を強める | v6 `indent_guide_active` | `indentguideactive` `noindentguideactive` | `on` |
| 段の幅（推し当てが外れたとき） | v6 `indent_guide_width` | `indentguidewidth=2\|4\|8` | 4 |
| ペアガイドの表示 | `features=bracketpairs` | `bracketpairs` `nobracketpairs` | 既定オフ |

| 不可視文字の全体 | `features=list` | `list` `nolist` `list?` | 既定オフ |

   種類のスイッチは全体（`list`）がオンのときだけ効く。全体がオフのとき種類の値は読むだけで描かない（種類を全部オフにして全体をオンにした状態は「何も出ない」で、拒否しない）。

5. **虹の色は core の 1 本の純関数。** `rainbow_colors(const SyntaxPalette &, const Palette &, std::size_t wanted) -> RainbowColors`（最大 6 色の配列と取れた数）。候補は `SyntaxPalette` の役割の色を `keyword` `function` `string` `type` `number` `operators` `constant` `warning` `error` の順に見て、互いに ΔE76 ≥ 20・本文の色（`foreground`）から ≥ 15 のものを貪欲に取る（下調べ §5 の数え: 4 色取れるのは 125 テーマ中 117、5 色 95、6 色 54）。インデントガイドの段 i と括弧の深さ i は同じ表の `i mod 取れた数` の色を使う（施主の「同じ並び」）。**見分けられる色が `wanted` より少ないテーマは、巡回の長さを取れた数に縮める**（4 色を頼んで 3 色なら 3 色で回る。隣の段が同じ色にならないのは 2 色以上のとき）。1 色しか取れないテーマ（`quiet`）は単色と同じ見え方になる。足りない 8 テーマ（`quiet` `industry` `novum` `winter_sentinel` `crimson_mercenary` `last_outlaw` `noir_vigil` `folded_city`）は試験の表に名指しし、取れた数を固定する。線に使う色は、強めない段は役割の色を背景へ `mix`（ADR 0017 の決定 4）で薄めた色、強める段は役割の色そのもの（見本の不透明度 0.45 / 1.0 に当たる割合は段 1 の /design の試用で決め、表の 1 か所に置く）。単色は `Palette::panel_border`、強める段は `Palette::muted`。不可視文字の印は `muted`、行末の空白と全角空白の印は強めの色（見本の `accent` 寄り・#1011 の「見つけたい空白」）。色の対応は core の関数だけが持ち、ui に色のリテラルを書かない（ADR 0008 決定 8）。トークンは足さない。
6. **速さ。** オフのとき、frame を作る道と renderer が足すのは機能ごとの真偽の読み 1 つだけで、欄を作らない（ADR 0192 の決定 7 と同じ形）。オンのときの上限: 見えている行だけを歩く。行の外を見るのは、インデントガイドの空の行の続き（前後 1 画面で打ち切る）・ペアガイドの囲む対の探し（matchparen と同じ窓＝見えている範囲の前後 1 画面・ADR 0164 の決定 2）・括弧の深さの遡り（構文の色の遡りと同じ 1 回の歩きに相乗りし、新しい遡りを足さない・決定 11）の 3 つだけ。オンの費用は別の基準で扱う（D60 と同じ考え・速さのゲートの既定オフの 8 本には混ぜない）。各段は任意のベンチを 1 本ずつ足し（`indentguides-single-key` `list-single-key` `bracketcolors-single-key` `bracketpairs-single-key`・`OPTIONAL_BENCHES` に足す・CNF-015）、測った数字を `docs/quality/feature-costs.md` と表の行に書いた段だけが段の印を持つ（ADR 0170 の追補 3）。8 本の基準のベンチで「悪化なし」を各段の PR に書く（QLT-014）。

### インデントガイド（段 1・#1975）

7. **字下げの数えと段の幅。** 行の字下げは core の 1 本 `indent_cells(std::string_view line)`（空白は 1 桁・Tab は `vim_tab_stop` の止まりまで・全角空白 U+3000 は字下げに入れない・`VimStepInsert.cpp` の `get_indent_str` と同じ規則をここへ寄せる）。段の数は `indent_cells / 段の幅`。**段の幅は文書の値**で、開いたときに core の純関数 `guessed_indent_unit(std::string_view head) -> std::optional<IndentUnit>`（`IndentUnit` は閉じた enum: `two` `four` `eight` `tab`）が本文の先頭の最大 1,000 行・64 KiB（窓の端は `whole_code_points`）から推し当てる: 空白で始まる空でない隣り合う行の字下げの差が 2 / 4 / 8 のどれかなら 1 票、Tab で始まる行は `tab` に 1 票。`tab` の票が空白の票より多ければ `tab`（段の幅は `vim_tab_stop`）、そうでなければ最も票の多い差（同数は小さい方）、票が 3 未満なら値なし。値なしのとき・無題の文書は設定の `indent_guide_width` を使う。置き場は `Document` の値（`DisplayForm` と同じく文書ごと・設定にも一覧 `session.v2` にも入れない）。推し当てるのは開く道の 1 か所（`open_document` と、`reach_tab` がまだ読んでいない文書を読むとき。同じ読みの道を通る。自動退避から名前のあるファイルを戻すときも同じ入口の関数を呼ぶ・名前の無い退避は無題の文書と同じく設定の値・2026-11-23 の追補）で、機能のオン・オフに依らず毎回行う（64 KiB の 1 回の歩きで、後からオンにしても開いている文書に値がある）。編集・保存では推し当て直さない。票の数え方の細部（差 6 の扱い・同数の順）は段 1 の試験の表で決め、この決定の形（開くとき 1 回・先頭だけ・当たらなければ設定）は変えない。
8. **`vim_shift_width = 8` とは別の値にする。** ガイドの段の幅は表示だけの値で、`>>` `<<`・autoindent・Vim の oracle が使う `vim_shift_width`（8 固定）は変えない。shiftwidth を可変にする（`:set sw=` と推し当てを `>>` にも効かせる）のは engine と oracle の fixture に響く別の仕事で、別 Issue の候補にする。
9. **空の行・強める段・折り返し。** 空の行（空白だけの行も）は、上の空でない行と下の空でない行の字下げの大きい方で続ける（見本の形）。見えている範囲の端の空の行は、範囲の外の空でない行を前後 1 画面まで探し、届かなければ届いた側の値で続ける。キャレットのいる段を強める（`indent_guide_active=on`）のは、キャレットの行の字下げの段の 1 つ外側の段の線で、キャレットの行から上下にその段より深い行が続く区間（見えている行の中で打ち切る）だけ。強めるのは操作中の枠だけ。線は 1 DIP、強める段は 2 DIP（見本）。線は行ごとの矩形にする（同じ段の続きを 1 本にまとめない・2026-11-23 の追補 1）。**折り返した行では最初の画面行の高さにだけ引く**（施主の決め。2 行目以降は字が x=0 から並ぶので線を引かない）。x は `area.left + line.left + 仮想桁 × 空白の幅`。行頭の空白と Tab だけなら x は仮想桁と空白の幅で決まる（Tab の止まりが空白の幅の倍数・`SetIncrementalTabStop`）ので hit test を回さない。空白の幅は `BodyTextLayouts` が書式の鍵ごとに 1 回測って持つ口を足して読む（今は `set_spacing` の中だけ）。比例の字体でも合うことを段 1 の窓の試験で確かめる。

### 不可視文字（段 2・#1977・#1011 の行末の空白）

10. **区間と印。** application が見えている行の `text` を 1 回歩いて `InvisibleSpan` を作る（行の外を見ない）。種類は `list_*` の値で選ぶ: 空白は `trail`（行末の空白の列だけ・`trailing_space`）か `all`（全部・行末の分は `trailing_space`）、Tab、全角空白（U+3000）。改行の形は `text` に無いので、行の終わりの 1〜2 バイトを `text_range` で読み `lf` / `crlf` を置く（行ごとに正しい印・混在の文書でも合う）。改行の無い最後の行は印なし。Vim のモードの最後の改行を隠す旗（`hidden_line_break`・ADR 0188）が立っていれば、最後の行の印も描かない。lone CR は既に `^M` の置き換えとして見えているので印を足さない。印の形（施主の決めた A）: 空白は字の中央の小さな点（`·`）、Tab は Tab の幅いっぱいの横線と右端の矢じり（`→`）、改行は行末の後ろに折れ矢印（`↵`）、CRLF はその前に小さな左向きの矢印（`←`）、全角空白は升の内側の四角の輪郭。どれも renderer が線と path で描き、太さと高さは行の高さから決める（字体に依らない）。**印の x は保持した字形 run の cluster と advance から引く**（構文の色の `glyph_pieces` と同じ写し・hit test を回さない）。保持できない行（`glyphs_ready` でない）だけ区間ごとの `HitTestTextRange` に落とす。改行の印は行の終わりの x（折り返した行は最後の画面行）を 1 回求める。Tab の cluster が Tab の幅の advance を持つかは段 2 の最初に確かめ、持たなければ次の字の位置との差で引く（どちらにしても 0 字形を `DrawGlyphRun` へ渡さない・ADR 0073）。選択の行末の改行の面（6 DIP・`newline_mark_dips`）と改行の印は、面の上に印を描いて両立させる。

### 括弧の色分けとペアガイド（段 3・#1976）

11. **色分けの深さ。** 括弧の対は matchparen と同じ `()` `[]` `{}` の表 1 つ（`bracket_of` / `VimBracketPair`）。文字列とコメントの区間の中は数えない（matchparen の役割の表と同じ・ADR 0164 の決定 3）。区間の無い文書（plain・`:syntax off`）は全部数える（matchparen と同じ規則で 1 本にする）。見えている最初の行の行頭の深さは、構文の色の遡り（ADR 0156 の決定 8・`max(first − 200, 1)` から）と同じ 1 回の歩きで数え、覚え（決定 9 の `SyntaxStateCache`）に深さを 1 欄足して続きを使う（遡りを 2 本にしない）。遡りで除く区間を作るために遡りの行を `lex_line` に通す費用（下調べの推測で約 1.4 倍）は、色分けがオンのときだけ払う。遡りの外で開いた括弧は色がずれる（限界）。閉じが多くて負になる深さは 0 に留める。深さ 0 の括弧も虹の 1 色目で塗る（VS Code の形）。描画は `colors` と同じ字形 run を切る道（ADR 0156 の決定 11 / 12）で、`ColoredRun` の列を作る renderer の 1 か所が構文の区間に括弧の 1 字の区間を重ねる（括弧の色は構文の色より上・置き換えより下）。段 3 は先に `bracketcolors-single-key`（括弧の多い C++ の文書）で run と `SetColor` の増分を測ってから描画を入れる（Issue #1976 の「先に費用を測る」）。
12. **ペアガイド。** キャレットを囲む最も内側の対で、開きと閉じが別の行にあるものだけ（同じ行なら引かない）。探しは `matched_bracket` に「囲む開きを探す」1 本を足す形で、窓（見えている範囲の前後 1 画面）と除く区間を引数に取る（ADR 0164 の決定 2 の関数を広げ、2 本にしない・`i(` の text object の遡りとは別のまま）。窓の外なら出さない。線は見本の形: **開きの括弧のある行の字下げの桁**に、開きの行と閉じの行の間の行を縦に通し、閉じの行ではその桁から閉じの括弧の桁まで横線を引く（閉じの桁がその桁より右のとき）。太さ 2 DIP。色は色分けがオンなら対の深さの虹の色、オフなら `accent`（オフのときは深さを数えない）。折り返した行は、インデントガイドと同じく各行の最初の画面行にだけ引く。操作中の枠だけ（キャレットに依る）。
13. **ペアガイドがインデントガイドと同じ桁を通る区間では、インデントガイドを引かずにペアガイドだけを引く（施主の確かめ待ち）。** 施主の「インデントの線とかぶらない工夫をしたい」への設計席の案で、見本の「同じ桁のインデントガイドに代わる」で見せた。線の桁が決定 12 で開きの行の字下げの桁なので、間の行のその桁には必ずインデントガイドがあり、2 本が重なる。間の行のその段のインデントガイドを frame を作る所で外す（renderer は外された欄を描くだけで、重なりの判断を持たない）。確かめが「両方引く」か別の形なら、この決定だけを追補で直す。

### 場所ごとの扱い

14. **split・プレビュー・IME・選択と検索・横の送り。** split のもう 1 つの枠も `visible_lines` を通るので、インデントガイド・括弧の色分け・不可視文字は両枠に出る。強める段とペアガイドは操作中の枠だけ（matchparen と同じ）。Markdown のプレビューと全面のプレビューは本文の行ではないので出さない。IME の差し込み行（`draw_composed_line`）には 3 つとも描かない（変換中は字の位置が変わり続け、変換は短い。構文の色の区間も付けない形と同じ・ADR 0156 の決定 8）。選択・検索・現在行の面の上にガイドが見え、印は字の上（決定 2）。横の送りは `line.left` を足し、画面の左の外は切り抜きで消える。
15. **巨大な行と格子は後の段。** 巨大な行の窓（`window.active`）と格子の表示（`DisplayForm::grid`）には、段 1〜3 では 3 つとも付けない（構文の色と同じ限界）。格子への写し（`GridRowView` に Tab の升の欄・最初の画面行 `row == 0` にだけガイド・升の掛け算で x）は 3 つまとめて別の段（別 Issue）にする。

## 失うもの

- ガイドの段の幅と `>>` の幅が違う文書がある（4 桁の字下げの文書でガイドは 4 桁ごと、`>>` は 8 桁動く）。shiftwidth を可変にするまで残る（決定 8）。
- 段の幅は開いたときの先頭 1,000 行だけで決まり、編集では変わらない。先頭と違う字下げの部分がある文書では、その部分のガイドが合わない。設定の値を変えても、推し当てが当たった文書には効かない。
- 推し当ては機能のオン・オフに依らず開くたびに 64 KiB まで歩く。開く道の費用が少し増える（段 1 の PR で `open-*` の基準のベンチの「悪化なし」を示す）。
- 折り返した行の 2 行目以降にはガイドもペアガイドも無く、長い行の所で線が途切れて見える（`breakindent` に当たる物を作る別件まで）。
- 括弧の深さは 200 行の遡りの外で開いた括弧を知らず、色がずれる。区間の無い文書では文字列の中の括弧も数える。
- IME の変換中はその行の飾りが消える。巨大な行と格子には段 1〜3 では出ない。
- `:set listchars` を書く Vim の利用者の設定は効かない（知らない option の失敗になる）。NBSP など 4 種類の外の不可視文字は見せない。

## 採らなかった案

- **印の字（`·` `→` `↵`）を本文の layout に混ぜる。** 表示の文字列が変わり、`BodyTextLayouts` の鍵・桁の対応・キャレット・折り返しが変わる。字体によって印の高さと幅もそろわない（施主の決めの「線で描く」）。
- **`listchars` をそのまま実装する。** Vim は `list` があって `tab:` が無いと Tab を `^I` の 2 桁で見せ、キャレットの置き方と折り返しが変わる。Nib は表示だけの設定で桁と本文を変えない。種類の名前と字の指定を Vim の書式で受けると、受けた字を描かない（線で描く）ことと食い違う。施主の決めは「`listchars` は当てない」。
- **6 色の虹を既定にする。** 見分けられる 6 色が取れるのは 125 テーマ中 54 だけ。施主の決めは 4 色（117 テーマ）で、5・6 色は設定で選べる（取れない色は巡回を縮める・決定 5）。
- **段の幅を `vim_shift_width` の 8 のままにする。** 4 桁・2 桁のコードで役に立たない。**shiftwidth ごと可変にする**のは engine・oracle・`NIB_FIXED_SETTINGS` に響き、範囲が大きいので別 Issue の候補（決定 8）。
- **推し当てをオンのときだけ・最初にガイドを描く frame で行う。** frame を作る所で文書の値を書くことになり、ほかのタブ（不変の束・ADR 0056）の値は切り替えまで決まらない。開く道の 1 か所で毎回行う方が経路が 1 本で済む（決定 7）。
- **括弧の深さを見えている範囲の最小の深さを 0 に寄せて決める。** スクロールのたびに色が変わる。遡りを 1 画面で打ち切る案も同じく色が揺れるので、構文の色の遡りに相乗りする（決定 11）。
- **ペアガイドの縦線を開きの括弧の桁に引く（下調べ §3.1 の案）。** 見本（施主が見た形）は開きの行の字下げの桁で、VS Code と同じ。開きの括弧の桁は行の中ほどにあることが多く、間の行の字にかぶる。
- **空の行を上下の小さい方で続ける（下調べ §2.1 の VS Code と indent-blankline の理解）。** 見本（施主が見た形）は大きい方で、ブロックの中の空の行で線が途切れない。
- **#1011 の行末の空白の強調を既定オンの別の機能として残す。** 同じ区間を 2 つの経路で作ることになる（ARC-012）。施主の決めで「空白: 行末だけ」に取り込み、既定はオフ。
- **3 つのオン・オフを `settings.v6` の鍵にする。** `features=` の名前で持てて、1.1.0 も往復で残す（ADR 0170 の追補 1）。鍵にするのは形の値だけ。

## 追補（2026-11-23・段 1 の PR #1992 のレビュー）

1. **線は行ごとの矩形（決定 9 の「まとめて 1 本の縦長の矩形」を改める）。** 行は `draw_line` が 1 行ずつ、現在行の面 → 検索 → 選択 → 下の飾り → 字 → … → キャレットと描く（決定 2）。行 i で後ろの行まで伸ばした縦長の矩形を描くと、行 i+1 の現在行の面（不透明）・選択・検索の面がその上に重なり、決定 2 の「ガイドは面の上に見える」が崩れる。行の終わりにまとめて描くと前の行のキャレットより上に来る。順を守るため行ごとの矩形にする。矩形の数は「見えている行 × その行の見えている段」で、桁の向きは 3 で抑える。まとめるなら `draw_pane` を面の段と飾りの段に分ける別の形になる（段 1 では採らない）。
2. **`IndentGuides` に段の幅 `step` を持つ（決定 1）。** renderer は段 i の x を `i × step × 空白の幅` で出すので、文書の推し当てと設定から決めた段の幅を行の欄に載せる（renderer は文書の値も設定の幅も読まない）。
3. **描く段は本文の欄の左右の端の間だけ（決定 6 の「見えている行だけ」に桁の向きを足す）。** 字下げの深い行（巨大な行のしきい値の手前の 16,000 桁など）でも、renderer は欄の左端より左の段を段の間隔の割り算で飛ばし、右端から先の段を回さない。段ごとの `SetColor` と `FillRectangle` は見えている幅の段の数で抑えられる。
4. **線の色の材料は renderer の覚え 1 つ。** 単色 / 虹・色の数・`rainbow_colors` が読む本文の色（`foreground` と 9 つの役割）・線の 3 色（`panel_border` `muted` `background`）が前の frame と同じなら前の `IndentGuidePaint` を使い、どれかが変われば core の `indent_guide_paint` で作り直す。オフの frame は真偽 1 つで描かない印だけを立てる（決定 6）。根の Newton は値が減らなくなった所で打ち切る（結果の色は 125 テーマで変わらないことを試験の表で縛る）。
5. **行頭の字下げの窓に上限（`indent_guess_bytes`・64 KiB）。** 空白だけの巨大な行で行の全体を写さない。上限まで空白と Tab が続く行は、上限までの桁を字下げとして答える（空の行として扱わない）。
6. **決定 2 の順の強制を狭める。** 描く順（選択・検索・現在行の面の上にガイド・字とキャレットの下）は `draw_plain_line` の 1 か所のコードが持ち、窓の試験は renderer の全体を通して面とガイドの重なりを画素で見ない（窓の試験には frame から renderer を通して描く道具が無い）。窓の試験が縛るのは、行の位置の組み立て（`indent_guide_row`: 横の送りを含む x の原点・最初の画面行の上端と高さ・欄の端・太さ）・描く段の区間・線の画素・色の材料の覚え（オフで描かない）まで。
