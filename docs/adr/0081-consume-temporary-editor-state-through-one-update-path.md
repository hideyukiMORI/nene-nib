# ADR 0081 — 一時的なエディタ状態は同じ更新経路へ所有権を渡す

- 状態: 受理
- 日付: 2026-10-09
- Issue: #321
- 影響する規則: ARC-001 / ARC-004 / ARC-005 / CPP-003 / CPP-005 / CPP-012 / CPP-016 / QLT-001 / QLT-012 / QLT-014

## 文脈

通常の一打鍵は `begin_intent` で状態全体を4回、`replace` と文書の保存位置とキャレット追従でさらに3回複製する。ほとんどの打鍵では、一意図だけの欄はすでに空で、画面の先頭行も動かない。
一時値に続く `with_*` も const のメンバーを呼んで再複製している。値として元の状態を保つ契約は必要だが、呼び手が所有権を渡した一時値まで複製する必要はない。

## 決定

1. **値の意味と所有者は変えない。** `EditorController` が状態を持ち、意図の入口と既存の編集操作だけが次の状態を決める。lvalue の `with_*` は元の値を不変に保つ。共有可変の状態や公開setterは作らない。
2. **実際に連鎖で使う6つに限って消費する口を設ける。** `with_edit` / `with_document` / `with_scroll` / `with_selection` / `with_history` / `with_vim` の const& 版は、状態を一度複製して同じ名前の && 版へ委譲する。&& 版だけが受け取った値を欄へ反映し、所有権を次の `EditorState` へ返す。処理を二重に実装しない。ほかの `with_*` は今回のために一括変更しない。
3. **借用と消費を同じ引数に混ぜない。** `Selection` / `ScrollState` の小さい値は値引数にする。本文・履歴・Vim状態・文書も既存どおり値を受ける。`state_` を機械的に std::move する置換は行わず、live state の更新はlvalueから一度複製する。&& の契約は所有権を渡した後の値を再び読むことを要求しない。例外が投げられた場合に編集途中のlive stateを失う範囲を広げない。
4. **一意図だけの4欄はまとめて戻す。** `with_intent_cleared()` は `last_failure` / `closing` / `close_request` / `operation_request` を一度の複製で戻す。controller の `begin_intent` は4欄がすでに空/falseならこの置換を行わない。`unreached_tabs_` のリセット、`keeps_message` に応じた通知の寿命、タブの歩きと裏の合図の扱いは変えない。
5. **編集と文書の保存位置を一度に反映する。** `with_edit` は本文・選択・履歴・文書の4引数を受ける。`replace` は旧履歴位置と `after_edit_at` の結果を元の状態から計算してから、この口で次の状態にする。undo / redo は現在の文書を明示して渡し、保存位置を動かさない。旧3引数の口は呼び手を移行して削除する。`Edit.restore` を決める位置、undoの単位、分岐後に保存位置を失う規則は変えない。
6. **画面位置が同じなら置換しない。** `follow_position` は従来の `first_visible_for_caret` と `first_visible_within` で計算し、先頭行と表示行数が同じなら `with_scroll` を呼ばない。通常・Vim・incsearchは同じ計算を共用する。

## 検証

- 状態のconst&更新で元の値を保つこと、&&更新と同じ結果になること、自己の欄を引数に渡す場合、編集と文書の保存位置、undo / redo を application の対象試験で確認する。
- 共通の編集と履歴の連鎖が変わるので、その試験が呼ぶ既存のVim fixtureも再生する。新しいoracle結果は不要。対象指定が無ければ既存関数を束ねる薄い `--application` selector を足し、全件実行はしない。
- 一意図の欄の直接の呼び手はタブと操作一覧と裏の合図、画面追従はincsearchなので、それぞれの既存scopeを選ぶ。build/静的解析/規約/整形は変更targetと差分を対象にする。
- 実機Releaseで `key-to-frame-single` と `key-to-frame-burst-200` を既存基準で確認する。本文や画面の仕様を変えないので画像の全場面撮影は追加しない。成功した結果は工程が変わっても再利用する。

## 限界と既存決定との関係

ADR 0009 / 0010 の本文・履歴・保存位置と、ADR 0052 の戻り先、ADR 0056 / 0058 / 0062 / 0078 の一意図の欄の寿命を保つ。公開APIの値カテゴリと `with_edit` の引数だけを変える。
重い履歴やレジスタの本文そのものの共有は #323 で扱い、この変更へ混ぜない。全31メソッドの一括書き換え、汎用setter、編集履歴の上限追加は採らない。
