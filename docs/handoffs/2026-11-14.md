## hide の判断待ち

`D:/NeNeNib/evidence/v1.0.0-release/open-questions.md` に詳しい形がある。3 つとも、決めるまで設計席は今の形のまま進めない所だけ止めている。

1. **Store 版で「Windows の右クリックに登録する」が効かなかったら、1.0.0 を止めるか。**
   - 何が起きそうか: ZIP 版では F1 のこの操作でエクスプローラーの右クリックに「NeNe Nib で開く」が出る。Store 版は Windows が書き込みを Store 版の箱の中へ移すので、**出ない見込み**（まだ誰も確かめていない・手順書の 6-C-4 で確かめる）。押しても壊れる物は無い見込みで、出ないだけ。
   - 案 A（**推し**）: 止めない。「Store 版では効かない」を既知の限界に書き（README と PRIVACY は既に「効かない見込み」と書いてある）、次の版で Store 版ではこの操作を隠す。申請を待たせないが、1.0.1 までは押しても何も起きない操作が見える。
   - 案 B: 止めて、先に「Store 版ではこの操作を隠す」直しを入れる。見えなくなるが、製品の変更なので作り直しと hide の試しのやり直し（半日〜1 日）。
   - 6-C-4 で出たら決める物は無い（文書の「見込み」を「確かめた」に直すだけ）。
2. **GitHub と Store のどちらを先に出すか。**
   - 案 A（**推し**・今の決まりのまま）: GitHub が先。hide の確かめが OK ならその日に出せる。ただし Store の審査でファイルの直しが要ると版を 1.0.1 に上げて作り直すので、GitHub の 1.0.0 と Store の 1.0.1 で中身が違う時期ができる（GitHub にも 1.0.1 を出せば揃う）。
   - 案 B: Store の認定を待ってから GitHub。審査で直しが出ても、まだ誰にも配っていないので同じ版で作り直せる見込み（Partner Center が同じ版の上げ直しを受けるかは確かめていない）。そのかわり審査の数日、GitHub の 1.0.0 も待つ。
3. **1.0.0 の後に設定の項目を足すやり方。**
   - 何が起きるか: 1.0.0 は設定のファイル `settings.v4` を厳しく読む。知らない項目が 1 つでもあると、その起動は配色や字体を既定のまま始め、設定の保存を全部断る（ファイルは壊さない・消さない）。後の版が項目を足して書くと、1.0.0 に戻した人や、新しい ZIP 版と Store の 1.0.0 を同じ PC で使う人がこの状態になる。最初に足したいのは「自動の字下げ」（`autoindent`・PR #1668）で、決めるまで入れない。
   - 案 A「版を上げる」（**推し**）: 項目を足すときはファイルの版を上げて `settings.v5` に書き、古い `settings.v4` は残す。1.0.0 に戻しても困らないが、新しい版で変えた設定は 1.0.0 からは見えない。項目を足すたびに版が上がる。
   - 案 B「読み飛ばして残す」: 次の版で、知らない項目を読み飛ばし、保存のときもその行を残す読み方に変える。ファイルは 1 つのままで、これからの版どうしは困らない。ただし **1.0.0 自身は変わらない**ので、1.0.0 に戻す人には効かない（案 A と組み合わせる形になる）。
   - 推しは案 A（1.0.0 と後の版を同じ PC で使っても困らないのは案 A だけ）。Store 版と ZIP 版を併用する人がどれくらいいるかで重みが変わるので、hide の考えで決めてほしい。
