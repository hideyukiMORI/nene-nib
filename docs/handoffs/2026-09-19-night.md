## 変更した経路

- ADR 0019: `VimEditorView` が本文・選択の借用と `VimViewport` を engine に渡す。`vim_step` は 3 引数の入口 1 本。画面と選択の正本は `EditorState` に残る。
- `VimNavigate` が選択と表示先頭を一緒に返す。H/M/L は既存 motion / operator / VISUAL の経路を使い、Ctrl-d/u/f/b と PgUp/PgDn は同じ engine で計算する。
- `ScrollExtent` は末尾空白の境界、`ScrollFollow` は自動追従の方針。通常編集と Vim の違いを controller が選ぶ。明示した末尾空白は以後の移動でも保ち、自動追従だけでは新たな末尾空白を作らない。
- 半画面の明示回数は表示高までに制限して `scroll_lines` に残す。Esc・他の鍵・open・モード切替で消さず、実際に表示高が変わったときだけリセットする。同じ高さの通知では消さない。
- INSERT の Ctrl-d/u/f/b は未対応の別操作なのでスクロールさせない。INSERT のページ移動は undo の単位を閉じる。

## 検証で分かったこと

- `-es` では画面位置を観測できなかった。viewport 入力のある fixture だけ通常 Vim＋標準 subprocess の pipe で実行し、初期・最終の画面整合を検査する。既存 256 件は入力・従来の期待値 8 項目・実行条件を維持する。
- 最終状態だけのテストでは足りない。`v<C-f>y` の最後だけへ合わせてページ移動を抑制すると、途中の画面が誤る。`v/V<C-f><Esc>` と中間の anchor / caret / viewport を別に検査する。
- 高さ 9 / 10 / 11 で、Vim の自動追従が最小移動から中央配置へ変わる閾値も実測した。上下の閾値と中央位置は非対称。数式と境界は ADR 0019 を読む。
- `3k` の 1 回の移動と `kkk` の連打では、画面追従のタイミングが異なる。大きい移動の閾値 fixture を作るときに連打へ置き換えない。本文・カーソルだけでなく表示先頭を比較する。
- oracle の `:normal!` は undo を実際の打鍵と同じ単位に分けない。INSERT の undo 境界・resize / open / toggle の状態保持は手書きの単体テストで検査する。

検証の実数と環境は [gate-proofs の 5-j](../quality/gate-proofs.md#5-j-vim-の表示領域-oracleissue-58adr-00192026-09-19)、最終フルゲートと CI の結果は PR に記録する。waiver は none。フルゲートは他のビルド・測定を止め、同時に 1 本だけ回す。
