# 大きなファイルと文字コード

NeNe Nib は、ログやデータのような大きなファイルも開けます。UTF-8 のファイルなら 1 GiB まで開けて、読み込んでいる間もほかのタブで書き続けられます。文字コードは、UTF-8 のほかに Shift_JIS と UTF-16 を扱えます。この章では、大きなファイルの開き方、1 行がとても長いファイルの見せ方、文字コードと改行の選び方を説明します。

> 開いたファイルの文字コードは、NeNe Nib が自動で見分けます。開くときに文字コードを選ぶ操作はありません。ステータスバーで選ぶ文字コードは、保存するときの文字コードです。

## 大きなファイルを開く

大きなファイルも、ふつうのファイルと同じように `Ctrl+O`（「Vim」モードでは `Ctrl+Shift+O`）やドラッグ＆ドロップで開きます。

| ファイルの大きさ | どうなるか |
|---|---|
| 64 MiB まで | その場で読み込んで開きます。 |
| 64 MiB を超え、1 GiB まで（UTF-8） | 裏で読み込みます。ステータスバーに「読み込み中: ファイル名 37%」のように進み具合が出て、読み終わるとタブが開きます。その間も、ほかのタブで書き続けられます。 |
| 64 MiB を超える（Shift_JIS・UTF-16） | 開けません。「64 MiB を超える Shift_JIS / UTF-16 は開けません。」と出ます。 |
| 1 GiB を超える | 開けません。「1 GB を超えるファイルは開けません。」（1 GiB のこと）と出ます。 |

MiB・GiB は、1,024 を単位にした大きさです（1 MiB は 1,024 × 1,024 バイト）。

- 読み込みを途中でやめるには、ウィンドウを閉じます。`Esc` では止まりません。
- 読み込み中に同じファイルをもう一度開いても、読み込みは最初からやり直しません。そのまま続きます。

大きなファイルでは、次の操作に時間がかかります。

- 保存と、文書の全体を探す検索は、終わるまで画面が止まります。
- 64 MiB を超える文書は、30 秒ごとの自動の退避（異常終了に備えて、保存していない変更を別の場所へコピーしておくこと）をしません。その文書では、画面の下に「64 MiB を超える文書は自動退避しません」と 1 回出ます。こまめに `Ctrl+S` で保存してください。

## 1 行がとても長いファイル

改行の無い 1 行が 16,384 文字を超えるファイルがあります。1 行に書き出したログや、改行を除いた JSON などです。こうしたファイルを開くと、はじめに「改行の無い巨大な行があります。格子表示で開きますか。」と聞かれます。

<!-- 画面: 「改行の無い巨大な行があります。格子表示で開きますか。」のダイアログの写真（あとで入れる） -->

| 答え | どうなるか |
|---|---|
| はい | 格子表示で開きます。格子表示は、文字を同じ幅のマス目に並べる表示で、等幅のフォント（どの文字も同じ幅のフォント）を使います。長い行もウィンドウの幅で折り返します。ステータスバーの右に `grid` と出ます。 |
| いいえ | いつもの表示で開きます。長い行だけは折り返さず、行番号の横に印が付きます。キャレット（文字を入れる位置を示す縦線。カーソルとも言う）のまわりだけを組み立てて表示するので、長い行でも重くなりません。 |

- 聞かれるのは、文書ごとに 1 回だけです。
- 開いた後で表示を変えるときは、`Ctrl+P` を押して `:` を打ち、`set display=grid`（格子表示）か `set display=text`（いつもの表示）を選びます。「Vim」モードでは、NORMAL で `:set display=grid` のように打っても変えられます。
- 長い行の無い文書も、格子表示にできます。文字を同じ幅で並べて見たいときに使えます。
- 長い行には、構文の色分けが付きません。

## 折り返し

長い行は、はじめはウィンドウの幅で折り返して表示します。折り返しのやめ方と戻し方は「[テーマと見た目](07-themes.md)」の章で説明しています。

## 文字コード

文字コードは、文字をファイルのバイトに置き換える決まりです。NeNe Nib は次の文字コードを扱えます。

| 文字コード | ステータスバーの表記 | 説明 |
|---|---|---|
| UTF-8 | `UTF-8` | 新しい文書は、この形で保存します。 |
| UTF-8（BOM つき） | `UTF-8 BOM` | 先頭に BOM（文字コードを示すための数バイトの印）が付いた UTF-8 です。 |
| Shift_JIS | `Shift_JIS` | 日本語の文字コードです。NeNe Nib が扱うのは、Windows で使われている拡張の形（CP932）です。 |
| UTF-16（リトルエンディアン） | `UTF-16 LE` | 1 文字を 2 バイト（または 4 バイト）で表す形です。リトルエンディアンは、2 バイトのうち下の桁のバイトを先に置く並べ方です。BOM の付いたものだけを扱えます。 |
| UTF-16（ビッグエンディアン） | `UTF-16 BE` | UTF-16 LE とバイトの並べ方が逆で、上の桁のバイトを先に置きます。BOM の付いたものだけを扱えます。 |

### 開くときの見分け方

開いたファイルの文字コードは、次の順に見分けます。

1. 先頭に UTF-16 の BOM があれば、UTF-16 として開きます。
2. 先頭に UTF-8 の BOM があれば、UTF-8（BOM つき）として開きます。
3. 正しい UTF-8 として読めれば、UTF-8 として開きます。
4. Shift_JIS として読めれば、Shift_JIS として開きます。
5. どれでもなければ、「文字コードを判別できませんでした。」と出て開きません。

- UTF-32 のファイルは開けません。「UTF-32 のファイルは扱えません。UTF-8 か UTF-16 で保存し直してください。」と出ます。
- EUC-JP や JIS（ISO-2022-JP）のように、上の表に無い文字コードには対応していません。
  - EUC-JP のファイルは、多くの場合 Shift_JIS として読める形なので、Shift_JIS として開いて文字化けします。Shift_JIS として読めない所があれば、「文字コードを判別できませんでした。」と出て開きません。
  - JIS のファイルは、英数字と同じ範囲のバイトだけでできているので、UTF-8 として開いて文字化けします。
- 開いたファイルは、開いたときの文字コードのまま保存します。

### 保存するときの文字コードを変える

| やりたいこと | 操作 | どうなるか |
|---|---|---|
| 文字コードを選ぶ | ステータスバーの右の文字コード（`UTF-8` など）をクリックする | 一覧から、保存するときの文字コードを選べます。 |
| 同じことを操作の一覧から行う | `F1` の一覧から「文字コードを選ぶ」 | 同じ一覧が出ます。 |
| 同じことを「Vim」モードで行う | `:set fenc=cp932` など | `utf-8`・`utf-8-bom`・`cp932`（Shift_JIS）・`utf-16le`・`utf-16be` から選びます。 |

<!-- 画面: ステータスバーの文字コードをクリックして出る一覧の写真（あとで入れる） -->

- 選んでも、画面の本文は変わりません。次に保存するときの形が変わります。
- 選ぶとタブ名の前に「● 」が付き、保存すると消えます。本文を変えていなければ、元の文字コードを選び直しても消えます。
- 文字コードを選ぶ操作は、`Ctrl+Z` では戻りません。戻すときは、元の文字コードを選び直します。
- BOM を付けたいときは `UTF-8 BOM` を、外したいときは `UTF-8` を選んで保存します。

Shift_JIS には、絵文字のように書けない文字があります。そうした文字を含む文書を Shift_JIS で保存しようとすると、「この文字コードでは保存できない文字があります。UTF-8 で保存しますか。」と聞かれます。「はい」を選ぶと UTF-8 で保存し、「いいえ」を選ぶと保存しません。

## 改行の形

改行の形には、Windows で標準の `CRLF` と、macOS や Linux で標準の `LF` があります。

- 開いたファイルは、読んだときの改行の形のまま保存します。
- 新しい文書は `CRLF` で保存します。
- 形を変えるときは、ステータスバーの右の改行（`CRLF` か `LF`）をクリックするか、`F1` の一覧から「改行を選ぶ」を選びます。「Vim」モードでは `:set ff=dos`（`CRLF`）か `:set ff=unix`（`LF`）でも変えられます。
- 文字コードと同じく、選んでも画面の本文は変わらず、保存するときに改行の形が変わります。`Ctrl+Z` では戻りません。

## 詳しく知りたい人へ: 開く速さ

開発者の PC で、NeNe Nib とメモ帳（Windows 11 のメモ帳 11.2609）を同じ条件で比べた結果です。測ったのは NeNe Nib 1.1.0 で、今の 1.2.0 ではありません。

| 測ったこと | NeNe Nib 1.1.0 | メモ帳 |
|---|---:|---:|
| 起動してから、200 行のファイルの文字が出るまで | 100 ms | 450 ms |
| 16 MiB のファイルを開いて、文字が出るまで | 117 ms | 908 ms |
| 16 MiB のファイルを開いた後のメモリ | 30.4 MiB | 88.7 MiB |

ms はミリ秒（1,000 分の 1 秒）です。16 MiB のファイルなら、メモ帳の約 8 分の 1 の時間で開き、使うメモリは約 3 分の 1 です。

数字は、Core i9-10850K・RTX 3090・Windows 11 の 1 台の PC で、設定は既定値のまま、同じウィンドウの大きさで、20 回測った真ん中の値（メモリは 10 回）です。

## 詳しく知りたい人へ: 大きさの上限と、文字コードの細かい決まり

大きなファイルでは、次の機能に上限があります。

| 機能 | 上限 | 超えたとき |
|---|---|---|
| 開く（UTF-8・UTF-8 BOM） | 1 GiB | 開けません。 |
| 開く（Shift_JIS・UTF-16） | 64 MiB | 開けません。 |
| 裏で読み込むようになる大きさ | 64 MiB を超えたとき | ステータスバーに進み具合が出ます。 |
| 自動の退避 | 64 MiB | その文書は退避しません。 |
| 印刷 | 16 MiB | 「印刷は 16 MiB までです」と出ます。 |
| `Ctrl+P` の一覧のプレビュー | 16 MiB | 「大きすぎるのでプレビューしません（16 MiB まで）」と出ます。 |
| 1 行の長さ（格子表示を聞く） | 16,384 文字 | 開くときに、格子表示にするかを聞かれます。 |

文字コードには、次の細かい決まりがあります。

- UTF-8 の BOM が付いているのに、続きが正しい UTF-8 でないファイルは、Shift_JIS として読み直さず、「文字コードを判別できませんでした。」と出て開きません。
- プロジェクトの全文検索（`Ctrl+Shift+F`）は、正しい UTF-8 でない行（Shift_JIS のファイルの行など）を探しません。16 MiB を超えるファイルも探しません。
- 言語サーバーは、BOM の無い UTF-8 のファイルだけを扱います。詳しくは「[言語サーバー](06-language-servers.md)」の章で説明します。
- 改行の形は、ファイルの最初の改行で決めます。最初の改行の前に CR があれば `CRLF`、無ければ `LF` です。改行が 1 つも無いファイルは `CRLF` として扱います。途中に別の形の改行が混ざっていても、改行の形を選び直さない限り、そのままのバイトで保存します。

次は「[困ったとき](10-troubleshooting.md)」で、よくあるつまずきと、その直し方を説明します。
