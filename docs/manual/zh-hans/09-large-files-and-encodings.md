# 大文件与字符编码

NeNe Nib 也能打开日志、数据等大文件。UTF-8 文件最大可以打开 1 GiB，并且在读取期间可以继续在其他标签页中编辑。字符编码方面，除了 UTF-8 之外，还支持 Shift_JIS 和 UTF-16。本章说明大文件的打开方法、单行非常长的文件的显示方式，以及字符编码和换行符的选择方法。

> 打开的文件的字符编码由 NeNe Nib 自动识别。打开时没有选择字符编码的操作。在状态栏中选择的字符编码是保存时使用的字符编码。

## 打开大文件

大文件也和普通文件一样，可以用 `Ctrl+O`（“Vim”模式下为 `Ctrl+Shift+O`）或拖放打开。

| 文件大小 | 结果 |
|---|---|
| 不超过 64 MiB | 立即读取并打开。 |
| 超过 64 MiB、不超过 1 GiB（UTF-8） | 在后台读取。状态栏中会以“正在读取：文件名 37%”的形式显示进度，读取完成后打开标签页。在此期间，可以继续在其他标签页中编辑。 |
| 超过 64 MiB（Shift_JIS、UTF-16） | 无法打开。会显示“无法打开超过 64 MiB 的 Shift_JIS / UTF-16 文件。” |
| 超过 1 GiB | 无法打开。会显示“无法打开超过 1 GB 的文件。”（指 1 GiB）。 |

MiB、GiB 是以 1,024 为单位的大小（1 MiB 为 1,024 × 1,024 字节）。

- 要中途停止读取，请关闭窗口。按 `Esc` 不会停止。
- 读取期间再次打开同一文件，读取不会从头重新开始，而是继续进行。

对于大文件，以下操作需要较长时间。

- 保存以及在整个文档中查找时，界面会停止响应，直到操作完成。
- 对于超过 64 MiB 的文档，不会每 30 秒进行一次自动备份（为防止异常退出，将未保存的更改复制到其他位置）。对于这样的文档，窗口底部会显示一次“超过 64 MiB 的文档不自动备份”。请经常按 `Ctrl+S` 保存。

## 单行非常长的文件

有些文件中，不含换行符的一行超过 16,384 个字符。例如写成一行的日志，或去掉了换行符的 JSON 等。打开这样的文件时，会先询问“文件中有不含换行符的超长行。是否以网格视图打开？”。

<!-- 画面：“文件中有不含换行符的超长行。是否以网格视图打开？”对话框的截图（稍后补充） -->

| 回答 | 结果 |
|---|---|
| 是 | 以网格视图打开。网格视图是将字符排列在等宽方格中的显示方式，使用等宽字体（所有字符宽度相同的字体）。长行也会按窗口宽度折行。状态栏右侧显示 `grid`。 |
| 否 | 以普通视图打开。只有长行不折行，并在行号旁边显示标记。由于只构建并显示光标周围的部分，即使是长行也不会变慢。 |

- 每个文档只询问一次。
- 打开后要更改显示方式，请按 `Ctrl+P` 并输入 `:`，然后选择 `set display=grid`（网格视图）或 `set display=text`（普通视图）。在“Vim”模式下，也可以在 NORMAL 下输入 `:set display=grid` 这样的命令来更改。
- 没有长行的文档也可以使用网格视图。想让字符以相同宽度排列查看时可以使用。
- 长行不进行语法着色。

## 自动换行

默认情况下，长行会按窗口宽度折行显示。取消和恢复自动换行的方法，在“[主题与外观](07-themes.md)”一章中说明。

## 字符编码

字符编码是将字符转换为文件字节的规则。NeNe Nib 支持以下字符编码。

| 字符编码 | 状态栏中的显示 | 说明 |
|---|---|---|
| UTF-8 | `UTF-8` | 新文档以此格式保存。 |
| UTF-8（带 BOM） | `UTF-8 BOM` | 开头带有 BOM（用于表示字符编码的几个字节的标记）的 UTF-8。 |
| Shift_JIS | `Shift_JIS` | 日语的字符编码。NeNe Nib 支持的是 Windows 中使用的扩展形式（CP932）。 |
| UTF-16（小端序） | `UTF-16 LE` | 用 2 个字节（或 4 个字节）表示一个字符的格式。小端序是指在 2 个字节中先放低位字节的排列方式。只支持带 BOM 的文件。 |
| UTF-16（大端序） | `UTF-16 BE` | 字节排列方式与 UTF-16 LE 相反，先放高位字节。只支持带 BOM 的文件。 |

### 打开时的识别方法

打开的文件的字符编码，按以下顺序识别。

1. 如果开头有 UTF-16 的 BOM，则作为 UTF-16 打开。
2. 如果开头有 UTF-8 的 BOM，则作为 UTF-8（带 BOM）打开。
3. 如果能作为正确的 UTF-8 读取，则作为 UTF-8 打开。
4. 如果能作为 Shift_JIS 读取，则作为 Shift_JIS 打开。
5. 如果都不是，则显示“无法识别编码。”，不打开文件。

- 无法打开 UTF-32 文件。会显示“不支持 UTF-32 文件。请另存为 UTF-8 或 UTF-16。”
- 不支持 GBK／GB18030。如需打开这类文件，请先用其他软件将其转换为 UTF-8。
- 不支持上表中没有的字符编码，例如 EUC-JP 或 JIS（ISO-2022-JP）。
  - EUC-JP 文件在多数情况下可以作为 Shift_JIS 读取，因此会作为 Shift_JIS 打开并出现乱码。如果有无法作为 Shift_JIS 读取的部分，则显示“无法识别编码。”，不打开文件。
  - JIS 文件只由与英语字母和数字相同范围的字节组成，因此会作为 UTF-8 打开并出现乱码。
- 打开的文件会以打开时的字符编码保存。

### 更改保存时的字符编码

| 任务 | 操作 | 结果 |
|---|---|---|
| 选择字符编码 | 单击状态栏右侧的字符编码（如 `UTF-8`） | 可以从列表中选择保存时使用的字符编码。 |
| 从命令列表中执行同样的操作 | 在 `F1` 命令列表中选择“选择编码” | 显示同样的列表。 |
| 在“Vim”模式下执行同样的操作 | `:set fenc=cp932` 等 | 从 `utf-8`、`utf-8-bom`、`cp932`（Shift_JIS）、`utf-16le`、`utf-16be` 中选择。 |

<!-- 画面：单击状态栏中的字符编码后显示的列表的截图（稍后补充） -->

- 即使选择了字符编码，界面上的正文也不会改变。改变的是下次保存时的格式。
- 选择后，标签页名称前会加上“● ”，保存后消失。如果没有更改正文，重新选择原来的字符编码也会使其消失。
- 选择字符编码的操作无法用 `Ctrl+Z` 撤销。要恢复时，请重新选择原来的字符编码。
- 要加上 BOM 时选择 `UTF-8 BOM`，要去掉 BOM 时选择 `UTF-8`，然后保存。

Shift_JIS 中有无法写入的字符，例如表情符号。尝试以 Shift_JIS 保存包含这类字符的文档时，会询问“部分字符无法以此编码保存。是否以 UTF-8 保存？”。选择“是”会以 UTF-8 保存，选择“否”则不保存。

## 换行符格式

换行符格式有 Windows 标准的 `CRLF`，以及 macOS 和 Linux 标准的 `LF`。

- 打开的文件会以读取时的换行符格式保存。
- 新文档以 `CRLF` 保存。
- 要更改格式，请单击状态栏右侧的换行符（`CRLF` 或 `LF`），或在 `F1` 命令列表中选择“选择换行符”。在“Vim”模式下，也可以用 `:set ff=dos`（`CRLF`）或 `:set ff=unix`（`LF`）更改。
- 与字符编码一样，选择后界面上的正文不会改变，保存时换行符格式才会改变。无法用 `Ctrl+Z` 撤销。

## 深入了解：打开速度

以下是在开发者的电脑上，以相同条件比较 NeNe Nib 和记事本（Windows 11 的记事本 11.2609）的结果。测量的是 NeNe Nib 1.1.0，而不是当前的 1.2.0。

| 测量内容 | NeNe Nib 1.1.0 | 记事本 |
|---|---:|---:|
| 从启动到显示 200 行文件的文字 | 100 ms | 450 ms |
| 打开 16 MiB 的文件到显示文字 | 117 ms | 908 ms |
| 打开 16 MiB 的文件后的内存 | 30.4 MiB | 88.7 MiB |

ms 是毫秒（千分之一秒）。对于 16 MiB 的文件，打开所需时间约为记事本的八分之一，使用的内存约为三分之一。

这些数字是在一台配备 Core i9-10850K、RTX 3090、Windows 11 的电脑上，保持默认设置、使用相同的窗口大小，测量 20 次所得的中位数（内存为 10 次）。

## 深入了解：大小上限与字符编码的详细规则

对于大文件，以下功能有上限。

| 功能 | 上限 | 超过时 |
|---|---|---|
| 打开（UTF-8、UTF-8 BOM） | 1 GiB | 无法打开。 |
| 打开（Shift_JIS、UTF-16） | 64 MiB | 无法打开。 |
| 开始在后台读取的大小 | 超过 64 MiB 时 | 状态栏中显示进度。 |
| 自动备份 | 64 MiB | 不备份该文档。 |
| 打印 | 16 MiB | 显示“打印的上限为 16 MiB”。 |
| `Ctrl+P` 列表的预览 | 16 MiB | 显示“文件过大，不预览（最大 16 MiB）”。 |
| 单行长度（询问是否使用网格视图） | 16,384 个字符 | 打开时询问是否使用网格视图。 |

字符编码有以下详细规则。

- 带有 UTF-8 的 BOM、但后续内容不是正确 UTF-8 的文件，不会作为 Shift_JIS 重新读取，而是显示“无法识别编码。”，不打开文件。
- 项目的全文搜索（`Ctrl+Shift+F`）不搜索不是正确 UTF-8 的行（如 Shift_JIS 文件中的行）。也不搜索超过 16 MiB 的文件。
- 语言服务器只处理无 BOM 的 UTF-8 文件。详情在“[语言服务器](06-language-servers.md)”一章中说明。
- 换行符格式由文件中的第一个换行符决定。第一个换行符前有 CR 则为 `CRLF`，没有则为 `LF`。没有任何换行符的文件按 `CRLF` 处理。即使中间混有其他格式的换行符，只要不重新选择换行符格式，就会按原样的字节保存。
