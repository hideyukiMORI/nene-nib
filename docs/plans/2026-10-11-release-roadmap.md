# 正式リリースまでのロードマップ

2026-10-11 / Issue #408 / hideの保存依頼による計画。

2026-10-12 / Issue #436 / hideの指示でシンタックスカラーリング、選択テキストのドラッグ＆ドロップ、横ホイール対応を追加し、細いスクロールバーの案を記録。通常モードのドラッグ選択とカーソルに追従する横スクロールは#410で対応済みとして、残作業を区別する。

正式リリースの柱を、split、1GB超のファイルの閲覧と編集、Markdownのリアルタイムプレビューとする案を進める。順序は、**範囲の整理 → 大容量編集の成立性確認 → 大容量対応 → 日常編集の仕上げ → split → Markdownプレビュー → 併用確認と公開**とする。

最も不確実な大容量編集を小さく確かめ、本文の持ち方・読み書き・背景処理の土台を先に固める。その上で表示枠を分け、プレビューを載せることで手戻りを抑える。各段階は使える成果で区切り、暦日の期限はまだ置かない。

## 大容量から始める理由と実装の区切り

現在の読込・行索引作成は同期で、保存は本文全体を一つの文字列へまとめる。64MiBの上限を引き上げるだけでは1GB超の応答性とメモリ使用量を保証できない。限定試作では、開けることに加えて編集後の保存・再読込まで確かめる。通常の多数行と長い行を区別し、ファイル容量だけで負荷を表さない。

段階1の入力、測定区間、回数、容量、文字コード、失敗と外れ値の扱い、判断条件は試験前に固定する。結果を見て合格まで反復せず、成立・範囲の縮小・設計の見直しのどこへ進むかを残す。

段階2は「大容量を見られる版」「編集して保存できる版」「検索なども実用的な版」に分ける。各区切りで通常のIssue・PR・対象検証・main統合を完了させる。本文の正本とファイルI/Oの正典経路を維持する。背景処理は既存のワーカー1本を前提とし、索引・検索・構文色の解析・プレビューが待たせ合う場合は処理の区切りや中断を設計する。並行性や所有の変更は該当ADRで決める。

splitは大容量の本文を複製せず参照するため、本文・undo・保存位置と、枠ごとの選択・カーソル・スクロールを分ける。Markdownはその表示枠と背景処理を利用する。3機能を持つことを、1GB超のMarkdown全文を毎打鍵プレビューできる保証には広げない。

シンタックスカラーリングはSPECIFICATION第6節に沿い、表示範囲を入力経路の外で自前の字句解析器へ渡し、行頭状態のキャッシュで差分更新する。巨大ファイルでは閾値で自動オフにする。対応言語と閾値は段階0で整理し、この追記では確定しない。段階5〜6ではMarkdownプレビューと解析が待たせ合う影響も確認する。

縦のホイール・ページ移動と、折り返しなしでカーソルに追従する横スクロールは対応済み。横ホイールによる手動スクロールを追加する。スクロールバーは、普段は細く控えめに表示し、マウスが近づくと太くして、見た目より広い操作判定を持つ案を段階0で検討する。縦は右端、横は折り返しオフで本文がはみ出すときだけ下端に表示する案とし、つまみで大きく移動できることと文書内の現在位置が分かることを重視する。具体的な寸法と表示条件は実装前の見た目の設計で決める。

選択テキストのドラッグ＆ドロップでは、選択元・挿入位置・移動とコピー・取消・undoを同じ編集の正典経路で扱い、文書や枠をまたぐ範囲は段階0の判断に従う。

## 性能を判断して示す方法

| 対象 | 守るものと示す値 |
| --- | --- |
| 単画面 | 既存の性能基準を維持し、関連する操作の退行を確認する |
| split | 通常表示と分割時の絶対値・差・入力遅延の分布・メモリ。独立文書と同一文書を区別する |
| 大容量 | 操作可能になるまでの時間、移動・検索・編集・保存中の停止、メモリ、保存内容の正しさ |
| シンタックスカラーリング | 文字入力の応答と色の更新までの時間を分け、連続編集・画面移動で古い解析結果を適用しないこと、大容量時の自動オフを確認する |
| Markdown | 文字入力の応答とプレビュー更新までの時間を別々に記録する |
| 併用 | 大容量処理と別文書の入力・プレビューの干渉、長い停止、メモリを確認する |

旧「総2ms」の試験結果とholdは残す。今後のsplit採用条件はADR 0075決定5に沿って段階0でhideと定め、新しい比較を行う前に記録する。今回のロードマップ保存は閾値変更でも採用判断でもない。

性能改善は各段階の使い方を妨げる箇所に絞る。単位の異なる処理や別日の改善率を加算せず、速さだけで完了とせず正しさと試用も確認する。検証は変更機能と直接の境界を対象に選び、関連入力が不変の成功結果を再利用する（QLT-001 / QLT-012）。段階6では併用による相互作用を追加確認し、各段階の成功済み検証を一律に再実行しない。

## 範囲を縮める場合の順序

1. 3枠以上、分割配置の復元、凝ったMarkdown拡張、プレビュー上の直接編集を後続へ置く。
2. 大容量で対応する文字コード・容量・重い操作、Markdown構文の範囲を限定して明示する。採用済み機能の保証を変更する場合は別途決定する。
3. 段階1で大容量の安全な保存やメモリ使用量の見通しが悪ければ、初版を1GB超の閲覧までとし、編集を後続へ送る案をhideと判断する。

縮小は自動適用しない。splitやMarkdownを含め、成立しない根拠と利用価値を示して初版の範囲を再判断する。
