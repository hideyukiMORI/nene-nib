他案件の画面操作と重いビルド/測定を止められる時間帯をhideと調整してから取得する。Releaseのみ。検証用profile・本文・出力・実行体コピーは本taskのD側出力へ隔離する。起動・刺激・終了・画面取得は既存 `eng/window_driver.py` を使う。実行体SHA、入力SHA、環境、全標本、欠測/例外、画像を残す。失敗後の無変更再試行や合格試料だけの採り直しはしない。

### 表示と編集

固定本文はASCII長行、日本語/結合文字/絵文字/Tab混在行、複数の短行。次を一連の実行で確認する。

1. 既定wrapで複数画面行を表示し、論理行番号は一度だけ描く。クリックとHome/End/上下のcaretがその画面行へ来る。
2. 正方向・逆方向・複数論理行のdrag、解放後/失焦後の停止、上下端/nowrap左右端での継続。選択を削除して保存し、本文bytesで範囲を照合、undoで復元。
3. ホイールと部分画面行、狭い/広い幅へのresize、font size変更、タブ切替・終了復元で本文とcaretを維持する。
4. 通常/INSERTで日本語IMEを折り返し端付近へ差し込み、下線/注目節/caret/候補位置・確定/取消を画像と保存本文で確認する。実IMEが応答しない場合は未測と明示し、模擬成功にしない。
5. Vimの論理行移動とH/M/L/半/全ページを短く確認する。未実装gj/gk/g0/g$やVimドラッグを成功項目へ含めない。

DPIは実機の利用可能な画面でのみ確認し、単一DPIしか利用できない場合は複数monitorの試験を未実施と記録する。描画資源のDPI変更と幾何キーは窓を作らない検証でも扱う。

### 性能

同じ主機でA=旧main相当の既存Release、N=候補nowrap、W=候補wrapを比較する。Aの製品入力はmain61a505dと一致し、既存のcf27a3a ReleaseのSHA照合/コピー記録を `baseline/provenance.json` に保持する。N/Wはcleanな候補commitから既存 `eng/build-release.ps1 -Ref HEAD` で作る。

指標は `startup-first-frame`、`key-to-frame-single`、`key-to-frame-single-long-line` の3つ。起動は本文layoutの所有移動、単打は毎入力の位置解決、長行は同じ論理行の全文字組みが直接の退行リスク。他の大容量/検索/一覧の性能測定は選ばない。

各指標・各条件5回、合計45試行。各round内の条件順を A,N,W / N,W,A / W,A,N / A,N,W / N,W,A に固定する。各試行は正典 `measure-speed.measure(exe,1,bench)` を使い、rawを個別ディレクトリへ残す。指標の定義・固定長行本文・待機・正式基準値/許容は変えない。各条件は同じCascadia Code 13.5pt、system theme、guide onをpreseedし、Aはsettings.v2、N/Wはsettings.v3でwrapだけ切り替える。

正式判定は候補既定wrapの3指標を既存QLT-014へ渡す（各3有効未満は計測不能）。nowrapは同じ表示条件での費用をAと比較する。wrap長行は画面に見える論理行数が変わるため、旧版との比を同等の表示の高速化率として扱わない。中央値・全試料・差・比とこの制約を併記する。閾値変更やreference更新は行わない。
