## 3. 形（各段の ADR で確定する）

### 3.1 索引の細身化と上限の 1 本化（段 1）

- 改行の索引を細くする: 64 KiB の塊ごとの要約（`VirtualColumnIndex` と同じ考え）に、行頭を 32 bit の差分で持つなど、**本文の 5% 以下（2 GiB で約 100 MiB）**を目標にする。ADR 0121 の追記。既存の 8 本（特に 16 MiB open・16 MiB 連打・`G` `gg`）で退行なしを示す。
- 上限の正本を 1 か所に（`maximum_file_bytes` を core か application の定数 1 つにし、退避の読み戻しも同じ値を読む）。
- ADR 0122 / 0141 の状態行を実態に合わせる（D49）。`refactor/452-streaming-utf8(-m)` の branch を消す（hide の了承の後）。

### 3.2 開く道の非同期化（段 2・新規 ADR）

- `FilePort::read` の同期の道を、型のある port（`DocumentReadPort{request(ticket, path), collect()}`・`FolderPort` と同じ形）に替える。worker が塊（1 MiB）ごとに読み、`Utf8Validation`（ADR 0122・main にある）に流しつつ改行の索引を作る。**検証が全部通ってから文書を採用する**（部分の本文を公開しない）。
- 符号化の判定: 先頭の塊で BOM と UTF-8 / Shift_JIS の候補を決め、残りは worker の検証で確定する。64 MiB を超える入力は UTF-8 / UTF-8 BOM だけ（L-3）。
- BOM の除去は `erase(0,3)` でなく piece の開始位置を 3 にずらす（memmove 0）。
- 取消（Esc か閉じる）・古い完了（要求の券と文書の incarnation で照合・ADR 0127 §3）・確保の失敗を値にする（`FileFailure::insufficient_memory` を足し、adapter で `std::bad_alloc` を値に変える・ARC-010）。
- ADR 0010 決定 12（同期の読み）を改める。開く道は `open_document` の 1 本のまま、戻り値の意味が「読み始めた / 失敗」に変わる。

### 3.3 読み込み中の UI（段 3・同じ ADR）

- 待っている間は**タブを足さず**、ステータスに「読み込み中: <名前>」を出す（設計案の「全部そろってから採用」に一番小さい）。見た目が変わるなら `/design` と D 番号。
- `open_document` の呼び出し元 4 か所（`accept(OpenDocument)`・`open_listed`・`reach_tab`・D&D）と起動の引数・復元を同じ 1 本に乗せる。失敗の出し方（ダイアログ / 1 行）は今のまま。
- `WorkCompleted` の規則（歩き・知らせ・変換・Vim の待ち・`.`・undo を動かさない）に載る。

### 3.4 全文の写しを消す（段 4・ADR 0137 の追記）

- 自動退避: 64 MiB 超は退避しない（L-4）・1 回知らせる。`joined_bytes` を `encoded_parts` の借用に替える。
- `merge_replayed_edits` の全文 2 本・UTF-16 の保存の写しを `segments()` の借用に。
- 契約 `verify_quiet_paths` に「写しの回数」を数える欄を足す（打鍵の道で全文を写さない）。

### 3.5 止まらない操作と保存の非同期化（段 5・新規 ADR）

- UI スレッドで全文を走る操作: 検索（`/` `?` `n` `*` `#`）は予算つきの継続（1 frame に N MiB まで・続きは次の frame）か worker。`G` `gg` `:N` は索引で済む。
- 保存を worker へ: 版の凍結（ADR 0127 §4 の一部を先に入れる）。保存中の編集は新しい版に積み、保存済みの位置は凍結した版で決める。tmp → `ReplaceFileW` の流れは ADR 0135 のまま。
- 自動退避の終わり（ADR 0137 決定 9・3 秒）は 64 MiB 超が対象外なので揃う。

### 3.6 ベンチと受理（段 6）

- `open-large-file-512mib` / `open-large-file-2gib` を巨大な行の 2 本（ADR 0138）と同じく**名指ししたときだけ**測る扱い。生成は固定の行を流して書き、大きさと SHA-256 で再利用。
- 報告に「先頭の本文が見えるまで」「索引が完成するまで」「private bytes の最大（`PrivateUsage`）」を足す。60 s の時間切れは暖機の試行と分ける。
- 100 ms の判定: 裏で読んでいる最中に別のタブで打つ新しいベンチ（L-5）。
- 受理は D41（独立レビュー・速さのゲート・CI・hide の試用）。宣言する上限（1 GB / 2 GiB）はここで決める（L-1）。

## 5. 確かめ方

| 対象 | 方法 |
| --- | --- |
| 索引 | 単体テスト（塊の境・CRLF・末尾）・16 MiB open と連打と `G` のベンチで退行なし |
| 開く道 | 契約 `--open-async`（要求 → 合図 → 採用・取消・古い券・失敗の値）・`--background-work`・`verify_quiet_paths` |
| 写し | `verify_quiet_paths` の写しの欄・16 MiB の自動退避の時間 |
| 保存 | 契約（版の凍結・保存中の編集・tmp の回収）・`eng/verify-window.py` で 2 GiB を開いて保存して読み戻す（SHA-256 の一致） |
| 速さ | 既存 8 本に退行なし・新しい 2 本と 100 ms の判定を記録。採用は D41 |

## 6. 残る不確かさ

- 2 GiB の `resize_and_overwrite` の確保が失敗したときの今の振る舞い（例外で落ちるか）。段 2 の前に小さな probe で確かめる。
- 索引を 5% 以下にする形で `G` `gg` `:N` と仮想桁の索引（`VirtualColumnIndex`）の速さが保てるか。段 1 で測る。
- worker 1 本に読み・索引・保存・退避・Markdown の parse が同居する。長い仕事は塊ごとに切って FIFO を塞がない（ADR 0062 の形）。塊の大きさは段 2 で決める。
- 検索の予算つきの継続は engine の外の preview（incsearch・ADR 0041）と同じ形にできるか。段 5 で設計する。
