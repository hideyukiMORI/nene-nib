# 編集の機能の追加計画（Vim / Neovim の定番の plugin の機能とヴァニラの穴・速さを最優先）

2026-10-28 / hide の指示（外から・「全部実装予定に入れて。ただ、速度向上は最大限に考慮」）/ 設計席（Nibリナ）。
エクスプローラー（`2026-10-28-file-explorer.md`・D66）とイージーモーション（`2026-10-28-easymotion.md`）に続く計画。施主決定 **D67**。

## 0. 速さの条件（全部の機能に共通・D67）

1. **使っていないときの打鍵の道に分岐を 1 つも足さない。** 既定オフの機能はオフのとき port も表も引かない。既定オンの機能（matchparen・変更の印）は「見えている範囲だけ・O(見えている行数)」で、1 打鍵の増分を A/B（ABAB・静かな機械）で測り、**空の文書の 1 打鍵の中央値の +1%（約 5 µs）を超えたら設計を変える**（merge しない）。
2. **8 本のゲートは不変**（QLT-014・基準値は変えない）。機能ごとに「オンの状態の任意のベンチ」を `OPTIONAL_BENCHES` に足し（`matchparen-single-key` `change-marks-burst-200` `grep-root-1000-files` など・ADR 0138 の形）、PR 本文に数字を書く。採用は D41（独立レビュー・ゲート・CI・試用）。
3. **全文を走らない。** 括弧の相手の探索は見えている範囲（と前後 1 画面）で打ち切る・変更の印は保存の時点からの `Edit` の列から増分で求める（全文の差分を打鍵ごとに取らない）・全文検索は worker で塊ごとに（取消できる・ADR 0062 の形）・置換の preview は incsearch と同じく見えている行だけ。
4. **frame を増やさない。** yank の光りはタイマーの意図 1 回で消える（frame は 2 回だけ）。印・下線・線は既存の描画の道（当たりの枠・`underline_runs`・tint）に載せ、layout を作り直さない（ADR 0114 / 0150 の保持を壊さない）。
5. **engine は純関数のまま**（ARC-003）。言語ごとの表（コメント記号・括弧の対）は core の `constexpr` の表 1 つ。

## 4. 確かめ方（共通）

- engine の機能（1・2・3・9・10・#768・#770）: 契約（scope ごと）と fuzz（`eng/vim-fuzz.py` の語に足す・ただし plugin の機能は oracle で測れないので `--exclude` で外す）・性質の試験（`.` の往復・undo 1 単位・UTF-8 と改行の形の不変）。
- ui の機能（4・7・8・エクスプローラー）: `nib_window_tests` の画素（WIC）と `eng/verify-window.py` の節。
- 速さ: 8 本のゲート不変 ＋ 機能ごとの任意のベンチ ＋ A/B（§0）。
