# Vim の鍵の変更の印の実測（2026-11-12・#1440・ADR 0181）

ADR 0181（Vim の鍵が「undo の単位を作ったか」と「本文を変えたと数えるか」は engine が効果に添える 1 つの印）の根拠の表。下ごしらえ G1（2026-11-12・Opus）が Vim 9.1.0004（`-u NONE -i NONE -N -n -es`）で 80 形を 1 形ずつ別の Vim で測り、9.1.0004 の source（`ops.c` `normal.c` `change.c` `register.c` `undo.c` `edit.c` `move.c`）の行で規則を読んだ表を、リポジトリの外の作業の記録から写した（作業の記録と道具はリポジトリの外にあり、ここにはこの表だけを残す）。

## 測り方

- 1 形ずつ別の Vim を起こし、`call cursor` で置き、準備の鍵（`yl` など）の後に `let &undolevels = &undolevels`（undo を区切る）と `set nomodified` を置いてから、対象の鍵を 1 本の `:normal!` で流した。前後の `b:changedtick`・`undotree().seq_cur`・`&modified`・`getpos("'.")` `"'["` `"']"`・無名レジスタを読んだ。
- `:normal!` の中でも、スクリプトの Ex の行の間でも、Vim は undo を区切らない（`xx` は 1 単位・実測）。fixture の oracle も 1 本の `:normal!` なので、oracle の答えでは「鍵ごとの undo の単位」は測れない。
- 本文の `abc/def` は 2 行（`/` が改行）、空の本文は空の行 1 つ（Vim には改行を付けて書いた）。0 バイトのファイルは Vim の `ML_EMPTY` という別の状態で、fixture の `text: ""` はこちらになる（補足 A）。
- 列: C = `b:changedtick` の増分（> 0 なら `changed_*` を呼んだ）・U = `seq_cur` の増分（> 0 なら `u_save`）・`'.` `'[` `']`（「保つ」は目印のまま＝書かなかった・「-」は未設定のまま）・`.` は記録されたか・保存の列は [保存直後, 鍵の後, u の後, C-r の後] の `&modified`・Vim 先頭は窓（60 行・高さ 8・先頭 53・`so=4`・`3<C-e>` の後）の答え（56 = 保つ・55 = 決め直した）・「Nib は積むか」は実装の前（`origin/main` `03983654`）の Nib。
