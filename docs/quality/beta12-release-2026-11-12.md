## 主な変更（beta.11 `03983654` から・公開の文に使う）

使う人に見える変化:

- **窓の角を四角にし、Mica を掛けない**（#1488・PR #1491・施主決定 D86・ADR 0008 決定 9 の追記・ADR 0013 / 0162 の追補）: エクスプローラーを出したときの本文の面の左上の丸みを外して直角にした（境界の線は残す）。窓の角は `DWMWA_WINDOW_CORNER_PREFERENCE` = `DWMWCP_DONOTROUND` で四角（Windows 10 と古い 11 では属性が無く今までどおり）。窓の背景に Mica を掛けない（帯は D16 から不透明なので見た目は変わらない）。
- **ミニマップの見えている範囲の色**（#1487・PR #1489・ADR 0171 決定 2 の追補）: 面は accent の 22%、上端と下端に 1 DIP の accent 70% の線、面を押している間は 32%。accent と背景のコントラストが 1.5 未満のテーマ（synthwave-84・cobalt2・tokyo-night-light）は text の色。
- **「フォルダを開く」= Ctrl+Shift+R**（#1495・PR #1497・施主決定 D85・ADR 0162 / 0172 の追補）: 通常 / Vim の両モードでルートのフォルダを選ぶ箱が開く。Shift なしの Ctrl+R は今までどおり Vim の redo と INSERT の `Ctrl-r {register}`。起動画面の「フォルダを開く」の行の右端に鍵の枠が出る。起動画面の読み直しの間に開けずに外した行は、古い読みが届いても戻らない。
- **右上の角と × □ ＿ の上端で大きさを変えられる**（#1498・PR #1510・ADR 0056 の追補・D82）: 最大化していない窓は縁（8 DIP・8 方向）が帯の要素より先に勝ち、窓の操作の上だけ縁は 4 DIP。最大化した窓とモニターの端に接した辺（右半分に Snap した窓の右端と上端など）は縁 0 で、画面の端へ投げたマウスは今までどおり × に当たる。直す前は最大化でも縁 8 DIP が 4 辺に残り、本文の左端・ミニマップの右端・ステータスバーの最下段の 8 DIP が押せなかった（直した後は client）。
- **描画を失って「保存しますか」を聞く間の下地**（#1499・PR #1509・ADR 0008 決定 9 の追記・ADR 0013 / 0133 の追補）: 取消の無い「描画できなくなったので閉じます。保存しますか。」の箱の前だけ窓に Mica を掛け、透けた見えない窓に箱だけが浮く形をなくす。`recover()` が成功した道・未保存の無い終わり・使う人の ×・OS の終了では掛けない。
- **Vim**: 矩形の `p` `P` で貼る桁が全角・幅 2 の絵文字・結合文字つきの全角などの途中に落ちる行は、その文字を割らず前に空白を入れる（`ab⏎いう` の `<C-v>jyp` は `aabb⏎ いいう`・#1482・PR #1512・ADR 0035 の追補）。`` `^ `` `'^` と `` d`^ `` などのオペレータの移動が INSERT を最後に抜けた位置へ飛ぶ（前は飛ばずにキャレットが残っていた・#1448・PR #1516・ADR 0152 の追補）。

内部の直し:

- **merge の道具**（#1501・`b13a37c8`・製品でない）: `eng/merge-pr.py` は merge の前の読みの一時の失敗を待ち直す。

## 既知の限界（各 PR の「残るリスク」から）

- 窓の角（#1488）: ごく小さな丸み（約 4 px・DWM が中身の visual を抜く）は残る（#1496）。Mica の無い起動直後の約 10 ms と device の差し替え・作り直し・広げるリサイズの 1 frame は窓の後ろが透けると読んだ（画素では未確認・施主は Mica なしの試用 exe でちらつきを言っていない）。
- ミニマップの色（#1487）: 整数の近似のコントラストは WCAG の正確な比と値が違う（切り替わるテーマの集合は同じ）。押しの描き直しは窓の手続きを通る試験が無い（読みだけ）。
- Ctrl+Shift+R（#1495）: 実機の鍵の入力では確かめていない。
- 右上の角の伸縮（#1498）: Snap の形（右半分・左半分・4 隅・上端に接する窓）の実機の確かめと `eng/verify-window.py --caption` の `hit:` の 10 件は回していない。上端に接して置いただけの窓は上端から伸ばせない・隣のモニターに接した辺は内側から伸ばせない（1 本の規則の限界・ADR 0056）。本物のマウスでの角・上端・右端の伸縮と × の上端 4 DIP の押し心地は施主の試用で確かめる。
- 非常時の下地（#1499）: 描画を失う道は実機で起こせないので、下地が実際に見えるかは未確認で、`end_window` の配線は試験が守っていない（#1511）。角の約 4 px の Mica の点（#1496）はこの非常時だけ出る。
- 矩形の貼付（#1482）: `<200b>` のような書式用文字・C1 制御文字の途中に落ちる貼付は fixture で測っていない。U+0085 の桁は Vim が 1 桁・Nib が 4 桁（#1514）。`gp` `gP` と `'[` `']` は後続（#1515）。NORMAL の `<Home>` の後の `j` `k` の欲しい列（#1505）は本件の外。
- `'^`（#1448）: `r<CR>` の後の書き直しと、途中の行の `o` を `u` で戻したときのマークは後続（#1518）。INSERT の中の `<C-o>` を Nib は文字として入れる（#1517）。NORMAL の `s` `S` は後続（#768）。
- fuzz の既知（#1483）: 対話の Vim の形で Nib が一致することは fixture で守れない（oracle は 1 本の `:normal!`）。折り返す行は測っていない（ADR 0146 の追補）。
- 前の版から残るもの: Markdown プレビューで長い段落を初めて表示する 1 回の費用（#1485）、編集 1 回の piece の列の作り直しの費用（#1474）、矩形の VISUAL の `p` `P` の後の `'.`（#1475）。
