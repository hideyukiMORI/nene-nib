# split の下準備 — 2026-10-03

Issue #290 / D40 / [ADR 0068](../adr/0068-split-starts-with-a-bounded-render-probe.md)。製品採用は未決。見た目はD12に従い別途選定する。この文書の操作詳細は設計案で、未実装。

## 範囲とタブ

最大2枠、上下または左右の等分から考える。タブは窓全体で1列の文書タブを維持する。タブ・Ctrl+P・既存のタブ移動で選んだ文書を操作中の枠へ表示し、もう一方はそのまま。同じ文書を両枠に表示でき、本文・undo履歴・名前・保存位置は文書に一つだけ持つ。

この案では現在のファイルの探し方、保存、文書タブの意味を引き継げる。通常/Vimを切り替えるNibに馴染み、分割配置ごとに別のファイル一覧を探す必要がない。一方、Vimのtabpageのように配置と複数文書の組をタブごとに切り替える使い方はできない。同じファイルが二つの枠に出るため、操作中の枠と各枠の文書名の表示が必要になる。タブ方式だけで速度が決まるわけではない。

3枠以上・入れ子の分割・枠ごとのタブ列・分割配置の永続化・境界のドラッグ・同時に二つのIME変換は今回の候補に含めない。

## 閉じる操作の案

「枠を閉じる」と「文書を閉じる」を異なる意図にする。2枠時の`:q`は操作中の枠を閉じ、文書タブと未保存の本文を残す案を推す。破棄を伴わないので保存確認は要らない。1枠時の`:q`は現行の文書タブを閉じる意味を保ち、未保存なら拒否し、最後の文書なら窓を終了する（D22）。`:q!`も、2枠のときは枠を閉じるだけで本文を破棄しない案とする。`:wq` / `:x`は現在文書の保存に成功してから同じ閉じる意図へ進む。

タブの×・Ctrl+F4・`:tabclose`は文書を閉じる。両枠で同じ文書を見ていても保存確認は文書ごとに1回。拒否/キャンセルなら両枠を保つ。成功時はその文書への参照を全枠から外し、影響する枠を残る隣の文書へ向ける。最後の文書なら窓を終了する。`q`系の詳細と枠移動のキーは、本実装IssueでVimの実測と使い方を照合して確定する。現在の実装は引き続き文書タブを閉じる。

## 状態の所有と移行順の案

| 所有者 | 持つもの |
| --- | --- |
| 文書 | TextBuffer、EditHistory、パス、文字コード/改行、保存位置、文書ID |
| 表示枠 | 参照する文書ID、選択/キャレット、先頭表示行、目標桁、半画面スクロール量、矩形 |
| 窓 | 文書タブの順とMRU、枠の配置と操作中の枠、設定/テーマ、通常/Vim、レジスタ/マクロ/繰り返し、共有一覧 |
| 操作中の入力 | IMEとEx/検索の入力、保留しているVim操作。枠の移動時に確定/取消の規則を一つに決める |

同じファイルを別のTextBuffer/undoへ複製しない。文書はIDで一意に引き、描画は見える行だけを作る。非操作枠のカーソルは変更範囲の前なら不変、後なら編集差分だけ移動、削除範囲内なら削除開始へ畳む方針。undo/redoでも実際の逆編集を通して同じ補正を使い、操作中のカーソル復元は既存`Edit.restore`を守る。位置の挿入時の寄せ方、改行の削除、検索の表示範囲は後続の契約で固定する。

描画とhit testとIME候補位置はcoreの同じ枠矩形を使う。タブ・保存・セッションは文書IDを使い、splitのための別ファイルI/Oやスレッドを作らない。セッションv1は当面文書タブだけを保存し、分割復元を採る段階でschema方針を決める。

順序は、描画費用の試作 → 採用判断と見た目選定 → 文書/表示状態の単一路への分離 → 2枠の意図と表示 → 境界検証。分離段階でも1枠を同じ経路で通し、旧経路を隠しフラグで残さない。

## 測定前に固定する手順

比較元は`checkpoint/pre-split-20261003`（`088481b0c79436e9616445559aa4268225bd2ac0`）。製品・試験・eng・CMakeLists.txtは検証済みReleaseの生成元`591b99f`と同一。AはこのRelease、Sは本文の描画を矩形の列へ通す1枠の試作、Hは上下2枠、Vは左右2枠。各版の生成元commitとexeのSHA-256を記録する。

- 1窓・同じ窓寸法・DPI・フォント・profile設定で、既存TimingPortのinput_receivedからframe_presentedまでを測る。実機の前面を使う。hideが外出中に継続する指示の範囲で実行する。
- 本文は空、既存`large_document`の16MiB/200,000行、長い日本語行（1行4096 bytes以上、1000行）。元ファイルを書き換えず、各試行を新しい隔離profileで開く。
- 既存`eng/measure-speed.py`の`keys_trial`と`window_driver.py`を共用する。暖機1文字を捨て、1文字と200文字の入力を各試行から記録する。起動・保存・フォルダ列挙の性能は対象外。
- 各本文について6組、奇数組はA→S→H→V、偶数組はV→H→S→A。全72試行を一度ずつ記録し、欠測/外れ値も削除しない。合格のための再試行はしない。
- 各値の中央値、最小/最大、各組で対応するAとの差を保存する。6本では安定したp95を推定できないためp95とは呼ばない。1文字/200文字の入力数が合わない、窓が覆われる、測定ファイルが無い場合は欠測。各条件で6本そろわなければ判定保留。
- Aの前半3本と後半3本の中央値差が1文字で`max(0.10ms, A中央値の10%)`、200文字で`max(0.50ms, A中央値の10%)`を越えたら、その本文は環境の揺れとして判定保留にする。
