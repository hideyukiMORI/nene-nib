# 設定モーダルと日英表示の操作設計案

2026-10-12 / Issue #454。#438の依頼と[段階0の範囲案](../plans/2026-10-12-release-scope-and-large-file-probe.md)を具体化する。

**状態: 提案。画面の採用・API/schemaの受理・実装は未了。** 試験保留中に設計だけを進める。ここで決める候補は操作と表示の契約であり、D12が要求する画面案の作成・hideの選択を代替しない。大容量の成立性確認や#446/#452の受理を前提にしない。

## 使い方の案

1. 画面上の文字付き「設定 / Settings」をクリックする。コマンド入力は要らない。
2. 現在の値と短い説明を読み、トグルや選択欄で変更する。本文の設定はまだ変わらない。
3. 「保存 / Save」で一括保存する。成功したらすべて反映して閉じ、元の文書へ戻る。
4. 「キャンセル / Cancel」またはEscで変更を捨てて閉じる。設定ファイルへは書かない。

入口の第一候補は、タブ帯の窓操作ボタンの左に独立した文字付きボタンを置く形。歯車だけを頼りにせず、タブ追加・一覧・窓の閉じる操作と区別する。狭幅でも入口を消さず、既存のタブあふれ処理へ幅を渡す。位置・寸法・配色は次の画面案で比較する。

F1の操作一覧にも同じ「設定を開く / Open settings」を載せ、クリックと同じ操作IDから開く。新しいショートカットは今回決め打ちしない。Ctrl+Pの既存の設定コマンドとVimのExは引き続き使える。

## 初版の6項目

| 順・項目 | 操作と説明の案 | 現在値・制約の正本 |
| --- | --- | --- |
| 1 表示言語 / Display language | 「Windowsに合わせる / Follow Windows」「日本語」「English」の選択。先頭に置き、どの表示言語からも自言語名で戻せる | 新設候補。下記の解決・移行規則を実装ADRで定める |
| 2 テーマ / Theme | 「Windowsに合わせる」と、検索できるテーマ一覧。選んだ色はモーダル内の見本で確認する | `ThemeCatalog` / `ThemeChoice`。組み込みと利用者テーマを同じ一覧から得る。独自の名前一覧を増やさない |
| 3 本文フォント / Editor font | インストール済みの字体を検索して選ぶ。現在設定された名前は、未インストールでも表示して保持する | `EditorSettings::font_family` / `DisplayText`。OS列挙はadapter境界、実際の代替は既存DirectWriteの規則 |
| 4 文字サイズ / Font size | ptを明示した編集可能な数値欄と増減操作。小数の現在値も丸めず示す | `FontSize`の8〜40 pt、既定13.5 pt。共通のparseと範囲検証を使い、UI独自の範囲を作らない |
| 5 行の折り返し / Word wrap | トグル。「長い行を画面幅で折り返して表示します」 | `LineWrapping`。既定オン。保存内容の改行を挿入する機能ではない |
| 6 操作案内 / Operation hints | トグル。「空の文書やステータスバーに操作のヒントを表示します」 | `GuideVisibility`。既定オン。F1自体の利用を無効にする設定ではない |

トグルは色だけでなく「オン / On」「オフ / Off」と位置でも状態を示す。見本には固定の短い日本語・英数字・記号を使い、開いている文書の本文を持ち込まない。フォント一覧の取得失敗は表示し、既存の設定名を空欄や別の字体へ置き換えない。

「既定に戻す / Restore defaults」は6項目の編集候補だけを初期値へ戻す。保存するまでは永続化しない。字体・サイズ・テーマ・案内・折り返しの既定は既存の`default_editor_settings`から得る。表示言語の既定候補は「Windowsに合わせる」。検索・構文色・ファイルの文字コード・Vim互換オプションを、未実装のスイッチとして先に並べない。

## 変更・保存・取消の境界

モーダルを開いた時点の確定値と、編集中の候補を区別する。候補はapplicationの入力状態として所有し、rendererが第二の設定状態を持たない。数値欄の空欄など途中の入力は編集文字列で持ち、妥当性を通るまで`EditorSettings`の値にしない。型と公開APIは実装前のADRで決める。

| 操作・状態 | 結果の案 |
| --- | --- |
| 項目を変える | 候補とモーダル内の見本だけを更新。本文・外側の見た目・設定ファイルは変えない |
| 言語候補を変える | モーダル内のラベルをその候補で見せる。フォーカス、入力値、選択、スクロールを保持。外側は保存成功時に一度切り替える |
| 有効な変更を保存 | 6項目全体を共通の設定保存経路へ一度渡す。各項目を順に保存しない。成功後に確定値を更新して閉じる |
| 無変更で保存 | 書込せず閉じる。起動時の設定読込失敗を成功扱いにして消す操作にはしない |
| 無効な数値等がある | 該当欄に理由を示して保存を無効化。先頭のエラーへ移動できる。取消は可能 |
| 保存が失敗 | 閉じずに候補と理由を保持。確定値・本文側の言語・見た目は元のまま。自動再試行しない |
| 別プロセスの設定変更を検出 | 既存の競合拒否を維持。上書きボタンや無言の再読込を追加せず、設定を保持したことと再起動で読み直す案内を示す |
| 起動時に設定を読めなかった | 理由と現在使用中の値を見せる。破損ファイルや未対応版を既定値で上書きする保存は許さない |
| キャンセル・閉じる・背景クリック | キャンセル/閉じるは候補を捨てる。背景クリックだけでは閉じず、本文へのクリックにも流さない |
| 窓自体を閉じる | 未保存の設定候補を捨てた後、既存の本文保存確認へ進む。本文側の終了を取り消しても設定候補は復元しない |

保存成功による字体・サイズ・折り返しの反映は、既存の文字組み更新・スクロール調整・キャレット追従を使う。本文bytes、選択の論理位置、undo、未保存印を設定変更のために書き換えない。変更に伴う画面上の位置調整と論理位置の保持を区別する。

現行の正典経路は`EditorController::persist_settings` → `SettingsPort::write` → `Win32SettingsAdapter` → `FilePort`。モーダル用に第二の保存処理やExコマンド文字列の組立てを作らない。Ctrl+P/Ex/拡縮操作も同じ入口を維持する。既存の設定保存遅延#424は未解決であり、この設計だけで応答性が成立したとはしない。

## キーボード・IME・配置

- Tab / Shift+Tabで項目とボタンを巡回し、モーダル外へフォーカスを逃がさない。フォーカス枠を見せ、画面読み上げへ名前・役割・値・エラーを渡すことを実装の完了条件にする。
- Spaceはフォーカス中のトグル/ボタンを操作する。矢印とEnterは開いた選択候補を優先し、Enterで候補を選んだ同じ入力を「保存」に流さない。フォーム上でのEnterは編集確定までとし、保存はフォーカスした保存ボタンの操作で行う。
- EscはIME変換→開いた選択候補→モーダルの順に一段だけ閉じる。変換中のEnter/Escを保存・取消へ流さない。
- 本文のIME変換中は開く操作を受け付けず、確定/取消後に開ける表示にする。勝手な変換確定は行わない。閉じた後は元の文書・編集モードへフォーカスを戻す。
- モーダル中の本文編集、タブ切替、Ctrl+P、Vimの鍵、拡縮ショートカットは本文へ渡さない。入力を録画・ドット反復・undoへ追加しない。ワーカーの完了通知と再描画は処理を続ける。
- 入力sessionやCtrl+Tabの歩きから開く際の確定/取消、Vimの未完オペレータの扱いは、既存の操作一覧入口と照合して実装ADRへ列挙する。推測で保留中の鍵を実行しない。
- 通常幅は見出し、6項目、見本、固定の保存/取消行という1ページ。狭幅はラベルの下へ入力欄を置く。最小窓360×200 DIPでは項目領域を縦スクロールし、見出しと保存/取消を残す。フォーカスした項目を見える位置へ送る。
- 本文サイズを40 ptにしてもモーダルのUI文字は本文倍率に連動させない。DPIと日英の文字列長に対応する。保存/取消、項目名、エラーを切り詰めて意味を失わせない。

配置の骨格は次のとおり。これは寸法・装飾の採用画ではない。

```text
設定 / Settings                         閉じる
表示言語                    [日本語 / English / …]
外観                        [テーマ・字体・サイズ]
編集                        [折り返し] [操作案内]
見本                        Aa あいうえお 123
エラー・補足                （必要時だけ表示）
既定に戻す                    キャンセル    保存
```

## 言語の初期値と切り替え

提案する保存値は「Windowsに合わせる / 日本語 / English」の3択。表示する言語は日本語か英語の2択とする。OSの表示言語の取得はadapterから注入し、coreがロケールや環境を読まない。自動選択は日本語なら日本語、それ以外または取得不能ならEnglishとする案で、具体的なOS取得契約は実装ADRへ残す。

- 新規利用で設定が無い場合は「Windowsに合わせる」。起動だけでは設定を書かない。
- 既存settings.v1/v2/v3から読む場合は、日本語を引き継ぐ案とする。更新しただけで既存利用者の表示言語を変えない。次の明示保存で新版へ移し、旧版は残す。
- 明示言語はOS変更に影響されない。「Windowsに合わせる」の解決は起動時と、その選択を保存する時点に行う案。OS言語変更の常時監視は初版に加えない。
- 保存成功後は再起動なしで自前の表示を更新する。操作一覧の候補や案内など言語に依存する保持結果を破棄/再生成し、本文・検索文字列・ファイル名は保持する。
- 新版不在時だけ旧版を読む契約、読めない新版から旧版へ戻らない契約、競合時の保存拒否を継ぐ。版名・キー・厳密な値・lock順序は別ADRで先に確定する。現在のsettings.v3は変更しない。

## 翻訳する範囲と共通の表

| 表示群 | 初版案 | 現在の所在・移行の注意 |
| --- | --- | --- |
| 設定の入口・モーダル・説明・エラー | 日英両方。操作名は共通の操作IDに結び付ける | 新設。既存設定の型付き失敗を文言へ写す |
| F1の操作名・短い名前・説明、本文/ステータスの操作案内 | 日英両方。共通操作の名前を画面ごとに再定義しない | `OperationTexts.hpp` / `OperationGuide.cpp`。`shown_chord`から鍵表示を導く |
| Ctrl+Pの出どころ名・検索案内・候補説明・脚 | 日英両方。記号と絞り込みの意味は不変 | `PaletteMarks.hpp` / `CommandChoice.cpp`。記号表の意味と表示言語を分離 |
| ステータスの通常モード名、行/桁、無題タブ、録画/通知の説明 | 自前の言葉を日英化 | `StatusItems.cpp`とrenderer/controllerの表示生成。意味の値を表示文字列から逆算しない |
| ファイル/設定/テーマの失敗、本文保存の確認 | 自前のタイトル・本文を日英化 | `EditorWindow.cpp` / `SettingsNotice.hpp`等。失敗の種類と引数を保持し、結合済み日本語を後から置換しない |
| Vim/Exの診断 | エラー番号と引数を保ち、説明は表示言語へ写す案 | `VimSearchNotice`とcontrollerのExメッセージ。既存の意味・成功/失敗・oracle用の識別を表示と分離するADRが必要 |
| OSが所有するファイル選択画面、IME候補、標準ボタン | OS側の言語に従う。アプリの日英切替で全体が変わるとは表示しない | アプリから渡すタイトル等は対象。OSボタン名を翻訳するためだけに独自ダイアログへ置き換えない |
| 将来の自前メニュー・split・Markdownの操作 | 実装時に同じ日英の表へ追加 | 未実装画面を現在対応済みと数えない |

翻訳しないものは、本文・ファイル名/パス・テーマ名・字体名・製品名・キー名・Vimモードの技術名・Exコマンド・設定保存キー・エラー番号・UTF-8/Shift_JIS/LF/CRLF等の識別子。例として`:set wrap`は日本語画面でもそのまま、`E486`は説明を変えても同じ番号と検索語を保持する。

表示文言は意味IDと型付き引数から一度生成する。操作名は既存操作表を拡張し、共通の名前を別の翻訳表にも複製しない。閉じた言語・意味IDの全件対応を機械で確認する方針をADRに書くが、この文書で検査をactiveにはしない。未訳を黙って日本語へ戻して完了扱いにしない。

操作一覧の検索は表示中の名前・鍵に加え、両言語の名前と既存の日本語読みを候補にする案。English表示でも「設定」「せってい」から戻せる。説明は従来どおり照合しない。重複候補は作らず、順位・同点の順序は既存の照合経路で定める。通常のファイル検索やVim検索の言語・照合規則は変えない。

## 実装へ切る順序

| 単位 | 成果 | 次へ進む条件 |
| --- | --- | --- |
| 1 画面案 | 通常幅・360×200 DIP、日英、エラー状態の画を作り、入口と配置を比較する | D12に沿ってhideが画面を選ぶ。今回の文書統合で代用しない |
| 2 言語と状態のADR | 言語設定/旧版移行、意味IDと表示生成、モーダル候補の所有、操作入口とIME/session境界を定める | 既存の設定保存と操作表を唯一の経路として移行できる |
| 3 設定値とモーダル | 言語の保存/移行、6項目、見本、保存/取消/失敗、マウスとキーボード、読み上げ情報を接続する | 対象契約と採用画との一致を確認する。全体の日英対応は単位4が揃うまで完了・公開扱いにしない |
| 4 日英表示を揃える | 上表の自前表示、検索候補、通知、保持結果の更新を移行する | 両言語の欠落・重複がなく、設定の再起動後保持が成立する |

単位1の画面案と単位2のADR文書は、試験なしで続けられる。単位3〜4の実装は公開契約・表示・保存形式を変えるため、試験保留中に検証済みとして統合しない。機能実装の順はロードマップの段階3を維持し、今回先行するのは段階0の設計だけ。

試験再開後に必要な対象は、設定候補の保存/取消/無変更/失敗、旧版移行と競合、言語全件と操作検索、フォーカス/IME、96/120/192 DPIと最小窓での日英配置に限定する。操作→保存→本文へ復帰→再起動後保持を確認する。本文入力の経路へ影響がある実装差分では既存の該当性能項目を選ぶが、今はビルド・アプリ試験・GUI・性能測定・CIを実行しない。

## 根拠と現在地
