## 設計席の決め（hide に確かめたいものは引き継ぎの「返事待ち」）

- 全文検索: OneDrive などクラウドのフォルダは歩き、取り寄せが要るファイルは読まない・リパースポイントで飛ばすのは MOUNT_POINT と SYMLINK だけ。入力欄の右に進み具合と件数。
- イージーモーション: 印はキャレットから近い順（一方向の動作は本文の順・両方向の `s` `l` は行と桁の距離）。`\` の後に表に無い鍵が来たら、ビープしてその鍵を普通の鍵として処理し直す（ADR 0163 の決定 1 を変えた）。印を描けない跳び先は作らない。
- 右クリックのメニュー: 見た目は Ctrl+P の面の言葉に揃える（/design のキャンバスは出していない・できた画面を hide に送った）。Vim のモードでも項目は使える（表の Vim の鍵の列を engine に流す・`"+y` `"+d` `"+p`）。F1 の一覧も同じ道。
- プレビュー欄: Ctrl+Shift+P は「いま描いている形」の次へ。当たりの印は保持せず今の当たりから毎回付ける。

## 試したこと・失敗・学び

- **独立レビューを省いた段で穴が出た。** イージーモーションの M3・M4 は同じ席の続きなのでレビューを省いて積み、PR の本文を書いていて気づいて CI の前にレビューを掛けた → 空の行の跳び先に印が出ない（必須 1）。直しを積んで全件の検証とゲートをやり直した。同じ席の続きでも、束で入れる前に 1 回通す。
- **ゲートの 1 回が無効になった。** 席に「記録のファイルができるまでビルドしない」と頼んだが、道具はファイルを計測の始めに作っていた。席 C が計測の途中に `nib_tests` を数分走らせ、すぐ知らせてくれた。その 1 回は数字が通っていても無効にし、道具を直して（`.partial` に書いて終わってから名前を変える）1 回だけ測り直した。
- **連打のベンチの揺れ。** まとめ枝 38 の連打が 37 より 28〜33% 高く出た（許容の内）。37 と 38 の exe を交互に測ると同じ高さで、機械の状態の揺れだった。連打は許容の床 2 ms で 0.6 ms の差が見えないので、気になる差は同じ時間帯に前の exe と交互に測る。
- **関数を名指しした指示が退行を作った。** 待ちの状態を捨てる口に `vim_interrupted` を名指ししたら、INSERT の Ctrl-o の印まで捨てた（イージーモーションの取消と右クリックのメニューの 2 回）。名指しする前に、その関数が捨てるものを読む。
- **merge の道具の形。** main を取り込んだ枝は差分の apply で積めないので `git merge-tree` と `commit-tree` で積んだ。本文の `PR #K（head …）` は 40 桁の SHA（短いと元の PR を閉じない）。直しの commit は件名の `(#N)` と `Closes #N` を同じ番号にする。`--execute` なしで計画を 1 回通すと CI の前に分かる。
- 設定まわりの窓の道具 4 本は main で落ちていた（書き込みを固定の sleep で待つ・後から入った仕様に検査が追いついていない）。#1668 の確かめの基準として回して見つけた。
- 実機の道具: `verify-window.py` の鍵の列に `<C-S-f>` を足した（G3）。SendInput の chord の後の posted の文字が先に処理される穴を直した。Git Bash から `\\w` を渡すと `\w` に変わる。Shift+F10 で開いた自前のメニューは、F10 が OS のメニューのモードに入れて 1 回目の Esc を食べていた（実機で見つけて直した）。
