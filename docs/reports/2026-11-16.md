## 試したこと・学び（走り書きから）

- まとめ枝の merge の道具は、直しの commit にも `Closes #<まとめ枝の Issue>` を求める（席が `Refs` と書いて断られ、同じ木で文だけ直した枝を作り直した・#1749 → #1750）。また「main に追いついていること」を求める（まとめ枝の CI の間は main に何も入れない・#1750 → #1762）。
- merge の道具は main の workflow で dispatch するので、PR の側で workflow を変えてもその PR の run に効かない。上限を上げる PR 自身の木を縮める変更を同じ PR に足して通した。
- 席 S2 が `[IO.File]` の相対パスで本体の checkout に同じ中身を書き戻した（中身は変わらず・本体は clean）。依頼書に「絶対パスだけ」を強く書く。
- 席 E1 は書き始める前に ADR 0188 と Vim の実測の食い違い（0 バイトのファイルを開いた Vim は `&eol=1`）を見つけて止まった（正しい止まり方）。oracle は空の入力のときだけ `setlocal noeol` を流す形に決めた。
- `eng/format-check.ps1` が未追跡の `build-rel/` まで見て落ちる・`merge-pr.py` が CI を起こした直後の 404 で止まる、の 2 つの道具の穴は起票がまだ。
