## Issue #123: 検索の当たりを全て塗り、キャレットのある一致だけ枠で囲む（ADR 0037・実装リナ）

設計側（Fable）の依頼。ADR 0037 の 1 commit を積んだ `feat/123-search-highlight`（origin/main `ae460a6` の上の `4c0414c`）で実装し、ADR 0037 は実測のあとで**受理**にした。統合単位は draft [PR #125](https://github.com/hideyukiMORI/nene-nib/pull/125)。Ready・必須 check・merge は設計リナ。

engine は `VimState` に閉じた 3 値 `VimSearchHighlight`（`on` / `off` / `suspended`・既定 `on`＝施主決定 D17）を持ち、`vim_step` の検索の入口 3 つ（`/` `?` の確定・`n` `N`・`*` `#`）だけが `suspended` を `on` へ戻す。Ex は `ExResult` に `optional<VimSearchHighlight>` が増え、`:set hlsearch` / `:set nohlsearch` / `:nohlsearch` / `:noh` の 4 つを返して controller の写し 1 か所が `VimState` へ置く（設定には載せないので保存しない）。一致の計算は照合器から `vim_line_matches(line, pattern)` を公開して `vim_search` の行内走査をそこへ寄せ、走査の規則を 1 本にした。application は `EditorFrame` を作るときに、Vim モードで強調が `on` で解析できる `last_search` があるときだけ**見えている行だけ**を数え、`LineView` の `matches` / `current_match` を選択と同じ `span_of` で作る。renderer は当たり → 選択 → 本文 → 現在の当たりの枠 → キャレットの順に描き、色は `palette.search` の面と `palette.accent` の 1 DIP の枠だけ（新しいトークンは要らなかった）。保存 schema・依存・ゲートの閾値は変更していない。
