**ADR は書いていない**（ARC-004 の適用で設計は変わらない）。ADR 0030 の「結果」にあった「前者は今も controller が `VimState` の入力記録を直接消す二重経路で、engine のポートへ寄せるのは Issue #92」の 1 文を、`vim_interrupted` に寄せた形へ更新した。fixture も足していない（固定 Vim に外部の割り込みは無く oracle では測れない）。

## Issue #91: VISUALで行った変更を`.`で範囲の大きさから再生する

統合単位は [PR #107](https://github.com/hideyukiMORI/nene-nib/pull/107)。**draftのまま**（Ready・merge・CLAUDE.md 6 節の更新は設計リナが行う）。ブランチ `feat/91-vim-visual-dot` は #98 の merge のあと origin/main `a44f380` へ rebase してあり、ADR 0033 の 1 commit ＋ 実装 3 commit。

設計側（Fable）の依頼。ADR 0033 は実測と実装のあとで**受理**にし、**食い違った 2 点は期待値ではなく決定と実装を直した**。

engine は `VimRepeatRecord` に `std::optional<VimVisualExtent> visual`、`VimReplay` に `std::optional<VimVisualExtent> reselect` を足しただけで、効果は 1 鍵 1 つのまま。`VimVisualExtent` は `std::variant<VimCharacterExtent, VimLineExtent>` の閉じた和型で、文字単位は「行数 ＋ `VimColumnWish` ＋ 桁」、行単位は「行数」だけを持つ。記録の分岐は `vim_step` の後段の 1 か所のままで、`vim_recorded` が前のモードで分け、新しい `visual_recorded` が「変更を起こす鍵から記録を始め、そのときの選択の大きさを載せ、`r` は次の文字まで・`c` は INSERT の Esc まで続ける」を決める。移動・選択の伸縮・`o`・種類の切替・yank は記録を始めない。`.` の step が `VimState.mode` を記録の種類の VISUAL へ切り替え、controller は core の純関数 `vim_visual_reselect(text, caret, extent)` が返した選択を `VimSelect` と同じ写しで置いてから、同じ `accept(VimKeyPress)` へ鍵を流す。UI・IME・描画・保存形式は変更していない。

**ADR の決定を実測で 2 つ直した。**(1) **`N.` は VISUAL の記録では回数を使わない**（`vlld` `2.` は 3 文字・`Vd` `2.` は 1 行・`vllcZ<Esc>` `2.` は `Z` 1 つ）。ADR 0030 の決定 6 の「回数の置換」は NORMAL の記録だけの規則だった。(2) **桁の意味が 3 つとも違った**。1 行の記録はキャレットからの「桁の個数」、複数行の記録は最終行の**絶対**桁（キャレットの桁に依らない）、`$` で選んだ記録は桁に凍らせず「行末まで」のまま（Vim の curswant が MAXCOL に残る）。3 つとも実装で合わせ、`VimColumnWish` を記録に持たせた。

**設計で足した細部が 1 つ**: 桁や行が足りずに畳まれた再生のあとでも、次の `.` は元の大きさで繰り返す（固定 Vim も同じ・`probe4.py` で実測）。`vim_step` は再生中も記録し直すので、「再生中か」を状態に持たずに済むよう、`.` の step が**大きさだけを持つ空の記録**を `recording` に種として置き、再生した鍵がそれを確定する形にした。
