## 変更

H/M/L、Ctrl-d/u/f/b、PgUp/PgDn を、回数・NORMAL / VISUAL・行単位の operator・INSERT のページ移動へ接続した。本文・選択・スクロールの正本を増やさず、借用する `VimEditorView` と選択・先頭行を同時に返す `VimNavigate` を採用した（ADR 0019）。通常編集と Vim のスクロール境界・自動追従は `ScrollExtent` / `ScrollFollow` で明示する。

主要な変更は `src/core/VimStep.*` / `ScrollBounds.*` と関連値型、`src/application/EditorController.*`、`src/ui/win32/EditorWindow.cpp`。検証は `tests/unit/NibTests.cpp`、`tests/vim/`、`eng/vim-oracle.py`、`eng/verify-window.py`、`tests/conformance/`。保存ファイルの形式は変えず、oracle fixture に任意の viewport 入力と期待値を追加した。

## 設計・検証上の発見

- Vim の `-es` は表示領域の観測に使えなかった。viewport がある場合だけ通常端末モードを標準 pipe で動かし、画面の整合と timeout を検査する。既存 256 件の入力・期待値・実行条件は維持した。
- VISUAL のページ移動は、中間状態と yank 後を分けて検査する必要があった。最終の viewport に合わせて途中の移動を抑える実装をレビューで検出し、削除した。原因だった Vim の自動追従を通常の `j/k` でも測り、既存の追従関数に一本化した。
- 自動追従で本文末尾に新たな空白を作らないことと、明示したページ移動後の空白を保つことを、それぞれ oracle と単体テストへ追加した。
- 実機検査の最初の失敗は、改行を `WM_CHAR` で送る検査側の誤りだった。製品は制御文字を捨て、Enter を `WM_KEYDOWN` で扱う。検査を同じキー経路へ直し、初期入力の終了も NORMAL のブロックカーソルの画素で待つようにした。M の期待位置は緩めていない。
- 画素検査は丸角カーソルの端の 2 画素を文字と誤認した。保存した画面で、空行の従来領域は 2、カーソルを避けた領域は 0、マーカーの文字は 442 と確認し、文字を測る領域を分けた。期待する空行の閾値 0 は維持した。修正後の実機検査は全体で終了 0。
