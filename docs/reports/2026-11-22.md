## 測れたこと

- 1 GiB（2,048 バイトの行 × 524,288 行）は、窓が出てから約 0.5 秒で本文が出て、Ctrl+End は 1 コマ。**作った直後で OS のキャッシュに載っている状態**（D は HDD・冷えた状態は測っていない）。
- 起動の窓は自分の大きさ（800×450 px・120 dpi）で出る。録画では、黒い下地の上で 60 fps の 1 コマ目から全体が見えた。
- 録画は ffmpeg の `ddagrab` ＋ `h264_nvenc` で 1920×1080・60 fps が落ちずに撮れた。

## 失敗と学び

- **イージーモーションの札が出ず、30 分ほど製品を疑った。** 原因は設計席のスクリプトで、Bash の heredoc に書いた `\\` が半分になり `\w` を送っていた。リポジトリの検査（`verify-window.py --easymotion`）を本番の exe に回して製品が正しいと分かった。先に検査を回せば早かった。スクリプトでは `chr(92)` を使う。
- **対応の OS を「Windows 10 / 11」と書いた。** README は Windows 11 x64。絵コンテと動画の最後の 1 枚を直した。画面に出す事実は書く前に正本を読む。
- **「起動音をもう一つの方に」を冒頭の音と読み違えた。** hide の意図は最後の音だった。指す所が 2 つ以上あるときは、変える前に 1 行で確かめる。
- **「4.4 MB」は 1024 で割った値**（1000 で割ると 4.6 MB）。動画ではバイト数を添えた。
- **行番号が 7 桁以上だと欄の左で桁が欠ける**（#1936・`font_size=18` で見た・既定の大きさでは未確認）。動画は 6 桁の見本で撮った。
- **clangd の命令は空白を含むので引用符が要る。** 未保存の文書の窓は `D.close` で「保存しますか」が出るので、撮影では `D.stop` で落とす。
- **Artifact の `edits` は権限の確認に通らなかった。** Edit で直してから publish する。
