## 設計席の決め（hide に確かめたいものは引き継ぎの「返事待ち」）

- **語の表は開く道で作らない。** 最初に補完を使ったときに 1 MiB 以下の文書だけ作り、64 KiB を超える編集で捨てる（ADR 0169 の追補）。開くときに作る形は 16 MiB 弱で 0.5〜0.8 秒を窓のスレッドで使っていた。
- **打鍵で自動に開く面は LSP の候補だけ。** 本文の語は、使う人が補完を呼んだときだけ。定義へ跳ぶのは何も待っていないときだけ。`gd` `K` は LSP が無ければ今までどおり失敗（ADR 0190 の追補）。
- **Vim の補完は oracle（`-es`）が正本。** `.` は入った語を入れ直す・Backspace は確定して 1 文字消して閉じる（端末の Vim とは違う）。Ctrl+P は面が見えている間だけ（hide「いいよ」）。
- **設定の面**: 探す欄では IME が使える（閉じるときに変換を取り消す）・選ぶ欄は表示の名前・LSP のオン・オフは「機能」の節・要約に内訳（ADR 0170 の追補）。`settings.v5` に鍵は足していない。
- **Markdown**: 打ち消し線は `~~` だけ（`10時~12時` を守る）・エスケープした印は alert にしない・表の 1 行は要素 1 つ（ADR 0151 の追補）。

## 試したこと・失敗・学び

- **時刻を推測で書いた。** 走り書きの時刻を `date` を読まずに書き、hide に「夜が遅くなってきた」と報告した（実際は 13:40）。hide の指摘で訂正。以後は時計を読んでから書く。
- **ゲートの盲点。** 語の表の上限（当初 16 MiB）を、ゲートの文書（16,800,000 バイト）がわずかに超えていて、開く道の費用が見えなかった。上限を持つ機能は、上限のすぐ下の大きさで開く道を 1 回測る。
- **数え漏れが後ろの段で見つかった。** 補完の面（#1844）が操作を足したのに、F1 の一覧の行数の検査 2 つ（`--command-palette` `--shell-registration`）を席もレビューも回していなかった。操作を足す依頼書には、この 2 つと `--every-scope` を検証に書く。
- **`nib_tests` は引数を 1 つしか読まない。** scope を 1 行に並べると黙って既定の実行になる。今日の依頼書は並べて書いていた（漏れは無かった・#1853）。
- **畳んだ PR の後ろの枝は素の merge で大きく衝突する。** まとめ枝が PR を 1 commit に畳むので、その PR の枝から切った後ろの段は同じ行が両側の追加に見える（30 ファイル）。起点を base にした 3 者併合で機械的に解けた（`D:/NeNeNib/scripts/20261118/b2/merge3.py`）。後ろの段は、前の段がまとめ枝に積まれてからまとめ枝から切る。
- **影の枝で検証を回すと規則の自己試験が落ちる。** `test-conformance` が歴史の「shadow:」の commit を GIT-003 で拾った。積み終えたらまとめ枝（木は同じ）に切り替えてから回す（道具に注記）。
- **まとめ枝の枝名に Issue 番号を入れ忘れた。** `chore/integration-20261118a` は GIT-002 に合わず、CI の規約の検査だけが落ちた（製品のビルドと試験は成功）。merge の道具の下見は枝名を見ない。同じ commit を `chore/1849-integration-20261118a` に置いて PR を出し直し（#1855 → #1856）、CI を 1 回余分に回した。積む道具の頭に枝名の検査を足した。
