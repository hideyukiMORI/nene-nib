## 分かったこと

- 1 行 16 MiB を開くの 2 つの山は計測器の問いへの応答（43〜97 ms）だった。待ちを除くと「はい」も「いいえ」も 82 ms で同じ。
- `nib_perf_probes` と同じく、席の PR 本文は見出しの形で書かれることがあり local の `git-conventions.py --pr-body` は通すが CI の `validate-git.ps1` は `目的:` の欄で落とす（#709・Issue #710）。設計席の branch も `<type>/<issue>-<summary>`（#705 → #708）。
- Ctrl+P の設定の候補は点数に候補の長さが入り「名前の長さ順」だった（#712）。`vscode-high-contrast-light` は #419 の取り込みから dark の値だった（#713）。
- 設計席の見立て 2 つを oracle が正した: 回数つき Ctrl-f / Ctrl-b が途中で端に当たった周の列は保たれる（#411）・`g^` は段の中で止まらず空白を越える（#721）。
- 並行して merge すると後の PR が main と衝突する（#722 は #723 の後で生成物の作り直しが要った）。
- 席が止まらず進めた判断で設計席が後から揃えたもの: fontsize のプレビューは次の段（frame の文字組みと ui の行高が保存した値）・Shift+Tab も先に接頭辞・巡回の戻り先は接頭辞を埋めた後の入力。
- 外からの講評は事実の表で受け、数行で直るデータ保護の穴（強行の終わりの退避・UTF-32 の誤判定）を先に直す。
- 基準値は定義が変わった本だけを採り直す（#704 で定義の変わらない 1 打鍵まで 1.351 に緩めていた → #736 で戻した）。
