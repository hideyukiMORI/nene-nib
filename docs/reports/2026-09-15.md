## 施主決定と設計判断

- 施主決定 D11〜D15 を SPECIFICATION に足した: ダークは Ubuntu 風の茄子色（#300A24）、見た目は `/design` の採用案（アクセントは Ubuntu 橙 #E95420）、有名なカラーテーマを `:colorscheme` で選べるようにする計画、フォントサイズの変更、編集中の見た目は `:` の行を案 A
- コンパイラは clang-cl 1 本（ADR 0003）。cl は Phase 0 の比較対象だけ。cl が拒否して clang-cl が通す穴は 1 つも無かった
- 描画は Direct2D ＋ DirectWrite ＋ DXGI の flip model（composition・waitable）＋ DirectComposition、背景は Mica（ADR 0002 / 0008）
- 並行性は UI スレッド＋固定ワーカー 1 本、例外区画は `src/adapters/win32`（ADR 0004）。Vim は自前実装で本物の Vim との差分テスト（ADR 0005）。速さのゲート・SIMD の区画・表駆動の分岐（ADR 0006）
- 本文は piece table・内部表現は UTF-8・undo は連続した文字入力の単位・意図は `std::variant` の閉じた和型（ADR 0009）
- ファイルはバイト列だけの `FilePort` と CP932 変換の `CodePagePort` の 2 ポート。文字コード（BOM → UTF-8 → Shift_JIS・どれでもなければ開かない）と改行（最初の改行で判別・無ければ CRLF）の判別は core の純関数。保存は同じフォルダの一時ファイル `.nib-tmp` からの置換。未保存の判定は undo 履歴の位置と保存時点の位置の一致（保存時に入力単位を閉じる）。64 MiB 超は開かない（ADR 0010）。設計レビューで 64 MiB の定数の重複・保存側の上限・BOM の後ろが壊れた列の扱い・起動引数の失敗の通知・保存ダイアログの既定拡張子の 5 件を直した
- テーマは `core::Palette` の値型（16 トークン）に閉じ、UI は色の定数を持たない。`:colorscheme` とフォントサイズの計画は `docs/plans/2026-09-15-colorschemes.md`

## 実測で分かったこと（規則ではなく道具の癖）

- `-Werror=vla` は C++ では効かない。VLA は `-Wvla-cxx-extension` が拒否する（Phase 2 の反例で発覚。名指しを変えた）
- clang-tidy の `bugprone-unchecked-optional-access` は MSVC STL の `operator*` を見ない。`value()` で読む規則にした
- Mica を透かすには `WS_EX_NOREDIRECTIONBITMAP` と、外観に合わせた `DWMWA_USE_IMMERSIVE_DARK_MODE` が要る
- core で `std::lround` を呼ぶと libm のシンボルが外へ出て ARC-003 が落ちる。DIP → 物理画素は整数演算
- `std::string_view::find` は `__std_find_trivial_*` を core の外へ出す。STL の純関数なので許可リストに足した
- Ctrl と Shift の組み合わせは `PostMessageW` では駆動できない（`GetKeyState` は生入力キューだけを見る）。**ただし `AttachThreadInput` で前面を取ってから `SendInput` を送ると Ctrl+S は駆動できた**（Issue #11）。undo・選択・クリップボードも同じ手で実機に載せられる見込み
- `MB_OK` の `MessageBoxW` は `WM_COMMAND(IDOK)` を Post しても閉じない（`GetDlgItem(IDOK)` も NULL）。`WM_CLOSE` で閉じる。`MB_YESNOCANCEL` の「いいえ」は `WM_COMMAND(IDNO)` で閉じる
- フォルダを `CreateFileW(GENERIC_READ)` で開くと `ERROR_ACCESS_DENIED` になる。理由を「読めない」にするには `GetFileAttributesW` で先に見る
- 最初の描画が出す `VisibleLines` の意図で表示値の `last_failure` が消えるので、起動引数の失敗を出すには描画の前に表示値を控える

## 残件と残るリスク

- ファイルは開いて保存できるようになり、未保存で閉じると確認が出る。Ctrl+O・Ctrl+Shift+S・ファイルダイアログ・「保存しますか」の はい／キャンセル はモーダルで自動検査に載っていない（手動確認が要る）。64 MiB 超・文字コードと改行の手動切り替え・外部変更の検知・バックアップは無い

- 実機は 120 DPI の 1 台だけ。96 DPI・`WM_DPICHANGED`・複数モニタ・Mica 非対応環境・ライトの外観は未確認
- ゲートはローカルで約 6 分（反例 26 本の clean build）。CI は約 2 分
