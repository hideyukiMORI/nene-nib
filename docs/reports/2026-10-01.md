## 同じフォルダ（D28 の 3 本目）の調査と施主の決定

#264 の席が走っている間に、Sonnet の席が今のコードを 2 回調べた（読むだけ・`out/probes/probe-samefolder-2026-10-01.md` と `probe-samefolder-ui-2026-10-01.md`）。分かったこと:

- 候補の列は面を開くときに 1 回作って持つが、絞り込みの結果は持たず、1 つの入力で frame を 2〜5 回作るたびに当たった全件を写している。描画は見えている行（最大 8）しか読まない。
- 選択は絞り込みの結果の中の位置で、候補の列を後から伸ばす口は無い。
- ADR 0004 のワーカーは実装が無い（スレッド・自前の窓メッセージ・タイマーは src に 0 件）。並行性の検査は active で、`src/adapters/win32` だけがスレッドを書ける。
- フォルダの列挙の口は `FilePort` に無く、パスからフォルダを取り出す関数と拡張子を取る関数は core に無い。

仕様に無い 2 点を、選択肢と良い点・悪い点の表で hide に説明した。hide の決定（仕様にはまだ書いていない。ADR を書くときに D33・D34 として入れる）:

- **出すファイル**: 画像・exe・zip・PDF など、よく知られた「テキストでない」拡張子だけ外す（設計席のおすすめのとおり）。
- **フォルダは裏で読む**: Ctrl+P は必ずすぐ開き、読めた分から一覧に足す。設計席のおすすめは「開く瞬間に読む」だったが、hide は「速さが売りのエディタだからこっちの方が合う」と裏で読むほうを選んだ。

設計席が決めて hide に伝えたこと（異論なし）: 同じフォルダのファイルだけ（下のフォルダは見ない・フォルダの行なし）・隠しとシステムは出さない・何も打たないときは一覧の最後・タブや履歴と同じファイルは 1 回だけ・無題では候補なし・件数の上限は実測して決め、超えたら 1 行知らせる・`/` は記号になる。**並びは「名前順」と最初に伝えたが、裏で読めた分から足すので「OS が返す順」に変えた**（NTFS では名前順・変えたことは hide に伝えた）。後から行が足されても、選んでいる行は同じ候補のまま。

ADR 0062 の下書きを書いた（`D:\NeNeNib\briefs\adr-0062-draft.md`・リポジトリにはまだ入れていない）。Issue は 3 本に分ける案: 面の重さ（絞り込みの結果を持ち frame は見えている行だけ）→ ワーカーとフォルダの列挙（adapters と型のある port）→ 同じフォルダを面に出す。ADR 0004 から変える点は 1 つで、完了を「heap の値を載せた窓メッセージ」ではなく「中身の無い合図＋ application が引く」にする。
