## 施主決定と設計判断

- **C1 は core だけ・見た目は仮**。有名テーマは本文の色しか定義しないので、タイトルバー・ステータスバー・パネルは Nib が決めるしかない。112 個の値を手で決める代わりに `derive_ui`（規則の形は整数・決定的・1 表）で導き、**値の妥当性は C3 で `build_boards.py` の絵にして hide が見る**（D12）。この Issue では絵を出さない
- **`derive_ui` は整数の sRGB 補間だけ**。core から libm のシンボルが出ると ARC-003 が落ちる（ADR 0008 の決定 5 と同じ）。コントラスト比（WCAG・`pow`）は tests 側で計算する
- **solarized-light の本文の前景は base01（4.99:1）**。Solarized の usage 表の body text は base00 だが 4.13:1 で決定 7 の 4.5 を割る。ゲートを弱めず、同じ出典の「optional emphasized content」から選ぶ（A / B / C の 3 案から A。実装リナの暫定案を採用）
- `SyntaxPalette` の役割名 `operator` は C++ の予約語なので `operators`（実装リナの判断を採用・ADR の決定 1 を直した）
- **VISUAL は `VimMode` の 2 値**（`visual` 1 値 ＋ `visual_kind` は 2 つの状態が矛盾しうる）。anchor は `VimState` に持たず `EditorState` の `Selection` を engine が読む（選択の正本は 1 つ・ARC-004）。効果は `VimSelect{Selection}` 1 つで「入る・動く・入れ替える」を同じ形に。排他 `[anchor, caret+1)` に置き換える案は描くキャレットがずれるので却下
- **ADR 0018 の決定 7 の「回数は VISUAL に入る前のものを捨てる」は設計の誤り**。実装リナが oracle（`3v` が 3 文字・`3V` が 3 行）と `:help v` / `:help V` を当てて Vim に合わせ、設計リナが同日に決定を改訂した（前日の決定 5 とは逆で、今回は実装リナが正しかった。**oracle と食い違ったら出典を当てる**の運用が両方向に効いた）
- VISUAL で効かない鍵（`p u ~ > < J r I A gv`・`X D C Y`）は**何もしない**（Vim の `u` は VISUAL では小文字化なので undo に流さない）。同じ鍵の fixture は oracle と食い違うので置けず、「何もしない」は機械が見張っていない（gate-proofs に明記）
- 次回の 3 候補（C2 設定の保存 / Vim の 4 本目 / C3 の `:`）は hide に聞く。設定の保存場所・形式・版の付け方は施主の好みが効く。設計リナの推しは **Vim の 4 本目 → C2 → C3**

## 実測で分かったこと（規則ではなく道具の癖）

テーマ（`docs/adr/0017-*.md` の「正直に」）:

- 有名テーマの色は出典の生データ（tmTheme・VS Code の JSON・less・spec・公式ページ）から写せた。出典に役割が無いところ（Monokai の行番号・operator・warning、Dracula の cursor・current line・行番号・warning）は同じテーマの近い色で埋め、One Dark と Night Owl の `current_line` は α 付きの色を背景に重ねた計算値
- 採用案 2 テーマの**本文トークン 16 個は新しい値**（Tango の色表から役割に割り当て。`operators` の水色だけ端末の配色由来）で、hide の目を通していない
- `derive_ui` と採用案の差（チャンネルあたり最大）: `title_bar` 2 / 5・`status` 1 / 2・`gutter` 12 / 21・**`ime` 44 / 45・`search` 21**。`ime` と `search` は採用案が独立に決めた色で規則の方向から違う（C3 で見直す）
- 本文／UI のコントラスト比: aubergine 15.13・neutral-light 15.18・solarized-dark 4.75・solarized-light 4.99・monokai 13.94・dracula 13.36・one-dark 6.57・night-owl 13.54・night-owl-light 9.88
- clang-tidy の `bugprone-unchecked-optional-access` は **`has_value()` の直後でない `.value()` も落とす**（CPP-004 は「`value()` で読む」とだけ書いてある。`std::optional` 同士の `==` 比較で回避）

Vim（`docs/quality/gate-proofs.md` 5-g・ADR 0018「正直に」）:

- VISUAL のキャレットは行の内容の終わり（NUL の桁）に載る。`v$d` は改行まで消して次の行と繋がる（`coladvance` の `one_more`）
- `op_delete` の「奇妙な Vi の振る舞い」（複数行の文字単位の削除が行単位になる）は **VISUAL に掛からない**（`!oap->is_VIsual`）。`removed_exactly` の別入口が要った
- `3v` / `3V` は回数ぶん選ぶ（上）。`V` の中の `$` `0`・`Vy` / `vy` のあとのキャレットは草稿どおり
