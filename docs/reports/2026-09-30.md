## Issue #240: タブの一覧と Ex と Vim の gt（ADR 0057・Sonnet の probe → 実装席 Opus 5.5・3 席）

oracle の fixture はタブを観測できないので、Sonnet の席が本物の Vim 9.1 で実測した（`out/probes/probe-vimtabs-2026-09-29.md`・約 240 件・`-u NONE -i NONE -N -n -es`・クリップボードに触れない）。直感と違った所: `{N}gt` は絶対の番号で範囲の外は失敗（後ろの鍵も打ち切る）／`{N}gT` は N 個ぶん戻る相対で折り返す／`:tabnext 4`（3 本）は E475・`:4tabnext` は E16／`0gt` は `0` の後の `gt`／`:tabne` は `tabnext`（`tabnew` は完全一致だけ）／`dgt` はオペレータを打ち消して失敗／`vgt` は動いて VISUAL を終える／`.` は `gt` を繰り返さない。本数 1 本でも同じ規則で説明がつく。

ADR 0057 の要点: 「どのタブへ行くか」は core の純関数 `tab_destination` の 1 本。Vim の `gt` `gT`・Ex の `tabnext` `tabprevious`・一覧の候補の実行がここを通って同じ `SwitchTab` に着く。engine はタブの本数と今の位置を `VimEditorView.tabs` から借用して失敗を自分で決める（状態の欄は増やさない）。一覧は新しい面を作らず、`CommandPalette` に候補の出どころ（`commands` / `tabs`）を足した。候補は題名と場所（`CommandChoice.detail`）で、実行は Ex の `tabnext N`。

**Vim と違えた所**: `:tabclose` は Vim の E784（最後の 1 本）と E37（未保存）を出さず、× や Ctrl+F4 と同じ流れ（未保存なら「保存しますか」・最後の 1 本なら窓を閉じる・D22）を通す。閉じ方が入口で変わらないことを優先した。controller は `EditorFrame.close_request` を載せ、ui が意図の結果を受ける 1 か所でそれを見て閉じる流れを呼ぶ。hide には判断が要らない報告として伝えた。

席の判断で受理したもの: 再生の途中で `gt` が切り替えたら、出ていく文書の編集をその文書の 1 単位に畳み、入った文書を次の起点にする／一覧が開いている間に「∨」を押すと閉じる（面の外のクリックで閉じる今の規則がそのまま効く）／`v9gt` は VISUAL のまま失敗／受けない引数の文言は「Not supported: <入力>」。席は途中で symbols が ARC-003 で 1 回落ちた（`std::stable_sort` が `std::nothrow` を core の外へ出す）。許可の表は触らず `sort` に書き換えた。

実機の画は 20 枚（`out/window-verification/tabs-240/`）。クリックも文字も窓へ post し、本物のキーボードとポインタは使っていない。fixture 1853 は不変・既定 18647 → 18824 checks・`--tabs` 143 → 248・`--ex-settings` 153 → 195・`--command-palette` 130 → 146。速さは 6 本とも基準内（`out/speed/2026-09-29T15-19-34Z.json`）。PR #247・main `32e7087`。

## Issue #248: Ctrl+Tab は最近使った順（ADR 0058・D23・実装席 Opus 5.5・3 席）

「最近使った順」の普通の意味（VS Code・OS の Alt+Tab）にした: Ctrl を押している間は順番を固定してその上を歩き、Ctrl を離したときに着いたタブを先頭へ動かす。押すたびに順番を入れ替えると、2 つのタブを行き来するだけで 3 つ目へ届かない。

使った順は application の状態が 1 本持つ（core の値 `TabRecency` と純関数 4 つ）。意図は `StepTab` を `WalkRecentTab` に置き換え、`SettleRecentTab` を足した。ui は Ctrl を離したとき（`WM_KEYUP`）とフォーカスを失ったとき（`WM_KILLFOCUS`）に、歩いているときだけ確定を送る（Ctrl+C のたびに描き直さない）。帯の位置の順の鍵（`gt` `gT` `:tabnext` `:tabprevious`・一覧）は変えていない。

**差し戻し 1 件**: 「歩いている間に、歩きを続けない意図が来たら先に確定する」判断が ui（`EditorWindow::send`）に書かれていた。どの意図が歩きを終わらせるかは状態の意味なので、`EditorController` の入口の 1 か所へ移した。移したことで、工程 1 の契約（controller を直に呼ぶ）と実機（ui が先に確定する）で使った順が食い違っていた所が見つかり、同じ結果になった。

fixture 1853 は不変・既定 18824 → 18864 checks・`--tabs` 248 → 288。実機は `eng/verify-window.py --tabs`（本物のキー入力・終了 0）。速さは 6 本とも基準内（`out/speed/2026-09-29T16-14-05Z.json`）。起動の 2 本の中央値が #239 の計測より大きい（起動 195 → 219 ms・窓 32 → 37 ms・各ベンチの 1 回目に外れ値）。本 Issue の差分は起動の経路に触れておらず、機械の状態の揺れと見ているが、次の区切りの計測で確かめる。main `ac88625`。
