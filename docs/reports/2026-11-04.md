## 今日分かったこと

- **まとめ枝は「積んだ木の検証」で意味の衝突を拾う**（#1180 × #1147）。1 本ずつの列なら CI が拾っていたものが、席の検証とレビューでは見えない。まとめ枝の手元の既定実行は省かない。
- 表の PR を `git merge --squash` で積むと古い枝（`0fbf14e8`）との merge-base で 27 ファイルが衝突する。各 PR の**自分の commit だけ**を `rebase --onto` で写してから squash する形が正しい（`stack2.sh`）。
- `--fixup` の件名は GIT-003 の hook が拒む。amend は `rebase -i` の `edit` で止めて行う（`edit-todo*.py`）。ビルドの作業木を汚さないために別の detached 作業木で rebase し、ビルドの作業木には `reset --hard <新しい先端>`（変わったファイルだけ書き換わる）。
- **同じ作業木でビルド中に積まない**（衝突の印を拾って無効なビルドになった）。
- 関数長の門（60 行）は 2 つの PR がそれぞれ 1 行足すと積んだ後にだけ当たる（合成ルート `run`）。probe の期待表の checksum は序数を含むので、操作が 2 つ増えると +512。
- `nib_tests` の fixture の再生は `settings` の `set scrolloff=N` を読んでいなかった（既存 157 件は全部 so=0）。so>0 の fixture は今日が初めて。
